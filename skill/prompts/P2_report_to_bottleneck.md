# P2 · 从综合/实现报告定位瓶颈

**一句话**：把 `util.rpt` / `timing.rpt` 的**原始行**贴给模型，要求它输出
「瓶颈在哪个模块的哪条路径、证据是哪一行、改什么、预期省多少、怎么验证」，
而不是要一段"优化建议"。

## 适用场景

- 时序不过（WNS < 0）或资源快满（LUT/BRAM > 80%），需要找**具体**热点；
- 位流能下但上板不稳，怀疑跨时钟域或组合逻辑太深；
- 想在报告里写"资源为什么这么多"，需要一个可对账的解释。

**不适用**：报告本身不完整（比如没跑 `report_utilization -hierarchical`）；
也没法在"还没有任何实现结果"时用。

## 怎么用

1. 先跑出**四份**报告（`skill/templates/run_vivado.tcl` 已固定文件名）：
   `timing.rpt` / `util.rpt` / `drc.rpt` / `check_timing.rpt`；
2. 把 `util.rpt` 的 hierarchical 段与 `timing.rpt` 的 top paths 段**原样**贴进去
   （不要摘要——摘要会丢掉正是你要的模块名）；
3. 要求模型逐条给"文件:行号"证据，然后把结论丢给 `check_impl_reports.py` 复核。

## 可复制模板

```text
你是 FPGA 实现工程师。下面是 Vivado 8.x 的真实报告片段和我用的器件/约束。
请只回答"瓶颈在哪、证据是什么、改什么"，不要给泛泛的优化建议。

【器件】<<xc7a35tfgg484-2>>
【时钟】<<sys_clk 50 MHz, ad_clk 60 MHz, 目标同频>>
【资源使用摘要】
<<粘贴 util.rpt 的 "| Slice LUTs | ... |" 等行 + hierarchical 段落前 30 行>>
【时序摘要】
<<粘贴 timing.rpt 的 Design Timing Summary 表头三行 + WNS/TNS 行>>
【最差路径 top 10】
<<粘贴 timing.rpt 里每个 path 的 "Slack / Source / Destination / Path Group / Logic Levels" 段>>

请输出：

1) 瓶颈判定（一句话）：资源受限 / 时序受限 / 二者都不是（那是设计问题）。
2) 表格：| 瓶颈位置(文件:行号→report:行号) | 证据原文 | 根因 | 修改方式 | 预期收益 | 风险 |
3) 三个"先做这个"的排序，并说明为什么排在前面（收益/风险/改动面）。
4) 每条修改后用什么数字验证（具体到报告里的哪一行、期望变成多少）。

约束：
- 只用我贴的报告内容，禁止假设我看不到的结构；不确定就写"需要 report_xxx 才能判"；
- 不许建议"降低时钟频率"或"换成更大的器件"作为首选（那是放弃指标，不是优化）；
- 如果瓶颈是复位/使能/常量这类控制信号扇出，明确指出，不要说"逻辑太复杂"。
```

## 已验证效果（本工程）

- **资源侧**：v74 显示+采集位流 LUT 10926 / 20800（52.53%）、BRAM 32/50、
  DSP 17/90；把 hierarchical 段贴进去后，定位到查表实现的 atan 表占 BRAM 大头，
  后续 v85 做到 86.96% LUT / 48/50 BRAM 时，能解释"为什么 BRAM 先满"。
- **时序侧**：v74 WNS +0.409 ns、0 失败端点（24625 个端点）；
  v85 显示位流 WNS +0.175 ns。两次都不是靠"再跑一次布局布线碰运气"，
  而是改具体路径（打拍/复制寄存器/改编码）。
- **反面收益**：模型曾建议"把 200 MHz 时钟降到 150 MHz"来换时序，
  被拒绝——那等于改指标；把这条写进约束后，它改为给"路径拆分"方案。

## 失效条件

- `util.rpt` 不带 `-hierarchical` 时只能看到顶层合计，模型会开始猜模块名；
- 跨时钟域问题不会出现在 timing 报告里（被 `set_clock_groups` 排除了），
  用这个提示词会得到"时序很好"的错误安心感——要另做 CDC 检查；
- 综合结果与实现结果可能差很多（`-flatten_hierarchy rebuilt` 会改变边界），
  拿 post-synth 报告定位实现瓶颈会指错地方。

## 来源

本工程 v70 曾经"报告 WNS 为正但上板偶发错误"，根因是跨半量程的符号扩展
（`deliverables/design_report.md` §11.14.1）——报告完全看不出来。所以这个提示词的最后一条专门要求
"瓶颈是控制信号扇出就明确说"，防止模型用"逻辑太复杂"糊过去。

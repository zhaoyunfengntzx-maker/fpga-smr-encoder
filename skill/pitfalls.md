# 踩坑清单（触发条件 → 现象 → 排查 → 修法 → 回归验证）

按"你在什么阶段、看到什么"排列，不按严重度。每条都能在 30 秒内执行排查步骤；
排查不到再用 `skill/` 里对应的长文。
每条末尾的 `src:` 是本工程的记录号或文件，用于回查当时的原始证据。

**通用判据**（所有条目共用一条铁律）：
> 结论只能来自确定性工具——测试台的 `TEST PASSED`、实现报告的
> `All user specified timing constraints are met.`、`tools/*_check.py` 的退出码。
> "AI 说没问题"不是结论。

## A. 仿真阶段

### P-01 测试台全绿，但 DUT 的输入根本没接上
**触发**：仿真几秒就结束、打印 PASSED；或者改了 RTL 行为却没有任何断言变红。
**现象**：`TEST PASSED (n checks)`，n 与激励点数不符或恰好等于 1。
**排查**：
```bat
python skill\scripts\tb_wiring.py sim\tb_xxx.v --dut rtl\xxx.v --strict
```
看 E1（输入没连）/ E2（输入接常量）/ W1（信号从未被赋值）。
**根因**：激励寄存器改名后实例化没跟着改；或 `.din(din)` 里的 din 只声明未赋值。
**修法**：补齐端口连接；把常量驱动改成真实激励；测试台加"输入必须变化"的断言。
**验证**：注入 `.en(1'b1)` 后测试台必须 FAIL（本工程 `skill/examples/wiring/` 就是这个夹具）。
**src**: 记录 1、`skill/testbench-blindspot.md` §3.1

### P-02 有符号右移写了 `>>`
**触发**：负数段误差突然变大、角度在 0/360° 附近抖动。
**现象**：误差 RMS 从 0.32 涨到 0.60 LSB；截断后的值"偏大"。
**排查**：`grep -n ">>" rtl/*.v`，逐个确认左操作数是否 `$signed`。
**根因**：Verilog 的 `>>` 对无符号是补 0；综合后对有符号也常按逻辑右移处理。
**修法**：显式 `>>>`，或先做符号扩展再移位；黄金模型里用 Python `>>`（同为算术右移）。
**验证**：负半周逐点比对 `--tol 0`；RMS 回到 0.9375 LSB 量级。
**src**: 记录 2、`skill/golden-model-bit-exact.md` §2

### P-03 半 LSB 舍入写成"直接截断"
**触发**：象限边界（45°/135°/225°/315°）附近整段差 1 码。
**现象**：随机抽 100 点完全正常，全周 2^20 点扫描才暴露。
**排查**：模型与 RTL 各自输出边界附近 ±8 个码，逐点对；或直接跑 `check_vectors.py --tol 0`。
**根因**：RTL 用 `(x + (1<<(n-1))) >>> n`，模型用 `x >> n`，差半 LSB。
**修法**：两边统一为 half-up；负数按向 -inf 方向舍入（与加法后截断一致）。
**验证**：全周扫描 RMS 与最大误差同时入报告；边界点单独列表。
**src**: 记录 7

### P-04 跨半量程（32768 附近）整段错
**触发**：角度在一个电周期内跨过半量程时，输出跳变或符号翻转。
**现象**：0–180° 正常，180–360° 的增量方向反了；v70 上板偶发。
**排查**：激励覆盖"从 32000 走到 33500"的连续段，看差值符号；
把 16 bit 码按有符号解读画出来。
**根因**：偏移二进制/补码混用；差值运算没做符号扩展，负数被当成大正数。
**修法**：差值统一 `$signed(a - b)` 后再判断；状态机对跨零点单独处理。
**验证**：专门一条"跨半量程"用例必须进回归集（不能只靠随机）。
**src**: 记录 12、`skill/fixedpoint-width-safety.md` §3

### P-05 UVW 扇区截断，50% 角度点错但测试台全绿
**触发**：用 UVW 做粗定位；角度只在一半的区间里对。
**现象**：扇区边界处角度错误；测试台只检查"角度递增"，所以通过。
**排查**：把 UVW 三位与角度码的对应表打出来，逐扇区对照；对 6 个扇区各取 3 个点。
**根因**：扇区号位宽算少一位，或扇区映射表边界写错（把 6 扇区当 3 扇区）。
**修法**：扇区数写成参数；映射表用 `case` 全覆盖 + `default` 报错。
**验证**：扇区遍历用例 + 每个扇区边界 ±1 码。
**src**: 记录 15、`skill/testbench-blindspot.md` §4

### P-06 调试信号恒为 1，掩盖了真实路径
**触发**：上板/仿真时某个 `dbg_*` 信号一直为高，让你误判状态。
**现象**：`dbg_adc_valid` 恒 1，实际 ADC 数据只有部分拍有效。
**排查**：给调试信号加"计数器"而不是只看电平；把它的翻转次数打印出来。
**根因**：调试信号接错层级（接了常量或未驱动的寄存器）。
**修法**：调试输出必须是真实寄存器的组合，加 `ILA` 采样确认；不用的调试口在发布位流里删掉。
**验证**：该信号的翻转次数应与理论值一致（例如 1 kHz 采样 → 每秒 1000 次）。
**src**: 记录 21、`skill/testbench-blindspot.md` §3.2

## B. 约束与时序

### P-07 源同步输入的 `set_input_delay` 写反/写成对称
**触发**：ADC/编码器接口时序不过，或"过了但上板误码"。
**现象**：WNS 负很多；或 WNS 正但采样数据错位。
**排查**：`report_check_timing` 里 `no_input_delay` 是否为 0；看 XDC 里
`-max`/`-min` 是否都来自数据手册的 tCO 范围（本工程 tPD 2..6 ns）。
**根因**：把 `-max` 写成负数或写成 ± 对称区间，等于宣布数据在时钟沿之后才有效。
**修法**：`-max = tCO_max + 走线_max`，`-min = tCO_min + 走线_min`；DDR 另写 `-clock_fall`。
**验证**：负余量的路径必须能解释成"时钟沿之后到达"，否则模型错了。
**src**: 记录 6、`skill/adc-source-sync-constraints.md`

### P-08 约束的周期写小了，报告变好看但与硬件脱钩
**触发**："随手写 10 ns"，而板上时钟是 20 ns。
**现象**：WNS 好看、资源变多，上板却跑不动。
**排查**：`report_clocks` 与 `clockInfo.txt` 对账；对每个 `create_clock` 追到原理图/晶振型号。
**根因**：为了"先让它过"改约束，而不是改设计。
**修法**：约束值必须来自器件手册/板卡原理图，并在 XDC 注释里写出处。
**验证**：时钟周期表进报告 §5；任何与硬件不符的约束视为造假。
**src**: 记录 6、`skill/adc-source-sync-constraints.md` §2

### P-09 跨时钟域被 `set_clock_groups` 排除后"时序全绿"
**触发**：加了 `-asynchronous` 之后 CDC 问题从报告里消失。
**现象**：WNS 正，但偶发数据错；复位释放不同步。
**排查**：`report_cdc`（Vivado 有 CDC 检查）；人工核对每个跨域信号是否有两级同步/握手。
**根因**：约束只声明"不分析"，不保证功能；CMOS 上就是会亚稳态。
**修法**：单 bit 两级同步器，多 bit 握手或格雷码；复位用异步置位同步释放。
**验证**：CDC 报告 0 Critical；上板长时间跑（≥2 h）无错。
**src**: 记录 33、`skill/adc-source-sync-constraints.md` §4

### P-10 报告/位流不是同一次构建（"数字对不上"）
**触发**：报告里的资源与截图不一致；位流改了但报告没变。
**现象**：v85 的 LUT 86.96% 与早期报告矛盾；SHA256 对不上。
**排查**：`python tools/check_build_freshness.py`；比对 `VARIANT_INFO.txt` 时间戳与 `.bit` mtime。
**根因**：增量编译/多个 `_impl_vNN` 目录混用；手抄数字。
**修法**：一次构建一个目录，报告与位流同目录同时间戳；报告数字一律由脚本从报告解析。
**验证**：`check_impl_reports.py --dir <该次构建目录>` 的 JSON 里带 `file:line` 证据。
**src**: 记录 71、`skill/vivado-report-autocollect.md`

## C. 工程与协作

### P-11 中文文件被写成 GBK（PowerShell 默认编码）
**触发**：用 `Set-Content`/`Add-Content` 改含中文的文件。
**现象**：git diff 全文件乱码；文档里出现 `????`。
**排查**：`git diff --stat` 看是否整文件变更；用 `file`/十六进制看是否含 `\xef\xbb\xbf` 或非法字节。
**根因**：Windows PowerShell 5 的默认输出编码是 GBK，而仓库是 UTF-8。
**修法**：`-Encoding utf8`（PS7 用 `utf8NoBOM`）；或改用 Python 显式 `encoding="utf-8", newline="\n"`。
**验证**：`git diff` 只显示改动行；`python tools/check_encoding.py`（有则跑）。
**src**: 记录 64

### P-12 下载/烧写卡死，其实是被占用的 hw_server
**触发**：`program_hw_devices` 长时间无输出；或报 "Labtools" 端口占用。
**现象**：Vivado 卡在 "Connecting to hw_server"；重复点下载无效。
**排查**：`tasklist | findstr hw_server`；看 3121 端口占用；关掉其它 Vivado 实例。
**根因**：上一次会话没退干净；USB-JTAG 被别的进程持有。
**修法**：`taskkill /F /IM hw_server.exe`，重插 USB，必要时重启 Vivado。
**验证**：`open_hw_manager` 后 `get_hw_targets` 能列出目标。
**src**: 记录 42

### P-13 子代理"顺手改代码"或给出无法复核的结论
**触发**：让子代理做审计/检查。
**现象**：基线被改；报告里有结论但没有 `文件:行号`。
**排查**：`git status` 是否比预期多出改动；逐条打开它给的行号核对原文。
**根因**：任务描述没写"只读"；或子代理对结果做了合理但错误的推断。
**修法**：任务里写死"禁止修改、必须给行号、不确定放存疑表"；结论回一手资料复核。
**验证**：每条结论都能在原文里指到；误报数记下来（本工程 26 条里 3 条误报）。
**src**: 记录 9/71/73、`skill/prompts/P4_subagent_audit.md`

### P-14 文档承诺了没做的能力（"技能包 7 项"其实没有脚本）
**触发**：写文档时把"计划做的"写成"已完成的"。
**现象**：评审按文档找脚本，发现只有 .md；或报告数字与仓库现状不符。
**排查**：把文档里每个"✅""已提供"变成一次文件存在性检查
（`python skill/scripts/skill_selftest.py` 就是这种检查的实例）。
**根因**：文档由模型写、由人相信，缺少"文档→文件"的可执行对账。
**修法**：每个可交付项配一个可运行命令；文档里写明该命令的期望输出。
**验证**：命令在干净环境跑通，输出贴回文档。
**src**: 本次技能包补充的直接动因

## D. 测量与报告

### P-15 用墙上时间测性能
**触发**：用 `time` / 手表测吞吐、转速、延迟。
**现象**：同一固件两次测出 719 / 740 rpm，差 3%，无法判断是否真优化。
**排查**：检查测量脚本是否 `time.time()` 包住仿真/采集循环。
**根因**：操作系统调度、串口缓冲、USB 轮询都会引入随机延迟。
**修法**：用电周期数 + 余数（计数器）算，或用硬件时间戳；固定采样窗口。
**验证**：同一输入重复 10 次，结果标准差应为 0（或仅 ±1 计数）。
**src**: `skill/deterministic-measurement.md`

### P-16 断言只看"次数/极差/恒真"
**触发**：测试台写 `if (max - min < 100) PASS`、`assert(count > 0)`。
**现象**：DUT 把输入直通也能通过。
**排查**：逐个断言问"要让它失败，最小改动是什么"；答不出就是废断言。
**根因**：用"看起来在检查"替代"逐点比对期望值"。
**修法**：黄金模型逐点比对；恒真断言删掉；负对照注入必须能触发。
**验证**：注入清单里每条都能让测试台变红。
**src**: 记录 15、`skill/testbench-blindspot.md` §2

### P-17 报告数字手抄，正文与图表不一致
**触发**：报告由多个来源拼装。
**现象**：正文写 LUT 52.53%，表格写 52.5%，图为 53%。
**排查**：`grep` 报告里所有百分数与小数；与 `util.rpt` 自动解析结果对账。
**根因**：人工抄写/四舍五入不一致；生成脚本与正文各自维护。
**修法**：报告由脚本从报告文件解析生成（本工程 `tools/build_report_doc.py`），正文只引用变量。
**验证**：重新生成后 diff 为空；`check_impl_reports.py` 输出与正文逐字一致。
**src**: `skill/vivado-report-autocollect.md`

### P-18 只测"功能对"，没测"资源/时序/复现"
**触发**：仿真通过就认为完成。
**现象**：交作品时才发现资源超 10%、在别人机器上综合不过。
**排查**：按 `skill/templates/REPRO_CHECKLIST.md` 走一遍，特别是第 3 节"从零综合"。
**根因**：把"仿真通过"当成验收标准。
**修法**：把四份报告 + 位流 SHA256 + 复现清单作为交付物的一部分。
**验证**：陌生机器（或干净 venv/另一目录）全流程跑通。
**src**: `skill/repo-reproducibility.md`

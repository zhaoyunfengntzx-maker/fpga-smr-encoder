# 技能包 5：确定性测量方法论（低速遥测测高速信号）

## 1. 一句话 / 解决什么问题

当你的"测量仪器"是一条**远慢于被测信号、且会丢数据**的链路（10 kHz 遥测帧测 20 kHz 输入、
USB 批量到达、丢帧 0.75%）时，有三种"看起来对、其实错"的算法，和两种"看起来不行、其实可行"的方法。
本技能给出判据与算式，让你在**不提高硬件帧率**的前提下拿到 0.03% 级别的频率读数与相位重建。

三个坑：① 用"收到多少帧"当时间基准；② 用上位机墙上时间当时间基准；
③ 把"相位不动"误判成"没信号"。

## 2. 适用范围

- 遥测/日志链路带宽远小于信号带宽（本工程：10 kHz 帧率 vs 20 kHz 输入）。
- 链路会丢帧或有检错重同步（本工程实测总丢帧 ≈ **0.75%**）。
- 你需要的是**被测物理量**（频率、相位、占空比、转速），而不是"这段数据的长度"。
- 不适用：你需要**波形形状**的场合——那必须靠缓存/示波器/ILA，或改用 §3.2 的等效采样。

## 3. 使用方法

### 3.1 频率：整数电周期数 + 小数残差（唯一正确的主口径）

设每帧携带一个绝对位置 `pos_full`（多周期计数 << 16 | 单周期角度），帧率 `F_s = 10 000 Hz`。

```python
# 整数部分：窗口内位置增量取整 —— 对丢帧免疫（丢帧只会少算增量，不会改变增量的整数部分）
n_int = int((pos_end - pos_start) / 2**16)

# 小数部分：每帧角度残差（mod 1 个电周期）—— 丢帧也不影响它的统计含义
frac  = mean(mod(angle_i / 2**16, 1.0) 的收敛值)

f_in = (n_int + frac) * F_s
```

**为什么不能除以"收到的帧数"**：链路丢了 0.75% 的帧，分母变小 ⇒ 频率被**抬高约 0.8%**。
实测：真值 **20 000 Hz**，错误口径读数 **20 156 Hz**（+0.78%），
正确口径读数 **19 999.9 Hz**（−0.1 Hz，与 50 MHz 晶振的 ±5 ppm 一致）。

**为什么不能除以墙上时间**：USB 批量到达/排队会引入**几个百分点**的抖动（实测 1 s 窗差 1.5%），
墙上时间口径只配当**参考**，不配当读数。

**双口径自检（务必实现）**：

| 两种口径之差 | 含义 | 动作 |
|---|---|---|
| ≤ 2% | 正常 | 直接用读数 |
| > 2% | 值得警惕 | 读数不变，**卡片上给告警** |
| > 10% | 每帧跨过半个电周期，整数部分已不可信（通常丢帧过半） | **改用带丢帧补偿的帧数时钟口径**，并在界面上写明"已改用帧数时钟口径" |

### 3.2 相位/波形：等效采样（equivalent-time sampling）

原理：把**每一帧**当作"以输入电角度为横轴的采样点"，因为每帧的输入相位都在缓慢漂移
⇒ 把样本按角度分箱（如 256 箱）取均值，就能重建出**远高于帧率**的周期波形。

```
横轴 = 输入电角度（由本帧角度给出）
纵轴 = 该帧的某路输出电平（如 A/B/Z/UVW 六路）
分箱 = 帧数与输入频率的"可通约性"决定填箱速度
```

**关键判据（决定你能不能看到波形）**：当 `f_in / F_s` 接近**整数**时，
每帧落在输入周期内的相位**几乎不动**，于是分箱**几十秒都填不满**。
- 本工程实测：`f_in ≈ 20 000 Hz`、`F_s = 10 000 Hz` ⇒ 比值 **≈ 2.000×**，
  每次运行相位只漂 **0.1 Hz** ⇒ 8 s 只填了 **44%（113/256）**，而 Z 脉冲曾出现 **0、16、121、123 帧**的极端观测
  （理论上每 10 秒应见约 5 个）。
- **零改动的解法**：把信号源频率从帧率的整数倍**挪开**（例如 `20 000 → 20 100 Hz`），
  相位会在 1 秒内扫完整个周期。
- **这不是缺陷**：等效采样本身就需要"慢慢扫相位"。把它写进文档，而不是当成 bug 修。

**Z 脉冲是特例**：Z 只占 AB 周期的约 **3.9%**，且每 **64** 个输入周期才出现一次
（`POLE_BITS=6`）；在上述整数比条件下，它可能几十秒一帧都抓不到。**允许 Z 出现在窗口标志之外**是 RTL 有意为之。

### 3.3 覆盖率与平衡性：把"看起来对"变成可判读的数字

重建出来的波形必须给出**覆盖度**，否则"画出来了"没有意义：

| 指标 | 本工程实测 | 判据 |
|---|---|---|
| AB 分箱覆盖 | **214/256 = 83.6%** | 与"可通约性"直接相关，低于 100% 不是故障 |
| UVW 分箱覆盖 | **256/256 = 100%** | 六扇区应全复盖 |
| A/B 占空比 | **50.5% / 49.5%** | 理想 50% |
| A→B 相位 | **−90.0°** | 理想 −90° |
| 六状态均衡最大偏差 | **1.02%**（各 ≈16.7%） | ≤ 数个百分点 |
| 非法 UVW 帧数 | **0** | 必须为 0 |

### 3.4 采样不足时要"说出来"，不要画出来

当 `inter` 与分箱数使等效采样也不足时，A/B 会被混叠成一条**看着很像方波**的假波形
（实测 `inter=256` + 256 箱时，**1.406°** 的真周期被混叠成 **~7 个周期/360°**）。
正确做法：**主动检测并改写标题**为"采样不足：A/B 波形不可信，只看 Z 与读数"。
⇒ 通用教训：**在数据上标注"我不确定"，比强行画出来更专业**（这条也写进了技能 3 §5）。

## 4. 失效条件

- `n_int` 的口径成立的前提是**每帧的位置增量 < 0.5 个电周期**；超过就发生周跳，
  必须改用更强的判据（本工程的阈值就是 §3.1 表里的 **10%**）。
- 等效采样**不适用于非周期或频率变化很快的信号**：它的前提是"相位在窗口内缓慢、单调地漂"。
- 等效采样给出的是**平均后的稳态波形**，看不到单次事件（毛刺、偶发丢步）。
  这类问题必须回到 ILA / 示波器 / 片上缓存。
- 若链路存在**时延抖动（jitter）而不是丢帧**，§3.1 的整数口径仍然成立，
  但"墙上时间口径"与它的差值会**系统性偏大**，不要据此判故障。

## 5. 提炼过程（从哪些失败或观察中总结）

1. **错误的频率口径被发现**：上位机最初用"位置增量 ÷ 收到的帧数"，
   真值 20 000 Hz 时读 **20 156 Hz**（+0.78%）——**与丢帧率同量级**，一开始被当成"信号源不准"。
   定位方式：把"帧数时钟 + 丢帧补偿"作为**独立第二口径**（20 006 Hz）与它对账，
   两者差 0.03% 说明是分母问题而不是信号问题。
2. **墙上时间口径的边界被量化**：USB 批量到达导致 1 s 窗内差 **1.5%**，
   因此定了"只当参考 + 差 >2% 给告警"的规则。
3. **"相位不动"被误判为"没有信号"**：Z 脉冲多次一帧都抓不到，
   排查方向一度指向 RTL 或接线；最后发现是 `f_in/F_s ≈ 2.000` 的整数比导致相位不漂。
   定量证据：`host/selftest_s4.py` 记录"8 s 只填 44%"，
   而把信号源从 20 000 Hz 挪到 20 100 Hz 后 1 秒内扫完整个周期。
4. **假波形被主动标注**：`inter=256` + 256 箱时的混叠结果（1.406° 真周期 → ~7 周期/360°）
   看起来完全像一条正常方波，只有把参数代进去手算才发现。⇒ 界面因此增加了"采样不足"判定与标题改写。
5. **覆盖度成为硬指标**：等效采样页面最终把"AB 箱覆盖 / UVW 箱覆盖 / 占空比 / 相位 / 六态偏差 / 非法帧数"
   六个数字同时打出来——**只有六个都对，"波形是对的"这句话才成立**。

**可直接借用的动作清单**：
① 主口径一律用"整数 + 残差"，并在代码里保留**第二独立口径**用于对账；
② 给两个口径的差值设**分级阈值**（2% 告警 / 10% 换口径）并写在界面上；
③ 任何重建波形都要同时给出**覆盖度**；
④ 把"相位不漂"作为一种**可预期的**现象写进文档，而不是留给下一个人重新排查。

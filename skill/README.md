# 技能包（Skill）总目录

> 本目录是本作品随工程一并提交的**可复用技能包**，对应《2026 FPGA 创新设计赛道选题指南》
> 自主选题赛道 3.3.5.2「技能包」一节的要求：
> 目录内每一项须写明**适用范围、使用方法与失效条件**，并说明**它是从哪些失败或观察中总结出来的**；
> 官方评价标准只有一句：**「一支陌生队伍拿到该目录，能否直接用在自己的题目上」**。
>
> 本目录中每一项都标注了它在**本工程之外**能用的场景（换题目、换板卡、换器件仍然可用），
> 以及它**在什么条件下会失效**。凡涉及"实测数字"的段落，均给出可回溯的证据锚点
> （`docs/DEV_STATUS.md` 章节号 / `sim/logs` / `_synth_work` 报告名 / 源文件行号）。

## 每一项的统一结构

每一项技能包都按同一模板撰写，便于陌生人扫读：

```text
# <技能名>
## 1. 一句话 / 解决什么问题
## 2. 适用范围（什么情况下用得上）
## 3. 使用方法（可直接照做的步骤 / 可复制的命令）
## 4. 失效条件（什么时候它不成立 / 必须换成什么做法）
## 5. 提炼过程（从哪些失败或观察中总结出来的 —— 含真实数字与锚点）
## 6. 已验证的效果（在本工程中的实测收益）
```

其中 §5 是竞赛指南点名要求的「从哪些失败或观察中总结」；§4 是「失效条件」。
**两节都不允许写"一般来说要注意……"这种空话**，必须有名有姓：哪个信号、哪一行、哪个数字。

## 怎么直接拿去用（给陌生队伍的三步）

1. 只想抄一条经验：直接读目标技能的 **§3 使用方法** 与 **§4 失效条件**，这两节是自包含的。
2. 想把技能 6（报告自动采集）搬到自己工程：把 `tools/` 下对应脚本与一个 `_synth_work/` 输出目录摆好，
   改脚本顶部的路径常量即可；脚本不依赖本工程的任何自定义 IP。
3. 想复现本工程：从根 [`README.md`](../README.md) 的「快速开始」按顺序执行；
   **不要**假设需要 PYNQ 或 PS——本工程是全 RTL、单时钟域设计。

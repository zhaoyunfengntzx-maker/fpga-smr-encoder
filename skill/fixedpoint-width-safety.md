# 技能包 2：定点位宽 / 截断安全检查（四类"静默错值" + v70 符号扩展死锁）

## 1. 一句话 / 解决什么问题

Verilog 的 `+`、`<<`、`{}`、`*` 都**不会告诉你它截断了**——结果是一个语法正确、仿真能跑、
偶发错误、且错误表现为"某些数据点不对"的**静默错值**。
本技能给出四类会在真实工程里反复出现的模式，以及每一类的**判据**（看到什么形状就该怀疑它）。

**一句话判据：凡是"拼接后参与算术"或"算术结果赋给一个刚够宽的网线"的表达式，都默认它是错的，除非你逐位算过。**

## 2. 适用范围

- 任何定点算术：乘法、比例缩放、相位/角度扩展、定标换算。
- 任何"把两个字节拼起来当 16 bit 用"的总线/寄存器解码。
- 任何 ADC/DAC 原始码到物理量的换算（偏移二进制 vs 二补码是高频坑）。
- 不适用：纯控制路径（状态机、握手），那里位宽意义不承载数值语义。

## 3. 使用方法（四类模式 + 每类的判据与改法）

### 3.1 类别 A：拼接/移位后相加 —— 操作数与被赋值对象位宽不匹配

**错误写法**（本工程真实发生过，`rtl/uvw_gen.v` 历史版本）：

```verilog
wire [AW+2:0] eang_x6;                                  // 18 位
assign eang_x6 = {eang, 2'b00} + {eang, 1'b0};          // 两个操作数都只有 18 位！
```

`{eang,2'b00}` = `eang*4`（18 bit），`{eang,1'b0}` = `eang*2`（18 bit）。
两个 18 bit 相加的结果**在赋值时被截断成 18 bit** ⇒ `eang_x6 = (eang*6) mod 2^18`。
而 `assign sec_raw = eang_x6[AW+2:AW];` 取的是 `eang*5` 的高 3 位。

**正确写法**（位宽显式、语义自证，多留 1 位给进位）：

```verilog
wire [AW+2:0] eang_x6;
assign eang_x6 = ({3'b0, eang} << 2) + ({3'b0, eang} << 1);   // eang*4 + eang*2 = eang*6
assign sec_raw = eang_x6[AW+2:AW];                             // 0..5
```

**位宽校验**：`eang ≤ 65535` ⇒ `eang*6 ≤ 393210 < 2¹⁹ = 524288`，所以 19 位（`AW+3`）足够。
**判据**：如果 `eang*6` 的正确上界只比被赋值网线宽度小不到 1 位，就必须做这个乘法上界验算。
**快速自检口诀**：*拼接表达式里每一个 `{}` 都只影响它自己那一位宽，相加之后归谁管，由最左边那个 wire 决定。*

### 3.2 类别 B：移位方向与舍入方向

- `>>>` 对 **signed** 是**向 −∞ 取整**，而算法常常要求**向零截断**（见技能 1 §5）。
- `>>` 对 **unsigned** 是逻辑移位，**不会饱和**：`8'hFF >> 1 = 8'h7F`，若数学期望是 127.5 或饱和到 255，都是错的。
- **判据**：写下这一行时，问自己"这个变量会出现负数吗？会出现上溢吗？"，两个问题都答完才允许写移位。

### 3.3 类别 C：偏移二进制 vs 二补码

AD9238 这类 ADC 输出的是**偏移二进制**（`0x800` = 零点），直接当有符号数参与算术会得到
一个"整体偏 2048"的结果——而它看起来只像"标定没做好"。
**判据**：ADC 原始码进入算术前，必须有一处显式的 `^ (1 << (BITS-1))` 或 `- (1 << (BITS-1))`，
并且在规格文档里写明是偏移二进制。本工程的定点格式表在 `rtl/SPEC_interface_contract.md` §0.2。

### 3.4 类别 D：Q 格式不对齐

Q1.15 的 `1.0` 是 32768，Q0.16 的 `1.0` 是 65536。两类数直接相加/比较就是**静默错值**。
**判据**：每个常量与每个变量都在规格表里带 Q 标记；凡是在代码里看不到 Q 标记的算术表达式，都视为待审计。

### 3.5 类别 E（v70 真机追加）：0..2^N−1 的无符号相位被"先符号扩展再相减"

**错误写法**（`rtl/pole_counter.v` v69，真机整机失效）：

```verilog
wire signed [AW+1:0] step_s = $signed(ang_s0) - $signed(ang_s1);   // ang 是 0..65535 无符号
```

`ang_s0=32851`、`ang_s1=32718` 时正确增量是 **+133**，但两个数都 ≥32768，被解释成负数
（−32685 与 −32818）⇒ `step_s = −65403`。累加器每跨半圈被扣掉 2^16，正负相消 ⇒ `cycle_cnt` 恒 0。

**正确写法**（先做模 2^N 无符号差，再零扩展成有符号）：

```verilog
wire [AW-1:0]        diff_u = ang_s0 - ang_s1;                // 模 2^AW，天然落在 0..2^AW−1
wire signed [AW+1:0] step_s = {{2{diff_u[AW-1]}}, diff_u};    // 零扩展：保留 ±180° 内的符号
```

**判据**：凡是 `$signed(x) - $signed(y)` 里 x/y 是"0..2^N−1 的相位/角度/计数器"，先问
"它们会不会同时 ≥2^(N−1)？"——跨半量程是**必然事件**（每转都发生），不是边界情况。
**快速验算**：合法的 `step_s` 应落在 ±2^(N−1)；若某一步的绝对值接近 2^N，就是符号扩展错了。

## 4. 失效条件

- 本技能是**静态审计清单**，它**不能替代仿真**：类别 A 的错误在某些数据范围下结果仍然正确
  （本工程 65536 个角度点里 32768 个错、32768 个对，**恰好一半**），
  只测几个点必然漏掉 ⇒ 必须配合技能 3（遍历状态空间）。
- 位宽放宽不是万能药：把 18 位改成 32 位能消除截断，但会同时放大布局面积与布线延迟；
  正确做法是**算出真实上界再留 1 位**，而不是"一律加宽"。
- 若设计里出现超出工具链综合能力的巨大位宽（例如 4096 位累加器），应改用分段累加或移位累加结构。
- 类别 E 只在**跨半量程**时触发：小角度激励下 `cycle_cnt` 完全正常，33/33 回归全绿也发现不了 ——
  必须用"跨 32768"的定向激励（本工程 `_boardtest/tb_acc2.v` 用 3000 个 +133）或真机整圈数据。

## 5. 提炼过程（从哪些失败或观察中总结）

**案例来源：`rtl/uvw_gen.v` 的 `eang*6` 被截断成 `eang*5`（已定位并修复）**

- **现象**：UVW 六步换相的扇区边界位置不对，且每个输入周期在 4→5→6→7→0 处产生 **1 拍毛刺态**。
- **根因**：见 §3.1；`eang = 8192` 时 `eang*6 = 49152`，但 18 位读出 40960 = `8192*5` ⇒ `sec_raw` 算出 0（应为 1）。
- **影响面（逐位算出来的，不是估的）**：65536 个角度里 **32768 个（50.0%）扇区号偏小 1**；
  真实扇区边界变成 `13108 / 26215 / 39322 / 52429`，应为 `10923 / 21846 / 32768 / 43691 / 54614`。
- **为什么一直没被发现**：原 TEST 1/2 只统计"6 次切换"与"6 状态驻留极差 ≤2"，
  而截断后的**平均驻留仍约 10923 拍**——**结构上不可能暴露它**。
  ⇒ 这是本技能与技能 3 共同的核心教训：**"断言全绿"与"逻辑正确"是两回事**。
- **修复验证**：新增 `sim/tb_uvw_gen.v` TEST 9 **逐角度扫描全部 65536 个点**，
  实测 5 个边界**精确等于** `ceil(k*65536/6)`，`sec_raw > 5` 的拍数 = **0**。
- **★ 附带教训（关于"看代码推演"）**：该表达式在修的时候，曾被先后两次误写成 `eang*3`
  （一次是在推演里、一次是在注释里）⇒ 结论：**这种"拼接 + 相加"表达式必须用实测数值验证，
  不能只看代码推演**。这句话已写进 `README.md` 的踩坑表与 `docs/05_vivado_sim_impl_report.md` §430 附近。

**案例 2 来源：`rtl/pole_counter.v` 的 `step_s` 符号扩展死锁（v69 真机，2026-11-01 定位并修复）**

- **现象**：屏上角度在动、ABZ 正常，但 RPM 恒 0、Z 不出现、UVW 不换相、BiSS 多圈全 0，
  四个观测量**同时失效**；10 s / 101,718 帧内 `cycle_cnt` 一个数都没变。
- **误判一**：先怀疑转台 PPR / `POLE_BITS` 配置。用 A/B 换位（换回已签核 v68 位流）证伪：
  症状完全相同 ⇒ 不是配置，也不是转台换了。
- **定位**：加"探针位流"（`wrap_p_raw = pair_valid`）读到 `distinct = 2049`，证明**角度有效**、
  只是增量没进累加器；模型仿真 `tb_dbg6` 复现
  `BADSTEP i=246 s0=32851 s1=32718 step=-65403 acc=32585` —— 正是附录 §3.5 的数字。
- **修复**：`diff_u = ang_s0 - ang_s1` + `{{2{diff_u[AW-1]}}, diff_u}`；`tb_acc2` 3000 个 +133
  从 `cycle_cnt=0` 变 6（理论 6.09），再 3000 个变 12（不丢圈、不重复）。
- **为什么回归没抓住**：33/33 测试台的激励都是"小角度、不跨 32768"，而该错误**只在跨半量程时**
  产生错误增量。这是"断言全绿 ≠ 逻辑正确"的第二个独立实例（第一个是 §5 的 `eang*6`）。
- **真机复验（5 条判据全过）**：Z 12.00 Hz；`cnt` 跨度 −2047..0、`distinct=2048`；719–731 rpm；
  UVW 六态均匀、293 换向/s；60 s / 598,115 帧无累积漂移。详见 `docs/33_v70_release_report.md`。

在每次提交前 grep 四个形状：① `{.*}.*[+-]` （拼接参与算术）

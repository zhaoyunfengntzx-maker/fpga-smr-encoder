# 技能包 1：与 RTL 逐位一致的定点黄金模型

## 1. 一句话 / 解决什么问题

**在写 RTL 之前，先用 Python 写一份"定点语义与 RTL 逐位一致"的参考模型**，用它给出算法正确性的数字结论；
再用它逐点对账 RTL 仿真，把"算法本身错"和"RTL 实现错"这两类 bug **彻底解耦**。

没有黄金模型时，一个 0.02° 的误差你不知道该怪公式、怪位宽、还是怪时序；
有了黄金模型，误差只有三种可能：模型本身就错（可单独验证）、RTL 没照模型实现（可逐点定位）、
或者误差已经在量化底噪之内（可以收工）。

## 2. 适用范围

- 任何包含**定点 DSP**（CORDIC、滤波器、坐标变换、PID、CRC、插值）的 FPGA 项目。
- 算法有数学定义式、但要在有限位宽下实现，且最终指标是"误差 ≤ X LSB / X 度 / X %"。
- 硬件还没到、仿真器还没跑通，但你需要**先证明算法链路成立**并拿到可写进报告的数字。
- 反过来：如果你的设计只是状态机/接口协议，没有算术，那不需要这个技能（见技能 3 更合适）。

## 3. 使用方法

1. **先定死"定点格式表"**，写在一份规格文档里（本工程是 `rtl/SPEC_interface_contract.md` §0.2）：
   每个信号的 Q 格式、位宽、有无符号、饱和还是回绕、右移是向零还是向下取整。
   这张表是模型与 RTL 之间唯一的合同，**不允许任何一方"顺手"改一个移位方向**。
2. **在 Python 里显式实现每一个语义**，不要用 Python 的默认行为顶替：

   ```python
   def asr(v, n):        # 算术右移：向 -inf 取整，对应 Verilog signed 的 >>>
       return np.floor_divide(np.asarray(v, np.int64), 1 << n)

   def trunc_shift(v, n):  # 向零截断的移位：RTL 里必须显式实现
       v = np.asarray(v, np.int64)
       return np.where(v >= 0, v >> n, -((-v) >> n))

   def sat_signed(v, bits):  # 有符号饱和
       lo, hi = -(1 << (bits - 1)), (1 << (bits - 1)) - 1
       return np.clip(v, lo, hi).astype(np.int64)
   ```
3. **把常量表按定义式现算，不要手抄**：
   `ATAN_TABLE = [round(math.atan(2.0 ** -i) / (2 * math.pi) * (1 << ZW)) for i in range(NITER)]`
   （手抄表会带固定偏置，本工程实测 **−0.38 LSB** 系统偏置就是这么来的）。
4. **让模型自己打印结论数字**，并且**凡是会被写进报告的数字都在模型里现算**：

   ```python
   #  ✓ 现算：从 rows 里取复合畸变工况与最差工况
   comp = [r for r in rows if r["name"].startswith("E ")][0]
   worst_row = max(rows, key=lambda r: r["e_cor_max"])
   print("%.4f deg -> %.4f deg，改善 %.0f 倍" % (comp["e_raw_max"], comp["e_cor_max"],
                                             comp["e_raw_max"] / comp["e_cor_max"]))
   ```
   ★ **不要把数字写死在打印语句里**：本工程 2026-10-10 把粗调判据统一成 1.999 后，
   复合畸变残余由 0.0220° 改善到 0.0165°（最差工况换成了另一条），
   写死的字符串会和同一份输出里的表格自相矛盾。**报告里的数字必须是模型当场算出来的。**
5. 用**全周细网格扫描**（本工程 2²⁰ = 1,048,576 点）而不是抽几个角度点，否则看不到最坏点。
6. 每次改 RTL 的算术部分，**先改模型**，再让 RTL 对齐模型，最后跑 tb 对账。

## 4. 失效条件

- **模型不是参考**：如果模型的定点语义和 RTL 不一致（哪怕只差一个 `trunc_shift` 与 `>>`），
  它给出的数字**没有任何意义**——它只是在验证它自己。判据：8 个正交/45° 精确边界点误差必须**全为 0**，
  若不为 0，先怀疑模型而不是 RTL。
- 模型**不能替代时序验证**：它不覆盖跨时钟域、不覆盖建立/保持、不覆盖复位序列。
- 模型**不能证明"硬件能做出来"**：本工程的模型结论成立，靠的是后续综合实现时序收敛（WNS +0.959 ns）
  与上板实测两条独立证据；只有模型数字而没有这两条，不足以支撑报告结论。
- 位宽放大到 numpy int64 之外（例如 > 2²⁰ 的累加器）时，`np.int64` 会静默回绕，必须先做位宽预算。

## 5. 提炼过程（从哪些失败或观察中总结）

本工程踩到、后来都写进模型的真实案例：

1. **`>>>` 在负数上不是"除以 2ⁿ"**：Verilog 对 signed 的 `>>>` 是**向 −∞ 取整**，
   而算法要求**向零截断**。实测：不修则 RMS 误差 0.597 LSB，修后 0.3229 LSB。
   ⇒ 模型里因此专门有 `asr` 与 `trunc_shift` 两个函数，**不许混用**。
2. **CORDIC 迭代级数必须取 17 而不是 16**：16 级时残余项叠加量化误差后最坏角误差
   **1.19 LSB > 1 LSB** 目标；17 级降到 **0.9375 LSB**（裕量 6.25%）。
   ⇒ 这个结论只能来自全周扫描，不能来自"看起来够用"。
3. **x/y 内部多留 4 位小数**（FEXT=4）：实测最坏 1.50 LSB → 0.9375 LSB。
4. **输出前加半个 LSB 四舍五入**：消除 −0.5…−1 LSB 的**系统性负偏置**，RMS 0.597 → 0.3229 LSB。
   判据是"均值"而不是"最大值"——**系统偏置只能从全周扫描的均值看出来**。
5. **象限折叠写反会引入 180° 固定误差**（实测偏 100°~180°）：这是最典型的"数值看着像对的"错误，
   因为每个点的误差都很大但方向一致，只看单点误差曲线会以为是"整体标度问题"。
6. **黄金模型先于硬件给出结论**：三层验证体系（模型 → RTL 仿真 → 实物）里，
   **第一层的数字在硬件做出来之前就已经有了**，这正是后续所有实物测量"对得上账"的前提。

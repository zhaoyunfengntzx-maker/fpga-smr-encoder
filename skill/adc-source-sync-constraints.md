# 技能包 4：源同步并行接口的 `set_input_delay` 诚实建模

## 1. 一句话 / 解决什么问题

FPGA 用一个输出时钟去驱动外部器件（ADC / DAC / 摄像头 / 并行 Flash），数据再随同一个时钟回来——
这叫**源同步**（source-synchronous）接口。这类接口的时序约束**不是"抄一个数"能写对的**，
因为约束里那个 `set_input_delay` 的值，等于**"数据到 FPGA 引脚的时刻"减去"FPGA 引脚上那个时钟沿的时刻"**，
而这两个时刻都必须从**发射链的每一段**算出来。

写小的后果：工具报"时序满足"，但板上是**赌运气**；
写大的后果：工具报负余量，但**没有任何工程师能解释每一条是什么**，于是被当成"设计坏了"。
本技能给出把这条链**逐段量化**的方法，以及"算完之后怎么用实测收口"。

## 2. 适用范围

- 任何"FPGA 提供时钟 + 外部器件返回并行数据"的接口。
- 任何你在 XDC 里写过 `set_input_delay` 但**说不清那个数字是怎么来的**的场合。
- 反之：若接口是真正的系统同步（外部时钟来自板载晶振、与 FPGA 输出时钟无关），
  你需要的是一条独立的 `create_clock`，而不是本技能。

## 3. 使用方法

### 3.1 五步推导（每一段都要给出处）

| 段 | 含义 | 本工程取值 | 出处 |
|---|---|---|---|
| ① 源时钟延迟 | 内部时钟到 ODDR 的延迟 | **3.762 ns** | `_synth_work/impl_timing.rpt` 的 `ad_clk` 输出路径 `Source Clock Delay` |
| ② 相位移动 | ODDR 相对时钟沿的相位（0 或半周期） | **0 ns（同相）** | `rtl/enc_top.v` 的 ODDR 相移设置 |
| ③ 输出缓冲 | ODDR + OBUF + 走线 | **3.016 ns** | 同上报告的 `Destination Clock Delay` |
| ④ 器件 `tPD` | 外部器件"时钟沿 → 数据有效" | **2…6 ns（手册）** | AD9238 数据手册；**不是**可以猜的量 |
| ⑤ 板级 | 排线/走线传播 | **≈1 ns**（每 15 cm 约 1 ns） | 实物长度实测 |

```
set_input_delay -max = ① + ② + ③ + ④_max + ⑤
set_input_delay -min = ① + ② + ③ + ④_min + ⑤
```

### 3.2 本工程的最终约束（`constr/enc_top.xdc:219-222`）

```tcl
set_input_delay -clock sys_clk -max 14.000 [get_ports {ad_ch1_d[*] ad_ch2_d[*]}]
set_input_delay -clock sys_clk -min  9.500 [get_ports {ad_ch1_d[*] ad_ch2_d[*]}]
set_input_delay -clock sys_clk -max 14.000 [get_ports {ad_ch1_otr ad_ch2_otr}]
set_input_delay -clock sys_clk -min  9.500 [get_ports {ad_ch1_otr ad_ch2_otr}]
```

`14.000 = 3.762 + 0 + 3.016 + 6 + 1 ≈ 13.78`；`9.500 = 3.762 + 0 + 3.016 + 2 + 1 ≈ 9.78`（向下取整取整）。
**OTR 与数据走同一排线、来自同一器件，所以必须用同一组值**——早期版本给 OTR 单独写 `max 8.000`，
比数据多 1 ns 且无器件依据，属"看起来更谨慎、其实是编的"。

### 3.3 把"历史口径"留在约束文件里，而不是删掉

约束文件里同时保留三样东西（本工程 `constr/enc_top.xdc:195-254` 就是这么写的）：

1. **当前生效的约束值**（上面四行）；
2. **旧口径 + 为什么作废**：`24.000/19.500` 是"发射沿晚 10 ns（反相）"时的诚实值，
   相位移改到同相后变成 `14.000/9.500`；
3. **实测收口记录**：示波器实测 `tPD_meas = 3–4 ns`（在手册 `2…6 ns` 内）
   ⇒ 建立余量 ≈ **+12.3 ns**，因此"改下降沿捕获 / 缩线 / 降采样率 / `set_false_path`"这四步**不必执行**。

> 为什么这样做：评委/接手人会问"你这条约束为什么是这个数"。**能指出每一段的出处，
> 并且能指出上一版为什么错**，才是"设计过程中判断依据"的证据，而不是"我们抄了一个模板"。

### 3.4 实测收口（必做，不能只靠算）

- **探针选择**：探 FPGA 输出的 `ad_clk` 与外部器件的**最高位/符号位**，
  量"时钟沿 → 数据跳变"的延迟 `tPD_meas`。
  ★ **不要探 `D0`**：满幅正弦下 `D0` 每秒跳变数百万次，在 5 ns/div（屏宽 50 ns）下必然糊成一片，
  那不是故障。符号位只在过零点翻转（1 kHz 输入 ⇒ 20.18 kHz），触发挂它即可。
- **判据**：`tPD_meas ≤ 4 ns` ⇒ 继续；`≥ 5 ns` 或 ILA 里角度有毛刺 ⇒ 改相位（见 §3.5）。
  本工程实测 **3–4 ns**。
- **记录表**：把测量时间、探头接点、读数写进一份独立的记录文件（本工程 `docs/09_scope_measure_log.md`），
  否则半年后无法回答"这个余量是量出来的还是算出来的"。

### 3.5 余量为负时的处理顺序（先测量，再改功能，最后才改约束）

1. 缩短排线（≤5 cm）/ 在时钟线上串 22~33 Ω；
2. **功能级修复**：把捕获寄存器改到 `clk_i` **下降沿**（同一个 BUFG 时钟，只换边沿），
   建立窗口从 ~7.8 ns 变成 ~17.8 ns；代价是需要在捕获后加一级 `posedge` 重定时。
   ★ **"晚一个周期再捕获"没有用**——数据周期与捕获周期相同，相位关系不变。
3. 降采样率（注意：`create_clock -period` 改成 40.000 **不是**降采样率，那只是改约束）；
4. **最后**才 `set_false_path`，且必须在进度文档里写明"该路径未做时序分析"。

## 4. 失效条件

- **极性/相位口径必须先对**：本工程曾同时存在两套互斥说法——一处说"`ad_clk` 上升沿比内部时钟晚 10 ns、
  建立余量 3 ns"，另一处说"两者上升沿在同一物理时刻"，而约束按后者写（`max 7.000 / min −1.000`）。
  真原语对照实验证明**前者为真**，于是改成诚实约束后出现 **WNS −3.271 ns / 26 个失败端点**。
  ★ 教训：**"约束里的数字"与"注释里的结论"必须互相印证；不一致时先做一次能分辨两者的实验。**
- 本技能只对**固定相位**成立：若设计改用 `IDELAYE2`/`IDELAYCTRL` 动态吃相位
  （例：Xilinx 官方 RGMII 例程默认 `IDELAY_VALUE = 0`，靠 tap 扫描），
  则"`set_input_delay` 推导"不再是主要手段，必须改为说明 tap 的扫描范围与判据。
- 若外部器件的 `tPD` 手册里没给（或给的是典型值），本技能给出的是**上界模型**，
  必须用 §3.4 的实测把余量收口，否则只是把不确定性从代码搬到了报告。
- 位宽/总线：数据与 OTR（或任何随路控制信号）若走**不同长度**的走线，必须各算各的，
  不能共用一组值（本工程正是"同器件、同排线"才允许共用）。

## 5. 提炼过程（从哪些失败或观察中总结）

1. **两套互斥说法并存半个月**（`docs/DEV_STATUS.md` §1.19）：约束文件第 130 行说"晚 10 ns、余量 3 ns"，
   后面的"★★ 关键修正"块说"引脚下是同一时刻"，并把约束写成 `max 7.000 / min −1.000`。
   真原语对照实验证明前者为真，但**约束没跟着改**。
2. **把整条发射链算进去之后，结论变成"设计本来就没有 50 MHz 的建立余量保证"**：
   `16.78 ns`（引脚沿）+ `tPD 2…6` + 排线 `1` ⇒ 数据到脚 **19.78…23.78 ns**；
   而捕获寄存器看到的沿 ≈ 24.0…24.6 ns ⇒ 最坏 **−1.6 ns**、典型 **+1 ns**
   ⇒ 原来的"3 ns 余量"是**漏算了两条时钟网络路径**的乐观结论。
3. **诚实约束的代价被完整记账**：改后生产版 `WNS −3.271 / TNS −84.284 / 26 个 failing endpoints`
   （24 根数据 + 2 根 OTR，正好全部输入），报告结论行第一次变成 `Timing constraints are not met.`。
   关键解读：这 26 条**全部**是"ADC 数据相对内部时钟的建立关系"，由外部往返延迟决定，
   **不是**内部逻辑不收敛（内部寄存器到寄存器最差仍在 18–19 ns 量级、余量为正）。
4. **后来找到真正的根因是相位口径**：ODDR 相移与生成的采样时钟极性不匹配，
   去掉两处 `create_generated_clock -invert` 后，`WNS` 从 **−3.352** 回到 **+0.959 / 0 个失败端点（11,275 端点）**，
   并可给出精确归因：**负值里约 3 ns 是相位口径错误，其余是真实建模余量**。
5. **实测把最后的问号收掉**：`tPD_meas = 3–4 ns` ⇒ 建立余量 ≈ **+12.3 ns**（`tPD=3.5` 时；
   按手册 `2…6 ns` 展开为 **+13.8 … +9.8 ns**），与 XDC 的推导区间一致。

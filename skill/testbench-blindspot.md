# 技能包 3：测试台盲区排查（"断言全绿"为什么会漏掉 50% 的缺陷）

## 1. 一句话 / 解决什么问题

一个测试台写完之后，**唯一有意义的检查是"它的断言能不能抓住我已经知道的错"**，
而不是"它有没有打印 TEST PASSED"。
本技能给出"盲区"的定义、三类会制造盲区的断言形状，以及把它们换成不会骗人的检查的方法。

**盲区定义：一个测试台对某类缺陷恒返回 PASS 的性质。** 盲区不是没写断言，而是**断言与缺陷正交**。

## 2. 适用范围

- 任何有状态机 / 有相位 / 有分频 / 有"每 N 拍一次"行为的 RTL。
- 任何"输出看起来对，但其实只是平均值碰巧对"的场合。
- 不适用：纯组合逻辑的查找表函数（穷举输入就够了，不需要"盲区"分析）。

## 3. 使用方法

### 3.1 三类制造盲区的断言形状（看到就改）

| 形状 | 为什么有盲区 | 换成什么 |
|---|---|---|
| **只看次数、不看位置**<br>`if (switch_cnt == 6) PASS;` | 任何"周期正确、相位错、边界错"的实现都会满足它 | 同时断言**每个边界的绝对位置**（期望值用公式现算，不要写死） |
| **只看极差 / 只看平均**<br>`if (max_dwell - min_dwell <= 2) PASS;` | 偏差是**系统性**的时候，极差与平均都可能恰好合格 | 逐个**状态**与期望值比对，而不是只比对它们的差 |
| **断言一个恒真/恒假的条件**<br>`if (valid_bit == 1) PASS;` | 这个信号**永远是 1**，等于没有断言 | 先单独证明这个信号的取值集合非平凡（见 §3.3），再拿它做条件 |

### 3.2 三条不会骗人的检查方式（按优先级）

1. **黄金参考逐点比对**（最强）：用技能 1 的模型生成期望输出，测试台**逐点**比对，
   并统计 `最大误差 / RMS / 超差点数`。本工程顶层集成台 `tb_enc_top` 就是这样：
   **1,048,576 个角度点**逐点比对、零超差。
2. **遍历状态空间**：如果状态空间不大（例如 16 bit 角度 = 65536 点），**直接全扫**。
   本工程 `sim/tb_uvw_gen.v` TEST 9 遍历全部 65536 个角度点，
   断言的期望值用 `ceil(k*65536/6)` **现算**，因此不可能与实现"共谋"。
3. **负对照（故意制造已知错误，看它是否报错）**：把待测信号接错、把某个常量改 1，
   确认测试台**变红**。一个从没红过的测试台，不能作为证据。
   本工程 BiSS 探针就是这样组织的：A = 正常（主判据）、C = 反例、B = 受控违例。

### 3.3 "先证明测试台是活的"

对任何打算用作断言条件的信号（如 `adc_valid`、`frame_active`、`valid`），先跑一次**取值集合统计**：
把它的 0/1 计数、跳变次数打印出来。**只在取值非平凡时才允许用它做条件**。
本工程的教训：`dbg_adc_valid` 恒为 **1**，因此它作为 ILA 触发条件等于没有触发——
正确做法是改用 `dbg_z_window`（每 64 个输入周期出现一次）。

### 3.4 给测试台自己也建缺陷清单

测试台的 bug 会把真实缺陷**藏起来**。因此回归汇总里要**分开记**：
"修掉 N 个真实 RTL 缺陷"与"修掉 M 个测试台缺陷"。
本工程 2026-10-10 那一轮的记录是 **15 个真实 RTL 缺陷 + 9 个测试台缺陷**。
两个数字都要写进报告——这是"我们验证过验证器"的证据。

### 3.5 边界跨越激励（v70 追加：小角度激励的第四个盲区）

凡是"跨半量程 / 跨符号位 / 跨 0 点"才有意义的逻辑，**必须有一条专门跨越它的激励**，否则：
- 增量累加器、相位展开、多圈计数：小角度来回摆动时 `cycle_cnt` 永远正常；
- 方向判断、UVW 换相、BiSS 多圈：反向与环绕边界常常一次都没被走过。

**做法**：① 用**整圈数据**或单调斜坡跨越 `0 / 2^(N−1) / 2^N−1`；② 至少一条**反向**激励；
③ 断言"跨边界那几步的增量符号与数值"本身，而不只是最终计数。本工程 v70 之前 33/33 全绿，
正是因为所有激励都停留在"小角度、不跨 32768"。

## 4. 失效条件

- 遍历状态空间仅在小状态空间可行；对 32 bit 计数器或长序列必须改用覆盖度导向的随机/约束激励，
  并明确写出**没被覆盖的区域**（诚实标注比假装覆盖好）。
- 逐点比对要求模型可信（见技能 1 §4）：模型错了，比对越严格错得越自信。
- 负对照只能证明"测试台能抓住某一类错"，不能证明它抓住所有错；因此负对照要针对**每一类**
  关键错误各做一次，而不是只做一个。
- 断言里写死期望值 = 把参考实现与待测实现**绑在一起**，改动任何一侧都会让测试失去意义；
  期望值必须能由公式或模型生成。

## 5. 提炼过程（从哪些失败或观察中总结）

**主案例：UVW 扇区号截断（50% 角度点错）却让现有断言全绿**

- 原 `tb_uvw_gen` 的 TEST 1/2 断言是：① 一个输入周期内有 **6 次**扇区切换；
  ② 6 个状态的**驻留极差 ≤ 2**。
- 被测实现的真实缺陷：扇区号在 **32768/65536 = 50.0%** 的角度点上偏小 1，
  边界从 `10923/21846/32768/43691/54614` 错到 `13108/26215/39322/52429`。
- 为什么断言抓不到：截断后的**平均驻留仍约 10923 拍**、仍然是 **6 次**切换
  ⇒ **两个断言在结构上都与这个缺陷正交**。这不是"断言写少了"，是**断言选错了观测量**。
- 修法：新增 TEST 9，**遍历全部 65536 个角度点**，期望边界用 `ceil(k*65536/6)` 现算，
  并额外断言 `sec_raw > 5` 的拍数 = **0**。修复后实测 5 个边界精确相符。

**次案例（同类盲区的另外三种真实形态）**

1. **触发/使能信号的盲区**：ILA 探针最初挂 `dbg_adc_valid` 触发 ⇒ 永不触发。该信号实测**恒为 1**。
   改挂 `dbg_z_window` 后正常（保留期实测置位 **2489** 帧）。
2. **测试台自身缺陷掩盖 RTL 缺陷**：本工程两例——ILA 探针**位序反转**、
   UART→SPI 桥的 **TX 仲裁**问题，都是先被测试台"通过"，由另一条证据路径（ILA 上板观测 / 真机命令超时）
   才暴露出来。
3. **"看起来像方波"的假波形**：上位机在采样不足时会把混叠结果画成一条**看着很像方波**的曲线
   （实测 `inter=256` + 256 箱时，1.406° 的真周期被混叠成约 7 个周期/360°）。
   修法不是"改断言"，而是**主动检测并改写标题**为"采样不足：A/B 波形不可信"。
   ⇒ 这条的通用教训：**在数据里标注"我不确定"比强行画出来更专业。**

4. **"全绿但从未跨边界"的盲区（v70）**：`rtl/pole_counter.v` 把 0..65535 的无符号相位按补码
   符号扩展再相减，跨 32768 时 `step=-65403`，`cycle_cnt` 恒 0。33/33 回归全绿，因为没有一条
   激励跨过半量程；最终靠真机整圈 + `tb_acc`（三个样例）+ `tb_acc2`（3000 个 +133，跨越 6 次）
   才抓住。⇒ 盲区不只来自"断言选错观测量"，也来自**激励没走到那个区域**。

**可直接借用的动作清单**：
① 回归汇总里把"RTL 缺陷数"与"测试台缺陷数"**分成两栏**；
② 每个断言旁边写一句"它能抓住哪一类错、抓不住哪一类"；
③ 任何用作断言条件的信号，必须有取值集合统计（非平凡）作为前提；
④ 每类关键错误至少配一个**负对照**。

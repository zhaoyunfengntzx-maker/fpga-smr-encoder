## 0. 一句话诊断

这套上位机已经过了"能用"这一关：协议坑全踩过（0.38% 校验错不重传、写寄存器必须 `[写,读,读,读]` 并同时认 AA55/0x5A、频率必须用「整数电周期 + 小数残差」合成）、277 项回归、19 类自查问题修完、还有离线火焰门禁。

它现在卡住的**不是稳定性，而是三个台阶**：

| 台阶 | 症状 | 本质 |
| --- | --- | --- |
| ① **看得见，量不出** | 有波形、李萨如、ABZ 六状态、转速小数位，但界面上没有一个数字能回答"这台转台现在是多少角秒" | 缺**测量**：游标、统计量、参考线、误差报告 |
| ② **板上跑着，界面上没有** | FPGA 已有锁定状态机、掉锁计数、偏置慢跟踪、延迟前馈、4096 点误差表；上位机只碰了 14 个寄存器 | 缺**可观测性**：把已有硬件能力变成可见/可调 |
| ③ **现场问题带不回来** | CSV 40 MB/min、无元数据、无回放；日志是自由文本 | 缺**可交付性**：数据、报告、日志离不开那台机器 |

所以"怎么让它更好"不是加功能，而是把这三个台阶踩上去：**能证明精度 → 能自己发现异常 → 能把证据带回来**。

### 1.1 最有价值的一条：**板上有 12 个地址段，界面一个都没看见**

| 地址段 | 内容 | 界面现状 |
| --- | --- | --- |
| `0x0120-0x0129` | 延迟前馈 TAU（单位=抽样点×256）、FF 使能、每抽样点位置增量、当前修正量 | **无** |
| `0x0130-0x0135` | 锁定状态机（INIT/TRACK/LOST）、sticky（曾锁定/曾掉锁 W1C）、累计掉锁次数、当前连续坏样本数 | **无** |
| `0x0138-0x013C` | 偏置慢跟踪：sin/cos 偏置、`valid`/`big` 标志 | **无** |
| `0x0141-0x0147` | 全周补偿表 4096×16、使能位、回读探针 | **只有 CLI**（`host/lut_tool.py`） |
| `0x0103/0x0104/0x0106/0x0108/0x010A-0x010C` | AB/UVW 迟滞、AB 限频、Z 脉宽、Z/UVW 相位 | **无** |

这些不是"锦上添花"：**PLL 掉锁、前馈修正量打满、偏置跟踪 `big`** 恰恰是转台现场最容易出、也最难解释的三类问题（转速波动大、低速爬行、温漂）。现在它们只能靠人肉读寄存器。

## 3. 三个重点方案（要说清"凭什么能做成"）

### 3.1 方案 A1/A2：把"看着像"变成"量得准"

**为什么现在能做**：遥测帧 v2 每帧已经带 `s_n[15:0]`、`c_n[15:0]`、`angle[15:0]`（`tools/uart_scope.py:11-13`）。**零 RTL 改动、零带宽增加**，10 kHz × 1 s = 1 万点，numpy 一次最小二乘 <5 ms。

**做法（四参数回归，推荐）**：以 FPGA 自己算的 `angle` 为自变量，拟合

```
s_n ≈ a1·sinθ + a2·cosθ + o_s
c_n ≈ b1·sinθ + b2·cosθ + o_c
```

由此一次得到四个前端指标：

| 指标 | 公式 | 物理含义 |
| --- | --- | --- |
| sin 幅值 / cos 幅值 | `R_s = hypot(a1,a2)`、`R_c = hypot(b1,b2)` | 两路增益是否均衡 |
| **正交误差 ε** | `ε = atan2(-b1,b2) - atan2(a2,a1)` | 两路相位差偏离 90°，直接对应角误差 `≈ ε·sin(2θ)/2` |
| **偏置** | `o_s`、`o_c` | 与 `0x0138-0x013B` 慢跟踪的偏置对照 |
| **噪声** | 残差 RMS | 前端信噪比 / 接触电阻劣化 |

**交叉校验**：再用李萨如点云做一次**最小二乘椭圆拟合**（不依赖 `angle`，纯几何）。两条路方法的「幅值比 / 正交误差」应在千分位内一致；不一致说明 `angle` 本身有问题（CORDIC 或粗精融合），这本身就是一条诊断结论。

**必须写进文档的边界**（否则会被误用）：
- 这是**前端一致性诊断**，不是绝对角精度。回归以 FPGA 自己的 `angle` 为基准，闭环自洽，看不到 CORDIC/融合算法本身的误差。
- **点云覆盖判据**：把 `angle` 直方图分 128 箱，每箱 ≥3 点才允许出数；否则提示"转速太稳/输入频率≈帧率整数倍，点云聚簇，无法拟合"。
- 输入 50 kHz 时 10 kHz 遥测每电周期仅 0.2 点，靠频率的自然波动散开相位；若用户把转速锁得极稳，采样点会退化到固定几个相位。

**游标测量（A2）** 与 A1 正交：A2 解决"看波形取数"，A1 解决"整体健康度"。两者共用同一套统计内核（`filters.py` 扩展为 `measure.py`）：Vpp、RMS、均值、过零率、相位差、THD。

### 3.2 方案 B1：前端自校正闭环（**不需要外部基准**）

A1 给出 `R_s/R_c/ε/o_s/o_c` 后，理论上可以直接算出补偿量并写回。**但先要确认一件事：RTL 有没有可写的增益/正交校正寄存器。**

- 已知可写：偏置是**慢跟踪自动**的（`0x0138-0x013C` 是只读跟踪结果，`BIAS_ST.bit1=big` 表示超限）。
- 未知：增益均衡与正交校正当前是否**只有固定常数**（需求文档说 FPGA 做了"幅值均衡和正交误差校正"，但 `regs.py` 里没有对应的可写寄存器）。

⇒ **B1 的第一步是半天的人机验证**：写一个只读探针，把 A1 拟合出的 ε 与 `0x0138` 偏置对比，同时试探是否存在隐藏的校正寄存器。结论分两支：
- 有可写寄存器 → B1 直接做成"拟合→写→复测"三步向导，一天内能演示收敛。
- 没有 → B1 降级为**只诊断不纠正**，把"新增校正寄存器"作为一条 RTL 需求提给板端（成本 ≈ 0.5 w，收益是让 8 Vpp 前端的残余误差可以被软件吃掉）。

这一步决定了 B1 是"5 天"还是"5 天 + 板端改动"。**建议先做这半天验证再排期。**

### 3.3 方案 B2：全周误差表向导（M8）

现状：`regs.py` 已有全部底层能力（`LUT_N=4096`、`0.0879°/点`、`lut_entry_writes()` 写序列、`0x0145` 使能/回读探针），`lut_tool.py` 已有 `--check/--dump/--upload/--zeros/--enable/--verify` 六种模式。**缺的是"界面里的闭环"和"基准从哪来"。**

**推算的自洽性检查**（按 `regs.py:162` 常数）：修正量 1 LSB = `0.00966 arcsec`，±32767 LSB ⇒ **±316.6 arcsec ≈ ±0.0880°**，正好等于一个表间距 `0.0879°`。也就是说表的设计是"每点最多修正一个点距"，合理。

**核心难点不是上传，是基准**。必须让用户在三种模式里选，否则做出来是伪需求：

| 模式 | 基准来源 | 能得到什么 | 现实性 |
| --- | --- | --- | --- |
| L1 重复性自检 | 无（正反转多次定位） | 回差、重复性、短期漂移 | ★★★★★ 无需外部设备，**建议先做** |
| L2 外部基准导入 | 激光干涉仪 / 自准直仪 / 多面棱体 / 光栅尺 | 绝对角度误差曲线 → 真正的 LUT | ★★★☆☆ 依赖现场设备 |
| L3 人工打点 | 操作员逐点输入基准读数 | 同上，但慢且易错 | ★★☆☆☆ 兜底 |

**上传耗时**：4096 点 × 2 次写（地址 + 数据）= 8192 次寄存器事务。按 `write_reg` 每次 `[写,读,读,读]` 在 2 Mbaud 上的实测节奏估 ≈1.2 ms/次 ⇒ **10-30 s**。所以向导必须有进度条、可取消、断点续传、写完 `--verify` 抽样回读。
**一条优化候选**：若 `0x0143` 写入能自增地址（RTL 待确认），写次数可减半 ⇒ 5-15 s。这条要先问板端，不要假设。

## 4. 三条主线：什么才算"变得更好"

| 主线 | 从 | 到 | 怎么验 |
| --- | --- | --- | --- |
| **可测量** | 肉眼看波形猜精度 | 45 s 内屏幕上出现"正交误差 ε=0.12°、幅值比 1.003、峰峰误差 42″" | 现场对着已知误差的转台，读数与外部仪器差 <20% |
| **可自愈** | 静默 15 s 重连 3 次就放弃；crc 率只计数不报警 | 状态机带退避无限重连 + 异常自动归因（线松/干扰/板复位）+ 建议动作 | 拔插 USB 10 次、热插拔 COM 换号，全程无需点击即可恢复 |
| **可交付** | CSV 40 MB/min，出事带回一台机器 | 5 MB/min + 元数据 + 双击回放 + 一键报告 | 拿一份现场 CSV，在另一台无板机器上完整复现现象 |

## 5. 一周最小切片（如果只给一周）

只做四件，全部低风险，都能独立演示：

1. **A3 编码器状态卡**（1 d）— 立刻让人看见掉锁次数、偏置 `big`、前馈修正量。这是"现场说不清的问题"最直接的止血。
2. **A2 游标测量**（2 d）— 需求里欠得最久的一笔债。
3. **A4 链路健康趋势 + 阈值告警**（1 d）— 把"0.38% 是固有的"变成"超过 1% 就是线有问题"。
4. **A7 + A5**（1 d）— 可见性门控（省 CPU）+ 诊断上屏（省电话）。

验收：`tools/check_offline.ps1` 全绿、277 项不回退、新增 30+ 项回归；用 `tools/gui_eth_smoke.py` 或真机跑 30 min 无异常。

## 6. 不建议做的（省下来的时间拿去做上面）

| 想法 | 为什么不做 / 要缓 |
| --- | --- |
| 给遥测帧**加字段** | 90% 带宽，余量 18 kB/s。加一个字节 = +5.6% 占用，等于把丢帧率翻倍。要加就得先上 C1 以太网 |
| 同时连**两块板** | 串口单主人 + 单链路设计，`SerialWorker` 是一对一。多板是架构重构，不是功能 |
| inter=256 时也画出 ABZ 方波 | 物理约束：`bins ≥ 8×inter`，1024 箱下 inter≤128。这是采样定理，不是 bug |
| 时域波形"不混叠" | 50 kHz 输入 vs 10 kHz 遥测，混叠不可消除。**李萨如才是正确视角**，已在 README 记录 |
| 用 matplotlib 继续堆面板 | 每次新增图都是一次全画布重绘。要么 blit，要么换后端，先别加 |
| 一次性把 2523 行 `main_window.py` 重写 | 现在没有 CI 兜底，重写等于赌。先 C5（pytest）再 C4（拆分） |

## 7. 需要你拍板的 5 个问题

1. **交付对象是谁**？自用 / 课题验收 / 外部客户。这决定"精度报告"和"首次使用向导"的优先级（外部客户 → 两者都升到 P0）。
2. **现场有没有外部基准**（激光干涉仪/自准直仪/光栅尺）？决定 M8 是走 L2 还是先做 L1。
3. **能不能动 RTL**？如果 C1（以太网遥测）和 B1（新增校正寄存器）都要板端配合，需要知道 RTL 的冻结窗口。
4. **记录数据最终去哪**？只留证据 / 还要做后处理分析（Python/MATLAB）。决定二进制格式要不要开放 schema。
5. **目标机器配置**？工控机 CPU 弱的话，C2（绘图后端）要提到 P1。

- 帧长 18 B、帧头 `AA 55`、`off9=0xA2` 为 v2 标记、校验 = `0xAA ^ 0x55 ^ payload` 逐字节异或（`tools/uart_scope.py:6-25`）。
- `pos_full[31:0] = 多周期计数<<16 | 角度`；`io_flags` bit0 `lag_warn`、bit1 `lag_fatal`、bit6 `cor_sat`、bit7 `amp_low|amp_high`。
- 机械角分辨率（`pairs=4`、16 bit 电角度）≈ `360/(4×65536)` = **4.94″/LSB**；全周表 1 LSB = **0.00966″**。
- 全周表 4096 点 = `0.0879°/点`，修正范围 ±316.6″ = 恰好一个点距。

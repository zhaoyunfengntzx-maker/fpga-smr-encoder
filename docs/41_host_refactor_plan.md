## 0. 三个确认把方案简化了

上一版方案里有一堆"如果…那么…"的分支，现在可以钉死：

| 原不确定项 | 现状 | 对方案的影响 |
| --- | --- | --- |
| 直连还是过交换机 | **直连** | 不做 DHCP/网段冲突处理；板子固定 `192.168.1.10`、PC 固定 `192.168.1.100/24`；掉线判定可以用最粗暴的"3 s 无包" |
| 目标机有没有千兆口 | **有千兆** | 连续流（12.5 MSPS × 4 B = 50 MB/s）可以完全放开，不用降抽取比 |
| 能不能大改上位机 | **可以** | 不必迁就现有 `SerialWorker` 的单类结构；可以拆模块、换绘图路径、重建主窗口的数据流 |

**唯一还被卡住的**是板端：遥测帧走 UDP、100 kHz 遥测率需要 RTL（2-3 周）。所以本方案**分成两条平行线**：

* **线 A（现在就能做，纯上位机）**：把软件侧的天花板拆掉 —— 接收/绘图解耦、真波形、频谱、测量、状态、记录、结构。
* **线 B（等 RTL）**：遥测走 UDP、100 kHz、UDP 命令通道。

线 A 不依赖线 B，而且**必须先做**：现在软件连 12.5 MSPS 都接不住（`main_window.py:1904-1906` 注释：画 4096 点几十毫秒，实测丢 39% 包）。线 B 上线前线 A 不做完，带宽提上去只会放大老问题。

## 1. 目标形态

```
                    ┌──────────── 板端 ────────────┐
   串口 2 Mbaud ────┤ 配置/寄存器（4B→6B 事务）    │  ← 不动，可靠小事务就该走这里
                    │                              │
   网线 1 Gbps ─────┤ 抓包（28672 点）+ 连续流     │  ← 已有
                    │ 遥测帧（待 RTL）             │  ← 线 B
                    └──────────────────────────────┘
                              │
                    ┌─────────┴──────────┐
                    │  Transport 层      │  SerialTransport / UdpTransport
                    └─────────┬──────────┘
                              │  bytes
                    ┌─────────┴──────────┐
                    │  TelemetryParser   │  纯函数：帧同步/校验/字段（可回放、可 golden 测）
                    └─────────┬──────────┘
                              │  records
              ┌───────────────┼────────────────┐
              │               │                │
        ┌─────┴─────┐  ┌──────┴──────┐  ┌──────┴──────┐
        │ RingStore │  │ Recorder    │  │ analysis.py │ ← 已落地
        │ (内存环)  │  │ (二进制+CSV)│  │ 拟合/频谱/覆盖│
        └─────┬─────┘  └─────────────┘  └──────┬──────┘
              │  snapshot(带包络/降采样)         │
        ┌─────┴──────────────────────────────────┴─────┐
        │  View 层：波形 / 李萨如 / 频谱 / 状态卡       │ ← 只在可见时画
        └──────────────────────────────────────────────┘
```

三条铁律（决定"大改"不炸）：

1. **收包线程只做"存 + 算"，绝不画图**。绘制请求走快照，丢掉也允许（丢的是帧，不是数据）。
2. **每个面板都有 `visible` 门**。现在七个面板每 100 ms 无条件全喂（`main_window.py:2535-2554`），一半 CPU 花在看不见的地方。
3. **纯逻辑必须能在没有板子、没有 Qt 的机器上自检**。这样改坏了当场就知道，而不是等到现场。

## 2. 第一批（已落地）：`host/analysis.py`

这是线 A 的地基：所有"精度/频谱/覆盖"的数字都从这里出，而且不依赖 Qt、不依赖串口、不写盘。

| 函数 | 作用 | 用在哪个界面 |
| --- | --- | --- |
| `fit_quadrature(s, c, theta_deg=None)` | 估 `R_s`/`R_c`/正交误差 `ε`/两路偏置/残差/SNR | 李萨如卡、诊断卡、标定向导 |
| `fit_ellipse(s, c)` | 二阶矩椭圆：轴比、长轴倾角、中心 | 交叉校验（两套算法互为验证） |
| `fit_circle(s, c)` | 代数圆拟合（Kåsa），给迭代初值 | 内部 |
| `spectrum(x, fs)` | 单边谱 + 谐波表 + THD（谐波幅度用插值频率上的直接 DFT，无扇贝损失） | 波形页、真波形页 |
| `coverage(theta, bins, min_count)` | 全周取点密度（空箱、最大连续缺口角宽） | 标定"能不能开始"的前置判据 |
| `basic_stats(x)` / `wrap_error_deg(e)` | Vpp/RMS/波峰因数；角度误差折 ±180° | 状态栏、报告 |
| `estimate_rate(f, pairs)` | 电频率 → 机械 rpm | 与现有转速互校 |

**实测（本机 Python 3.13 / numpy 2.3.5，26 万点）**：

| 调用 | 耗时 | 精度 |
| --- | --- | --- |
| `fit_quadrature`（含抽稀到 2 万点、26 轮迭代） | **55 ms** | Rs=999.99、Rc=1030.03、ε=0.5008°（真值 1000/1030/0.5°） |
| `fit_ellipse` | 17 ms | 轴比 1.0313（真值 1.03） |
| `spectrum`（12.5 MSPS，取末 65536 点） | 63 ms | 基波 1907.4 Hz（真值 1907.3 Hz） |

**自检 46 项全 PASS**，已加进 `tools/check_offline.ps1` 的 `$Modules`（现 8 个模块）。

两个踩坑记录（写进模块 docstring 了，避免以后有人"优化"回去）：

* **Heydemann 迭代是线性收敛的，每轮减半**。6 轮时 ε 还差 1.6%、Rc 差 0.24 LSB —— 所以默认 48 轮、阈值 1e-9，而不是"4 轮够了"。
* **谐波幅度不能用"附近最几格取最大"**。Hann 窗下非整周期有扇贝损失（半格 −1.42 dB），且各次谐波偏移不同 ⇒ 10% 的谐波被读成 **10.8%**，THD 跟着虚高。改成在插值后的真实频率上做直接 DFT 求和后，读到 10.00%。

## 3. 第二批：E0 接收/绘图解耦（线 A 的关键，4-5 天）

**问题**：`stream_capture.py:85` 有 `history = 1 << 18`（26 万点）环形缓冲，但 `main_window.py:1920` 只 `snapshot(1024)`；注释写明原因是"画 4096 点几十毫秒，收包线程拿不到 GIL → 丢 39% 包"。

**改法**（不动 RTL、不动协议）：

1. **包络在收包侧算好**：`snapshot(cols=2000)` 直接返回 `(x, ymin, ymax)`（`filters.envelope` 已有，复用），UI 只搬 2000 组数据。
2. **快照可丢**：定时器到点时若上一次绘制没结束，这次直接跳过（丢帧保数据）。
3. **可见性门控**：`panel.isVisible()` 为假时不计算、不绘制；七个面板全部接这个门。
4. **blit**：matplotlib 只重画线，不重画坐标轴/网格（`set_data` + `draw_artist` + `blit`）。
5. **降采样策略分级**：窗口 > 20 ms 用 min/max 包络（保峰）；窗口 ≤ 2 ms 用逐点（保真）；频谱用原始样点。

**验收**：连续流 12.5 MSPS 下，UI 保持 ≥20 FPS 且**丢包率 < 0.1%**（对比现在实测 39%）。这一条能量出来，E0 就算成了。

## 4. 第三批：真波形页 + 频谱页（4 天）

* **真波形**：直接吃连续流的 12.5 MSPS 样点，按"一屏整电周期"对齐（触发沿用 `panel_wave` 现有的 `s_n 过零` 逻辑，但改成在样点域找过零）。50 kHz 输入时一屏正好 1 个 20 µs 周期 ⇒ 终于能看清正弦有没有畸变。
* **频谱**：`analysis.spectrum` 出图（线性/对数纵轴），叠加谐波表和 THD 读数。这是"精度问题从猜变成定位"的那一步。
* **阶次分析**（可选）：转速波动时按角度重采样再 FFT，看齿槽/偏心 —— 数据够就行，先不做。

## 10. 一句话

"大改"不是重写界面，而是**把数据流从"收包线程被绘图拖死"改成"收包线程只存不算、界面按需取快照"**；`analysis.py` 已经把这套改造需要的数学先落地并测过了，接下来是把数据送到它手里。

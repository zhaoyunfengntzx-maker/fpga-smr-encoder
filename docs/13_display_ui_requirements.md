## 0. 一句话目标

**不做第二个上位机，做一块"能脱离电脑独立演示"的本机人机界面**：把编码器的倍频设置、转速/位置、

### 2.1 ★ 目标像素时钟定为 **50 MHz**（不用 MMCM）——已推翻调研报告的 51.2 MHz

调研报告推导的 51.2 MHz / 59 Hz 是**反推值，不是厂商值**。实测结论是 **50 MHz / 58.60 Hz**，且理由充分：

1. **50 MHz 就是板载晶振**，`sys_clk` 直接当 PCLK ⇒ **零 MMCM、零 IP、零跨时钟域**。
   这一条保住了本工程"全系统单时钟域"的核心架构叙事（`docs/01_technical_solution.md:93`），
   而引入 51.2 MHz 会同时打破它，并给 20.8 天的工期加一次 CDC 验证。
2. **"2 的幂"不需要像素时钟是 2 的幂**。调研报告想要的"1 样本/像素"用**相位累加器**即可做到：
   50 MSa/s ÷ 逐行 1024 像素 = **每像素恰好 48.83 个样点**，用 1024 累加步进即可无抖动重采样；
   而所有 FFT/分箱窗口都可以**在 50 MHz 域内自由选点数**（FFT 点数是设计参数，与 PCLK 无关）。
3. **51.2 MHz 唯一能省下的是"重采样相位累加器"（约 34 bit）**，代价却是 1 个 CMT + 一次 CDC +
   新的 XDC 时钟约束 + 重新收敛。**收益 34 bit 寄存器，代价一次时序/C DC 风险 —— 不划算。**

> 结论：**PCLK = sys_clk = 50 MHz，单时钟域，零 MMCM。** 上一版草案里"51.2 MHz 更能解决关键约束"
> 的判断**作废**（该结论建立在一个错误前提上：误以为"1 样本/像素"必须靠时钟频率相等）。

## 3. 显示引擎架构决策（三条硬结论，来自可行性调研 + 本地资源核算）

### 3.1 硬约束：**全屏帧缓冲在本器件上物理不可能**

1024×600 全屏缓冲：8bpp = 614,400 B = **133 个 RAMB36（器件的 2.67 倍）**；RGB565 = 267 个；
即使 1bpp 也要 614,400 bit = 16.7 个 tile。⇒ **不做全屏帧缓冲，这不是取舍而是硬约束。**

### 3.2 采用**混合（Hybrid）渲染**架构

```
程序化背景/网格/边框/仪表盘      ← 纯组合逻辑谓词，0 BRAM
+ Copper 逐扫描线寄存器表        ← 635×32 bit = 0.55 tile，每行读 1 次
+ 16×16 位图文本层（中文 16×16；数值大字 30×48、小字 11×14，见 §5）
+ 逐列 min/max 包络（时域波形）      ← 1,024 列 × 24 bit = 0.67 tile/通道
+ 逐列 6-bit 状态（数字时序）        ← 1,024 列 × 6 bit = 0.17 tile
+ ~~仅 X-Y 李萨如图用 1bpp 位平面~~  ← **v58 删除 P3 后不再需要**（原 512×512 = 7.1 tile）
+ 单像素/拍固定延迟流水线合成   ← ~2,150 LUT / ~1,000 FF / 0–8 DSP
```

**为什么时域波形不需要"上一个采样"**（这是本方案最关键的实现结论）：
逐列存 ymin/ymax，渲染时与左邻列合并 `lo(x)=min(ymin[x],ymin[x-1])`、`hi(x)=max(ymax[x],ymax[x-1])`，
像素级判据只有 `lo(x) <= y <= hi(x)` —— **2 个比较器、零历史、1 拍 1 像素、完全流水**。
代价是缩得很远时丢失列内细节（用 min/max 而非"首/末采样"语义可保住毛刺）——**可接受**。

### 3.3 BRAM 预算（v58 删 P3 后：全部 50 个 RAMB36 中的 17–30 个，留 ≥20 个余量）

| 用途 | 估算 |
|---|---|
| 字符单元表（128×37 单元 × 8 bit） | 1.03 tile |
| 字库（v58：val 30×48 + lab 11×14 + 中文 16×16） | **4 tile**（146,944 bit ≈ 3.99 RAMB36） |
| **中文 16×16 字库（目标 300–500 字）** | **3.5–6 tile**（32 B/字） |
| Copper 逐扫描线表 | 0.55 tile |
| 时域包络 ×N 通道 | 0.67 tile/通道 |
| 数字时序状态（6 通道） | 0.17 tile |
| ~~李萨如 512×512×1bpp~~ | ~~7.1 tile~~（**v58 删除 P3，不计入**） |
| 原始 ADC 采样环缓冲（可选，长捕获） | 2–4 tile |
| 读预取/双缓冲余量 | 3–5 tile |
| **合计** | **17（精简）～30（丰富）** |

### 3.4 明确**不做**的技术路线（附理由）

| 不做 | 理由 |
|---|---|
| **DDR3 + MIG 做帧缓冲** | MIG 引入 43 引脚 + 新时钟域 + 校准风险，而 UI 根本不需要它（BRAM 24–37/50 够用）。且它会占掉本机 5 个 CMT 里的 3–4 个。 |
| QSPI Flash 存位图 | 只读 + 取引脚要动 `STARTUPE2`（有破坏配置的风险）；而全部素材只要 100–200 KB = 2–4 tile。 |
| 8bpp/16bpp 调色板帧缓冲 | 同样面积 1bpp 位平面省 8 倍；用"位平面 + 逐扫描线调色寄存器"（Amiga/SAGA 模型）。 |
| 逐像素 1 次 BRAM 读 | 单口 36.86 M/s vs 50 M/s ⇒ 端口占用 72%，是陷阱。正确做法：**32 bit 字预取，每 32 像素读 1 次 = 2.3% 端口占用**。 |
| 覆盖式模态盖住波形 | 反模式（§8 第 6 条）。编辑面板放**下半屏**，上半屏波形继续刷新。 |

### 5.1 三条排版铁律

1. **等宽（tabular）数字 + 固定小数位** —— 否则数值刷新时整行左右抖动（仪器 UI 最致命的业余感）。
2. **单位用 11×14 小字、次级色，与数值基线对齐**，不缩放混排。
3. **每个页面只保留 2 级西文（30×48 / 11×14）+ 1 级中文（16×16）** —— 手写渲染器的成本控制，也是视觉秩序。

### 5.2 不用颜色也能区分状态（四重冗余，1-bit 渲染尤其重要）

`● 正常` / `▲ 警示` / `✖ 故障` = **字形 + 中文文字 + 反转视频（白字反色块）+ 可关闭的 2 Hz 闪烁**。
**颜色绝不作为唯一的状态编码**（色弱评委 + 强光下的真实问题）。

## 6. 交互规则（触摸仪器专用）

### 6.1 触控目标

| 类型 | 尺寸 |
|---|---|
| 最小（仅非关键项） | 40 px |
| **推荐（标准）** | **48 px** |
| 主操作 | 56–64 px |
| 危险动作 | 72–96 px |
| 相邻间距 | ≥8 px（理想 12 px） |

### 6.2 ★ 两阶段提交（本需求最重要的一条交互契约）

任何写硬件寄存器的操作，都必须走：

```
改值 → [待应用 黄] → 点「应用」 → [应用中 …] → 回读寄存器确认 →  [已应用 绿]
                                                            └→ 不一致 → 自动回滚（红 + 错误码）
```

**屏幕绝不允许显示"用户想要的理想值"**，只能显示**寄存器回读确认过的实际值**。
理由：`rtl/SPEC_interface_contract.md §1.12` 已明确"读命令要连发两帧、写命令的应答内容是上一帧的没有语义"，
不设回读就无法区分"写成功"与"链路假死"。

### 6.3 倍频 `inter` (2…256) 用什么控件

**连续滑条在 1024 px 上做 256 档 = 每档 <4 px，物理上不可用。** 必须用：
**预设档位步进器（2,4,8,16,32,64,128,256）+ 长按加速 + 离散滑条（档位吸附）+ 数字键盘兜底**。
`div` (1…8) 用 8 档步进。编辑面板同时显示 `等效倍率 = inter/div` 与预测的 AB 边沿率，**改前就能看到后果**。

### 6.4 什么必须先确认（防误触）

| 必须二次确认 | 可以直接生效 |
|---|---|
| 清除锁存故障（`0x0405` 写 1 清） | 页面导航 |
| 恢复出厂默认 | 查看类操作 |
| 任何会改变 ABZ/UVW 输出的极性/方向位（`0x0109`） | — |

> v58：页内 Tab 已随 P3 删除，不再有「Tab 切换」这一行。

### 6.5 长按 / 撤销

- **长按**只用于两件事：①步进加速 ②"防误触但不必弹窗"的动作（配环形成进度反馈）。
  **长按绝不作为唯一入口**（用户不知道能长按 = 功能不存在）。
- **撤销**：编辑面板的「取消」= 不写寄存器（天然可撤销）。已写入的值不提供撤销，但**提供"上一次值"记忆**，
  在面板上以"↩ 回到 ×8"的形式给出。

## 7. 数据来源与解算口径（**不新增遥测帧**，C2 直接读内部信号）

屏 UI 与编码器同片，**不需要串口**。所有数据直接从 `enc_top` 的内部信号与寄存器组读取。

| 屏上要显示的量 | 来源 | 口径与风险 |
|---|---|---|
| 倍频 / 分频 | 寄存器 `0x0101/0x0102` | `inter = {0x0102[1:0],0x0101[7:0]}`（0 视为 256）、`div = 0x0102[4:2]+1`。**改它们要同时写两个地址** |
| 输入频率 `f_in` | ①遥测帧的 `pos_full` ②**（推荐）RTL 新增频率计数器** | ★ **只拿 16 位 `angle` 求导在 >5 kHz 就混叠**（`host/encoder.py:10-12` 明确记录）。屏端**必须**用 `pos_full` 的 64 周期解回绕，或直接在 RTL 里数周期。 |
| 机械转速 RPM | `RPM = 60 × f_in / 极对数`（`0x0100`，默认 4） | 标「估算值」。`POLE_BITS=6` 是虚拟 Z 口径，想按那套看就填 64 ⇒ `60×f_in/64` |
| 方向 | `pos_full` 增量符号，或 `0x0500` 的 dir 位 | 需要"中间断流后重新起算"保护（照抄 `host/encoder.py:124-128` 的做法） |
| 累计转数 | 累计电周期数 ÷ 极对数 | 从"本次上电"起算，**不是掉电保存的绝对值**，屏上要写明 |
| `s_n` / `c_n` 波形 | 遥测帧 off4..7 的 `s_n`/`c_n`（16 bit） | 帧率 10 kHz ⇒ 时间分辨率 100 µs，是**软件极限**；该口径保留在本表（v58 已删 P2 底部「等效采样 100US」注记，屏上不再单列） |
| 原始 `sin/cos` 高速波形（可选 ②） | 直连 `ad9238_capture` 的输出或 `sc_correct` 的输入 | 需新增采集环缓冲（2–4 tile）。**必须标"原始 50 MSa/s，非遥测口径"**，否则与上位机数字对不上 |
| ABZ / UVW 六路电平 | 遥测帧 off9..11 的 `io_state` / `io_flags` | 时间轴画 A/B 会**混叠**，必须按**电角度 64/128 箱**等效采样，并在图上注明 |
| Z 重复率 / 脉宽、`dir`/`limiter`/`z_window` | 遥测帧 `stat`、`io_flags` | — |
| 幅值 / OTR | `0x0530` `STAT_AMP_SQ`、`0x053A` `STAT_FLAGS` bit3 | `amp_sq` 是 (0.60)²…(1.20)² 门限口径（`0x0520/0x0524`） |
| 告警与锁存 | `0x0404 STAT_VAL`（读一次同时得 `0x0405` 高字节）、`0x053A/0x053B` | ★ **`0x0405` 是 W1C（写 1 清），与 专用细分 ASIC"写 0 清位"相反**；写 bit0 还必须同拍发 `clr_otr`，否则 `led[0]`/`irq_n` 不恢复（2026-10-10 上板实测踩过） |
| 标定状态与控制 | `0x0502 CALIB_CTRL`（start 写两次会触发两次标定）、`0x053A` bit4 caldone / bit5 calbusy | 写 start 位**只发一帧** |

### 7.1 UART 的处置（C2 推论）

- **屏的命令绝不走 UART**（余量只有 9.3%，一次寄存器读要 4 B 命令 + 6 B 应答，会把遥测挤爆）。
- **UART 遥测帧保持不变**（`AA 55` 头、18 B、10 kHz）⇒ **电脑上位机与屏可以同时工作**，
  两端看到同一份数据，互不干扰。
- ⚠ **已确认的后果**：屏改了寄存器，**电脑上位机不会自动刷新**（遥测帧里不带配置回读字段）。
  处理办法：屏改完可选**主动通过遥测帧的保留位广播一次"配置已变"**（`0x0101` 有保留位）；
  若不做，就在文档里写明"两侧配置视图可能不同步，以回读为准"。**→ 待确认项 Q6。**

### 7.2 渲染侧的时序约束（必须遵守，否则重蹈 −2.181 ns）

| 约束 | 数值/做法 |
|---|---|
| 像素流水线 | **固定延迟、全寄存器化，1 拍 1 像素，无任何停顿** |
| 单像素组合逻辑深度 | ≤4–8 级 LUT6（约 10–25 LUT 等效） |
| 流水线寄存器宽度 | 40–56 bit/级 ⇒ 全 UI 约 300–450 FF |
| **禁用** | `char_code * 16 + y[3:0]` **绝不能组合出现在像素路径上**（必须预算/流水） |
| **禁用** | 任意折线/多边形在像素路径上实时栅格化 ⇒ 一律**预栅格化进位平面**（消隐期或第二端口） |
| BCD/ASCII 转换 | 每帧在消隐期批处理一次（239,040 拍预算，double-dabble ~32 拍） |
| BRAM 访问 | 每平面 32 bit 字预取、**每 32 像素读 1 次**（2.3% 端口占用） |
| 帧间撕裂 | 位平面**双缓冲，VBlank 交换** |

## 8. 反模式清单（8 条，评审前逐条自查）

1. 把桌面 UI 按比例缩小到 1024×600。
2. **比例字体跑数字** ⇒ 刷新时整行抖动。
3. **颜色作为唯一状态编码**。
4. 装饰性渐变、圆角、阴影（手写渲染器的成本黑洞，且不增加信息量）。
5. 危险动作（清故障/恢复默认）混进常规列表。
6. **模态对话框盖住正在刷新的波形**。
7. 缺少"生效收敛态"——用户不知道值到底写进去没有。
8. 缺少空态/错误态（没信号时屏幕一片空白 / 一片 `0`）。

## 10. 触摸修复方案（S0，半天）

**已确认事实**：`lcd_test2` 仿真曾 PASS（锁定类型 = 1（GT911）、点数 = 2、坐标 = (600,256)），

> **2026-10-15 更新（重要，先读这段）**：多点问题已定位到**两个真实缺陷**，并已在 `lcd_test2` 里修掉：
> 1. **点位解码错位**：GT911 每个点占 **8 字节**（`0x814F + 8k`），旧代码按 **5 字节** 解码，
>    点 1 起全部错位（实机 `T2` 恒为 `(0,1025)`，`1025 = 0x401` 正是错位拼出来的假数）。
>    ⇒ 新渲染器**必须**按 8 字节/点解析，且**假从机模型也要按真片布局**，

> **2026-10-15 第二次上板补充（比上面更要紧的一条）**：多点修复版烧进去后出现

> 每拍把计数清零）⇒ "状态被从机拖住"就是不可恢复的锁死。已修：

> ② `touch_i2c_ctrl.v` 的 `ST_WAIT` 加 50 ms 兜底，超时强制回 `ST_IDLE + STEP_POLL`；
> ③ 遥测 byte4/5/6 的空位改为上报两套状态机的 `state/step/busy`（**§5.1**），
> 卡死时直接读数定位；
> ④ 第 9 个自检台 `lcd_test2/sim/tb_i2c_watchdog.v` 把"卡住 → 恢复 → 下次请求正常"钉死。
> **对 C2 渲染器的要求**：触摸状态机的等待**一律要有超时**，且把"最后一拍状态"暴露到调试通道；
> 不要写"等 `done` 一直等"的代码。细节见 `docs/LCD_test_program_readme.md` §6 第 6/7 条与 §9.7。

⇒ 这不像硬件坏，**最可能是四个初始化/时序细节之一**。排查顺序（按成本从低到高）：

1. **GT911 复位时序与 INT 电平**：GT911 靠 `INT` 在上电/复位期间的电平选择 IIC 地址（0x5D 或 0x14）。
   `lcd_test2` 探测到 `probe_gt=130`（GT911 有应答）说明地址选对了，但**必须确认 `0x8040` 的
   控制寄存器（复位/上报率）与 `0x8047` 之后的配置区是否真的要重写**——GT911 出厂配置通常够用，
   **重写配置区反而可能导致 `0x814E` 不上报**。★ 第一件事：**把配置区写入整个跳过，只读 `0x814E`**。
2. **`0x814E` 的读法**：GT911 是"读到点数后**必须写 0 清**"，且清之后要等下一轮扫描。
   `lcd_test2` 若在同一轮里读完就清，下一次读可能仍是 0。
3. **中断/轮询的抢占**：INT 快通道与 10 ms 轮询若同时读 IIC，可能互相打断。
   ⇒ 加一个"IIC 忙"互锁，并在 IIC 读失败时**不要**认为"点数 0"（区分 NACK/超时/真 0）。
4. **上拉电阻**：J7 排线上 `touch_scl`=T4 / `touch_sda`=U5 是否已有上拉（若靠 FPGA 内部弱上拉，2 Mbaud 下会失败；
   但 IIC 只跑 100–400 kHz，通常够用）。

**S0 的验收**：实机上连续 100 次读 `0x814E`，出现点数 > 0 的次数 ≥ 90；触摸坐标与实际落点误差 ≤ 20 px。
**若半天内修不好**：按 C1 **当场降级** —— 用板载 `key_n`(W9) 做唯一输入，UI 退化为
"4 页循环 + 每页一个可调项"，**不做逐像素命中测试**（这条降级路线要预留，但按 C3 先不实现）。

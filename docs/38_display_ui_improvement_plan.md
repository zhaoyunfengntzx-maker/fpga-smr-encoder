## 1. 问题清单（按严重度）

### P0-1 恢复默认后「逻辑时序」页卡死（新故障，逻辑时序页不再刷新，输入波形页正常）

现象来自你的描述，离线我无法直接复现，但代码里有三条可疑路径，按可能性排序：

| # | 假说 | 依据 | 15 分钟验证 |
| --- | --- | --- | --- |
| A | 恢复默认把 `0x0109 OUTPUT` 写成 0（ABZ/UVW 输出关），A/B 不再翻转 ⇒ 轨迹静止 | `rtl/reg_file.v:330` 默认 `0x00C0`；`disp/ui_restore.v` 的恢复表若漏该项或写错值 | 串口读 `0x0109`，应为 `0x00C0`；屏幕 P6 的 ABZ/UVW 项应显示 ON |
| B | 恢复序列没跑完 ⇒ `ui_state` 停在"进行中"，页面被策略层挡住刷新 | `disp/ui_edit.v` 两阶段提交 + 回读确认 | 串口看 `0x0404/0x0405`；切到别的页再切回 P4 是否恢复 |
| C | 恢复把 `0x0100 UVW_CFG` 写成 0（pairs=0→32）或 `0x0101 INTER` 写成 2 ⇒ A/B 频率突变 32× | `rtl/reg_file.v:313-314` 默认 4/32 | 读 `0x0100`、`0x0101` |

**需要你配合的一次读数**（板子现在就能做）：串口读数会直接定案——
`0x0100 / 0x0101 / 0x0106 / 0x0109 / 0x0514 / 0x0515`，以及"恢复默认前后"各读一次。
我可以把这个做成一条 `_boardtest\ui_restore_probe.py` 命令（1 分钟），或者你先手动读。

### P0-2 转速 / 角度：数值压住单位（照片里 "842.6**M**"、"- 135.3 DEG"）

- 数值层格宽 **32 px/字符**（`disp/disp_engine.v:986` `val_cx = pix_x[9:5]`），
  转速字段 `f_col=3`、`f_wid=8`（`disp/val_format.v:141-160`）⇒ 右端到 **x=352**；
  而 `RPM` 标签在格列 20 = **x=320**（`tools/gen_text_ram.py:141`）⇒ 必然压字。
  你看到的"M"就是被压掉一半的 `RPM`。
- 角度字段 `f_col=18`、`f_wid=7` ⇒ 右端 800 px，`DEG` 在 x=800，正好压线；
  更糟的是符号固定写在第 0 格（`disp/val_format.v:424` `cbuf[0] = CH_PLUS`），
  所以 "-" 与数字之间会空出好几格（照片里减号孤零零在最左）。

### P0-3 输入频率带两位小数（28602.54），要整数

- `disp/val_format.v` 的 `f_frac(0) = 2` ⇒ 两位小数。你要整数，是**一行改动**（`f_frac(0)=0`）。
- 顺带：整数后字段可以窄 2 格，正好腾出单位空间（与 P0-2 一起改）。

### P0-4 P2 输入波形"杂乱乱晃"：窗宽是 2.4 ms，标签却写 100 µs，而且没有触发

- `disp/wave_trace.v:36` `SWEEP_DIV = 12'd128`，944 列 ⇒ **944×128 / 50 MHz = 2.416 ms**；
  标签 `等效采样 100US` 是旧口径（`tools/gen_text_ram.py:514`，注释里还写着"波形来自遥测帧 off4..7"）。
- 28.6 kHz 在 2.4 ms 里是 **69 个电周期** ⇒ 屏上必是 69 根竖条纹（和你照片里数得出来的一致），
  这不是"信号脏"，是**窗口比信号周期大 69 倍**。
- 更关键：**扫描是自由运行的，没有触发**（`wave_trace.v` 里 `frame_st` 一到就归零重扫），
  每帧起始相位随机 ⇒ 条纹横向"乱晃"。示波器为什么稳？因为它等触发沿。

### P0-5 P4 逻辑时序页：A/B 密到糊、U/V/W/Z 几乎是直线、轴标 "2US/PT 428PT" 也是旧口径

- `disp/logic_scope.v:81` 用 `angle[15:9]` 当写箱 ⇒ **128 箱 = 1 个电周期**。
  一个电周期里 A 跳 32 次 ⇒ 每箱摊 0.25 个 A 周期 ⇒ A/B 必然糊成密集竖线（照片如此）。
- U/V/W 在这个窗口里应该是 **6 段**（每段 ~21 箱），Z 是每转 1 个脉冲（833 ms，本窗口完全看不到）。
  照片里 U/V/W 是平的 —— 需要确认是"高电平直线"还是"没画"，这条我列为**待实测确认**，
  不先下结论。
- 轴标 `TRIG Z 2US/PT 428PT`（`tools/gen_text_ram.py:589`）= 856 µs 窗口，与现在的
  "1 个电周期（≈116 µs @8.6 kHz）"完全不是一回事 ⇒ 标签必须跟着真实参数走。

### P1-6 累计转数一直是虚线 + 卡 4 亮"故障"

- 判据在 `disp/disp_engine.v:758-770`：`enc_bad_c = sig_bad`（v74 只剩 `amp_gone`），
  幅值一掉就显示空态 + 故障，判据只看内部信号。
- 但"转了几圈"这件事，v71 修好位置计数之后编码器**自己就算得出来**（内部 `rev_cnt`/`pos_full`），
  判据与显示数据同源。建议改成"用内部多圈位置显示转数"，链路状态只留在告警里。

### P1-7 P7 标定页：曲线没有坐标/图例、GAIN 显示 32768 与 P6 的 1.000 不同口径

- `GAIN-S 32768 / GAIN-C 32768` 是 Q1.15 原始值，P6 显示 1.000 ⇒ 同一物理量两种写法。
- 误差曲线只有一条红线（"后"那条绿线只在 `calib_done` 后出现），且没有 ±0.5° 参考线与纵轴刻度，
  只能看"平不平"，看不出"精度多少"。

### P2-8 倍频编辑面板压在主页面数值上（照片 5：PRESET 32 盖住转速/角度）

- 面板是叠加层，底下的 P1 六卡数值仍照常绘制 ⇒ 两层文字打架。

### 验证链（每阶段都走一遍）

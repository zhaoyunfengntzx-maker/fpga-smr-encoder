## 1 审计口径

判定分三级，严格对齐本仓库「每条结论跟一个数字 + 标签」的写作规则（`deliverables/README.md:73-75`）：

- **可写**：有 `[实测]` 支撑，且措辞不超过证据边界。
- **条件可写**：事实成立，但字面含义超出证据；加限定词后成立。
- **不可写**：无证据，或与 RTL 行为 / 报告自述直接冲突（会被评委现场翻 RTL 打脸）。

「闭环」按控制论三要件拆解（第 2 节逐条比对）：
1. **测量**——系统自己测出误差；
2. **反馈**——误差回到执行机构或参数，且**在运行中持续作用**；
3. **收敛**——多轮之间误差单调下降或有界振动。

**注意**：本仓库存在一个真实的、常开的闭环——**相位跟踪环**（`rtl/lock_sm.v` + `rtl/loop_filter.v` + `rtl/lag_ff.v`，II 型 PI + 前馈，`design_report.md:272-315`）。本轮要判断的是：这个环能不能叫作「**自校准**」？答案见 §2.3(c)。

### 2.2 三要件逐条判定

| 要件 | 六参数标定 | 偏置跟踪 | 全周表 | 总体 |
|---|---|---|---|---|
| ① 自测误差 | ✅ 用 sin²+cos² 与互相关估计偏差 | ✅ 用慢速低通估 bias | ✅ 用外部基准表 | 满足 |
| ② 运行中反馈 | ❌ 一次写死，运行中不再更新 | ⚠️ 有，但**分块阶跃**且默认关 | ❌ 离线写表 | **不满足** |
| ③ 多轮收敛 | ✅ 20 轮 20/20 一致（一致性，非收敛性） | ✅ 慢跟踪收敛，但 <12 rpm 失效 | ✅ 幂等（差全 0） | **部分** |

**关键反证 #1（设计者原话，最硬）**：`design_report.md:1458` 把「**估计器不要在被控回路上闭环**」写成本仓库的**四条流程约束之首**。同页 `:1452` 记录第一版偏置估计正是照控制论做了反馈环（`bias ← EMA(s_cor)`，而 `s_cor = s − ofs − bias`），后果是「稳态只能补一半，且与 PI 环路持续耦合」，全链路 `max_dev` **1763 LSB16**、UVW 扇区 24→22、两次标定结果不再逐位相同，最终**被迫改成块率开环积分并把使能位复位值设为 0**。

> 换句话说：**「闭环」在这个项目里不是没做，而是被实测证伪后主动删掉的**（v66 真缺陷）。此时对外宣称「闭环自校准」，等于把报告里最贵的一条教训反着写。评委翻到 §11.12 一句话就能问倒。

同义表述见 `:926`（§8 #13）：「偏置跟踪**故意不用 EMA**……是 v66 抓出的真缺陷。」

**关键反证 #2（标定没有「环」）**：`design_report.md:710-714` 写明标定是「写 `0x0502=0x0001` 触发、bit0 自清、bit2 done」，**上电不自动标定**，掉电后 `0x0510…0x051A` 复位中性（OFS=0、GAIN=0x8000、PHASE_K=0、SHIFT=0）。「自」校准的「自」如果指「上电自动」，与 RTL 不符。

- 窗口长度：**N=64 个电周期 ≈ 16,384 样本**（`rtl/reg_file.v:354` 复位 64；`:704` `nsamp=16384/16384`）。
- 唯一存在的「重试」（`rtl/calib_ctrl.v:178,564-590`，≤3 次）是**窗口有效性重试**（非整周期就重收），**不比对残差**；每次触发 `retry_cnt` 从 0 重计（`:458`）。
- ⇒ **没有收敛判据、没有残差监测、没有参数自整定。**`win_bad` 只报「窗口畸形」，不报「标定不准」。

**关键反证 #3（没有基准就没有环的输入）**：`design_report.md:904`（R15）——**没有可信到 ±0.5″ 的外部角度基准**，「表是通路，不是已证实的精度」。闭环要成立，必须有一个「误差从哪来」的可信量值；这里没有。

**关键反证 #4（RTL 里那行陈旧注释是陷阱）**：`rtl/enc_top.v:463-465` 仍写着

```verilog
// ★ v9（S4）偏置慢跟踪：bias_track 观测的是**校正后**的 s_cor/c_cor，
//   输出的是"残余偏置"，所以叠加在寄存器偏置上（cfg_ofs + bias）构成闭环：
//   偏置漂移 → 残余非零 → EMA 学到 → 抵消。16 位饱和防溢出。
```

这描述的是**已废弃的 EMA 版**，与同文件 `:511-514`（分块积分）和 `rtl/bias_track.v:10-15` 直接冲突。**它既不支持「闭环自校准」，也不能拿来当挡箭牌**——评委 grep 到「构成闭环」再读三行就会发现是旧设计。建议顺手把这行注释改成「块率积分，非 EMA 反馈环」。同理 `design_report.md:63`「能不能把这些误差**在线标定掉**才是……分水岭」是**动机句**，容易被读成「已实现在线标定」，建议加「（本作品以一次解算 + 可选慢跟踪逼近之）」。

### 2.3 三种可能的「闭环」辩护，只有一种勉强站得住

- **(a) 标定—判据—复核闭环** ⚠️ **弱可用，必须写清「判据在上位机」**
  写 `0x0502` → 硬件 1 个窗口解算 → 参数进数据通路 → 回读 `0x0510…0x051A` → 用 `tools/calib_repeat.py` 判「`OFS_S` 在圆心附近 + `win_bad`=0」→ 不满足就重跑。
  证据：20 轮重复性 **20/20 GOOD**（`retry{0:20}`、`win_bad` 0/20）`[实测]`；参数幂等（OFS_S/OFS_C/GAIN_S/GAIN_C/PHASE_K 差全 0）`[仿真]`（`:703-704`）。
  **必须同时说明三点**：① 闭环的「判定」在**上位机脚本**里，硬件侧只有一次解算；② 该脚本**只判读不回写**；③ 这不影响精度，只保证**一致性/可重复性**。
  只说「闭环」不说这三点，就会被追问「环在哪」而答不上来。

- **(b) 偏置跟踪构成闭环** ❌ **不可用**
  要用它，得把 `0x0122` bit1 默认打开并做连续小步长；而 `:926` 正好论证了为什么不能这么做。自相矛盾。

- **(c) 相位跟踪环构成闭环** ❌ **词不达意**
  `lock_sm` 的 PI 环锁的是输入相位、输出的是角度，属于**位置跟踪**，跟「校准模拟前端」是两件事。硬套会被问「你校准的是什么」。

### 2.4 能写 / 不能写 / 要补什么

**能写（有证据）**
- 六参数**闭式**解算、1 个窗口（N=64 电周期 ≈ 16,384 样本）、约 1 µs、无迭代无搜索（`:149-183`，同类器件的对照列见 `:176-183`）
- 一键标定 20 轮重复性 **20/20** `[实测]`、**幂等**（参数差全 0）`[仿真]`（`:703-704`）
- 校正后复合畸变残余 0.0165°（1273×）`[仿真]`；真机分箱残差 −0.13°…+0.13° `[实测]`（`:191-197`、`:860-882`）
- 标定结果可回读复核、可按需重标（`:183`、`:710-714`）
- 三级残差抑制链：**前馈标定 → 偏置慢跟踪 → 全周查表**（后两级默认关，可现场启用）

**最安全的关键词措辞（推荐）**：**「闭式自校准」**（= 一次解算、免迭代、幂等可复核），或 **「一次解算自校准」**、**「幂等自校准」**。这三个词每一个字都有 `[实测]`/`[仿真]` 支撑，且不与任何设计教训冲突。

**不能写**
- 「上电自动校准 / 零操作自校准」（RTL 是按需触发，掉电复位中性）
- 「闭环反馈持续修正偏置」（分块积分 + 默认关 + `:1458` 明确反对）
- 「无需外部基准即可闭环到 ±1″」（R15：无 ±0.5″ 基准）
- 把 0.0165° 当作真机精度（那是 golden model `[仿真]`，且恰好等于 3 LSB16 量化底噪）
- 把「表能装能读回」当「装表更准」（`:904` 明确否认）

**要补（若坚持「闭环」二字）**
1. 一张**闭环标定流程图**：触发 → 采集窗口 → 解算 → 写寄存器 → 回读复核 → 重跑判据（20/20 判决门）。
2. 一句**边界声明**：判据在**上位机脚本**；偏置跟踪与全周表默认关闭，启用后精度受基准限制。
3. 答辩口径三问三答（见 §2.5）。

### 2.5 答辩预判（评委最可能追问的三句）

| 问题 | 建议回答（照读即可） |
|---|---|
| 「你的闭环，环在哪？」 | 「闭环在**判据**上：写触发位 → 硬件一个窗口解算出六参数 → 参数进数据通路 → 回读寄存器 → 用 `OFS` 是否落在圆心附近 + `win_bad` 是否为 0 判定 → 不满足就重跑，20 轮 20/20。**闭环的判定在上位机脚本，硬件侧是单次解算**；控制意义上的反馈环我们刻意没做——v66 实测过，EMA 式偏置反馈会把环路带崩（`max_dev` 1763 LSB16），所以 `:1458` 把『估计器不要在被控回路上闭环』写成了流程约束。」 |
| 「上电自动标定吗？」 | 「不自动。标定按需触发（KEY0 或写 `0x0502`），参数掉电复位中性，这是为了不让一次坏窗口污染整机。上电后用的是上一次烧录/写入的参数，或现场一键标定。」 |
| 「没有外部基准，怎么证明精度？」 | 「所以对外只报**仿真口径** 0.0165°（golden model、单周期电角度、恰好 3 LSB16 量化底噪）与**真机分箱残差** ±0.13°；±1″ 是目标不是结论。全周表通路已打通并逐点回读，等 ±0.5″ 基准到位即可开（R15 已如实登记）。」 |
| 「你们 RTL 注释里写着『构成闭环』？」 | 「那是 v9 EMA 版的旧注释，v66 已改成块率积分，注释没同步。以 `rtl/bias_track.v:10-15` 和 `design_report.md:1452` 为准。」（**最好提交前把这行注释改掉，别留这个把柄**） |

**「多协议」成立**：v90 生产位流 5 路（ABZ+Z / UVW / SPI 从站 / UART / 1 GbE），全部有 RTL 实例与引脚约束（`constr/enc_top.xdc:283-298`）。

**「高速」成立，但必须**逐协议**说**：
- 1 GbE：抓窗 **28,672 点 @50 MSPS = 0.573 ms**、ping **4/4**（2026-11-04 v90 实测；连续流 62,502 包/s 是 v62 旧测）—— **唯一的"高速"实测**；
- ABZ：边沿率 12.5 MHz 是**上限**；v90 转台 457–459 rpm（2048 p/r，正交 8192 边沿/转）对应约 **62.5 kHz 边沿**，余量约 200×（v74 期在 740 rpm 下实测 101 kHz 边沿，可作上限侧旁证）；
- SPI：12.5 MHz 是**结构上限**，没有外部主机上板证据；
- UART：2 Mbaud 是遥测口，占空 90%。

⇒ 把「高速」写成一个笼统形容词是危险的；写成「千兆以太网 ping 4/4、28,672 点 @50 MSPS 抓窗（0.573 ms）+ ABZ 12.5 MHz 边沿率上限」就不会被问倒。

**「适配」成立，但有边界**：`0x0100`–`0x010C` 全**运行期**可配——极对数 1…32、细分 2…256、后分频 1…8、AB 迟滞、UVW 死区、AB 限频 256 档、Z/UVW 相位、极性/方向、ABZ/UVW 输出使能（`rtl/reg_file.v:57-70,413-425,694-701`）。

★ **边界（必须知道）**：**没有协议选择寄存器**；SPI 帧格式是编译期 `USE_PKT_MODE`（v90 固定 1 = 32 位包模式，0 = 2 字节模式）；UART 波特率/帧率是编译期参数；**CPR 无寄存器**——`ENC_V69_CPR2048` 只是显示位流的编译期 define，只影响屏幕 RPM 换算，不影响 ABZ。
⇒ 所以「适配」应说成「**细分比/分频/相位/极性/使能运行期可配，接口形态编译期选定**」，而不是「一套位流适配任意主机」。

### 3.2 「高速」的边界（必须主动说，反而是加分项）

`design_report.md:370-375` 有一段**判决性实测**：

> 「700 kHz 输入 + 256 倍细分物理上不可能同时成立」。板上实测：`inter=256 @ 20 kHz` 要求 20.48 MHz 边沿率 ⇒ 实测 256 边沿 vs 应有 422.7 = **0.606×（丢 39.4%）**`[实测]`。

这段话的正确用法是**当成设计成熟度的证据**：我们知道极限在哪、用可编程限频把输出钳在 12.5 MHz 以内、并且拿实测证明了钳位生效。写进关键词解释里比藏着强——评委问到「12.5 MHz 怎么来的」时，答案是「我们实测撞过墙」。

同理 UART 的 **90.0%** 占用率也要说：它是**遥测口**不是主数据口，主数据口是以太网。（报告 `:610` 写 90.7%，见 §3.4 #4。）

### 3.3 不能写

- ❌ **BiSS-C**：`rtl/` 下已无 `biss_c_slave.v`（24 个 `.v` 里 `biss` 命中 0），git 提交 `e1109ec`「drop BiSS-C claims」删了 RTL/仿真/模型/探针/文档，引脚已释放（`rtl/enc_top.v:95-96`），抽头位恒 0（`:1813,1836`）；`docs/DEV_STATUS.md:16089` 记录 BiSS-C 在 v74 之前删除。**残留只有文档**：`rtl/SPEC_interface_contract.md:435-481`（§1.10，47 bit/CRC6/5 MHz 下 9.4 µs 帧）与 `_disp_work\`、`_sim_work` 里的旧仿真产物——**别在这些残留上被问住**。
- ❌ **SSI / EnDat / 编码器侧 I²C 从站 / 模拟正弦输出 / CAN / EtherCAT**：全都没有。唯一的 I²C 是**显示位流里的屏触摸主机**（`disp/i2c_master_seq.v`，例化 `disp/enc_top_disp.v:339-381`），不是对外接口。同类专用细分 ASIC 的公开资料同样没有 SSI / 模拟输出 / 正弦输出，所以这不是短板，但绝不能写成「支持」。
- ❌ **「共用同一 32 位角度字」**（现行旧词「多协议同源」的解释）：`design_report.md:1376-1384`（§11.8）明确写，ABZ 曾被切到 `angle_rep`，实测边沿 2048→4611（反向 4733）、UVW 扇区 24→22、`max_dev` 1763 LSB16，因此**回退**；现在 **寄存器/以太网回读 = 修正后位置（前馈+查表），ABZ/UVW/Z = 未修正原始位置**，两者只差固定延迟。⇒ 旧词「同源」是**错的**，**新词「多协议高速输出适配」恰好把这个错修掉了**，这是换词的额外收益，建议在变更说明里点出来。
- ❌ **「真实 Z 输入」**：只有**内部虚拟 Z**（每转 1 个，由内部计数产生）；真实 Z 需 J5 空闲脚 + AM26LS32（R16，`:1467`）。写「Z 输入」会被问「你的 Z 从哪来」。
- ❌ **「千兆链路全功能」**：无 MDIO，PHY 跑默认速率/双工，100 Mbps 对端不通；`eth_reply` 128 B 缓冲（`:1468-1469`）。写「1 GbE」可以，但**主用路径是 UDP 流 + 抓包**，不是通用联网。
- ❌ **「ABZ/UVW 也是修正后位置」**：`:1471` 明确「ABZ / UVW 用未修正位置（这是设计决定，不是缺陷）」，因此这两路看不到前馈补掉的 46″。

### 4.2 「高精度」到底能撑到哪

- **能撑**：细分引擎本身（CORDIC + 六参数校正）的数值性能有 `[仿真]` 硬支撑，0.9375 LSB 离 1 LSB 目标只差 6.25% 裕量，这是**RTL 级位精确**的结果，不是估算。
- **能撑**：真机 2048 电周期无丢拍、UVW 六态均衡、60 s UART 遥测 **597,886 帧 / 9,964.8 fps** 不丢 `[实测]`（2026-11-04 v90）——证明**通路与鲁棒性**（注意：597,886 是遥测帧，不是以太网帧）。
- **撑不到**：±1″ 机械精度。`design_report.md:1313-1317` 自己算过：细分余量两个数量级，**±1″ 的敌人是刻度误差/偏心、相位滞后 ω·T、偏置漂移、丢信号**，不是细分算法。
- **撑不到**：把 0.0165° 当真机精度（`[仿真]`）；把 0.0055°/LSB 当机械分辨率（那是**电角** LSB，机械是 0.0097″，两个数差 2048 倍，混用会被当场抓）。

### 4.3 不能写 / 必须限定

| 不能写 | 为什么 | 改成 |
|---|---|---|
| 「SMR 磁阻 + 2048 周期/转磁环」当既成事实 | 真实 SMR 传感头未接入（R7）；2048 周期/转来自**转台增量式编码器**（§6.7） | 「面向 SMR 磁阻等正交信号源设计的通用细分引擎；真机验证用 2048 周期/转转台编码器」 |
| 0.0165° 不带标签 | 是 golden model `[仿真]` | 保留数字 + 显式 `[仿真]` |
| 「精度 ±1″」 | 目标非结论，且无基准 | 「±1″ 为设计目标；当前真机分箱残差 ±0.13°」 |
| 「16 位绝对角度（0.0055°/LSB）」单独出现 | 0.0055° 是**电角** LSB，机械 LSB 是 0.0097″；两者差 2048× | 写全：「16 bit/电周期（0.0055° 电角；2048 周期/转下 0.0097″ 机械）」 |

### 4.4 「正余弦」这个词站得住吗

站得住，而且有独立证据：`design_report.md:642-653`（§5.2）写系统设计为**通用正余弦细分引擎**，输入接口对 SMR/TMR/AMR/光电/旋变等任何正交信号源均兼容。真机测试用 AFG-2225 产生 1 kHz / 8 Vpp / 90° 正交信号（模块 10 Vpp 即满量程，故统一用 8 Vpp），转台侧是 0.5 Vpp/腿经 G=8 差分转单端到 8 Vpp。

⇒ 「FPGA 正余弦细分」是**对系统输入性质的准确描述**，比旧词「SMR 磁阻」更安全（旧词把未接入的传感器写成了已用）。

## 5 三关键词整块（可直接粘贴）

两版。**A = 推荐**（关键词 1 用「闭式」，与设计取舍一致，零风险）；**B = 次推荐**（保留用户的「闭环」，但必须在词后紧跟限定语，并背熟 §2.5 的四问）。

### 版本 A（推荐：零风险）

```markdown
1. **闭式自校准**——六参数一阶/二阶矩一次解算（1 个窗口 ≈64 个电周期、约 1 µs），椭圆→单位圆；免迭代、免查找表、免上位机试凑，20 轮一键标定 20/20 一致、参数幂等。
2. **多协议高速输出适配**——生产位流并行输出 ABZ+Z（边沿率 ≤12.5 MHz、f_AB ≤3.125 MHz、最小边沿 80 ns）、UVW（1…32 极对，六态计数 `{5174,4761,4423,4776,4763,4786}`、523 次/3 s）、SPI 从站（≤12.5 MHz，32 位包模式）、UART 2 Mbaud 遥测（60 s **597,886 帧 / 9,964.8 fps** 不丢）、1 GbE UDP（ping **4/4**、抓窗 **28,672 点 @50 MSPS = 0.573 ms**）；以上均为 **2026-11-04 v90 实测**。细分比 2…256、分频 1…8、迟滞、限频、极对数、相序、极性、输出使能全部运行期寄存器可配。
3. **FPGA 正余弦高精度细分**——面向 SMR/TMR/AMR/光电/旋变等正交信号源的通用细分引擎；17 级全流水 CORDIC（max 0.9375 LSB / RMS 0.3229 LSB，[仿真]）＋六参数闭式校正（复合畸变 20.9839°→0.0165°，[仿真]）；16 bit/电周期（2048 周期/转下机械 LSB 0.0097″），真机 2048 电周期无丢拍、分箱残差 ±0.13°（[实测]）。
```

### 版本 B（次推荐：保留「闭环」，但词后必须限定）

```markdown
1. **闭环自校准**（标定—复核闭环）——硬件侧六参数一阶/二阶矩一次解算（1 个窗口 ≈64 个电周期、约 1 µs、免迭代），上位机按判据回读复核并重跑：20 轮一键标定 20/20 通过、参数幂等（差全 0）；偏置慢跟踪（块率 2.62 ms）与全周补偿表作为可启用扩展通路。
2. **多协议高速输出适配**——生产位流并行输出 ABZ+Z、UVW、SPI 从站、UART、1 GbE UDP 五路；ABZ 边沿率 ≤12.5 MHz（f_AB ≤3.125 MHz、最小边沿 80 ns、256 档可编程限频）、SPI 从站 ≤12.5 MHz（建议 10 MHz）、UART 2 Mbaud（60 s **597,886 帧 / 9,964.8 fps** 不丢）、以太网 ping **4/4** + 抓窗 **28,672 点 @50 MSPS = 0.573 ms**（**2026-11-04 v90 实测**）；细分比、分频、迟滞、限频、极对数、相序、极性、使能全部运行期可配。
3. **FPGA 正余弦高精度细分**——面向正交信号源（SMR/TMR/AMR/光电/旋变）的通用细分引擎；17 级全流水 CORDIC 相位解算（max 0.9375 LSB / RMS 0.3229 LSB，[仿真]），六参数闭式校正把复合畸变从 20.9839° 压到 0.0165°（[仿真]）；真机 2048 周期/转、分箱残差 ±0.13°、2048 电周期无丢拍（[实测]）。
```

### 7.4 0.0055°/LSB 与 0.0097″ 的口径混用风险

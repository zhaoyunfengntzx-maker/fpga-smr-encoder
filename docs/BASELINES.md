# 基线总表（v62 → v85）

本文件是全部位流基线的**唯一汇总口径**。每个数字都能在
[`deliverables/data/`](../deliverables/data/) 下找到对应报告或日志；
逐条哈希见 [`deliverables/data/SHA256SUMS.txt`](../deliverables/data/SHA256SUMS.txt)。

## 0. 口径

| 标记 | 含义 |
|---|---|
| `[构建签核]` | Vivado 实现完成，时序/DRC/布线报告齐全，位流可下载 |
| `[上板]` | 已下载到真实板卡并有人工读数/遥测记录 |
| `[验收]` | 按验收清单逐项确认（转台转速、Z、UVW、屏、触摸、以太网） |
| `[目视]` | 屏上 5 页逐页看过（与 `[上板]` 不同） |

**生产位流** = 编码器本体，无屏、无以太网，综合时**不带** `ENC_DISP_TAP`。
**显示位流** = 编码器 + 5 页 UI + 千兆网，必须带 `-verilog_define ENC_DISP_TAP`
（v74/v85 另加 `ENC_V69_CPR2048`）。两者不可混用。

## 2. 关键关系

- **v74 = v71 + Z 脉冲计数探针 + `RTL_BUILD_ID=0x0018`**。与仓库 `rtl/` 的差异只有
  `RTL_BUILD_ID` 与只读探针（`0x054A..0x054D`），不改变控制路径。派生脚本
  [`tools/make_v74_rtl.py`](../tools/make_v74_rtl.py)，构建脚本
  [`tools/impl_check_v74.tcl`](../tools/impl_check_v74.tcl)。
- **v85 = v74 的 RTL + v75–v85 的 `disp/` 改动**。六个 RTL 文件与提交版仅注释不同
  （"BiSS"→"rtl/"），综合等价，因此 v85 可由本仓库 `rtl/` + `disp/` 直接复现：
  `vivado -mode batch -source tools/impl_check_disp_v74.tcl`。
- v62 是"屏 + 网 + 编码器"同板跑通的演示基线；v70/v73/v74 的生产位流都在转台上做过
  上板验收，其中 **v74 是当前签核基线**（数据最全、资源余量最大）；v85 是最新显示构建，
  **只到 `[上板]`，没有 `[目视]`**。
- 显示位流的 BRAM 从 v71 起就是 48/50（96%），v74/v85 没有再增加 BRAM；
  v85 的 LUT 增长（84.63%→86.96%）来自 P7 相对误差曲线与 Z 计数门控。

## 3. 每个版本怎么复现

| 版本 | 复现命令 / 脚本 |
|---|---|
| v67 | `tools/make_lowsig_rtl.py` → `tools/impl_check_lowsig.tcl` |
| v68 | `tools/make_v68_rtl.py` → `tools/impl_check_v68.tcl` |
| v70 / v71 / v73 | `tools/make_v70_rtl.py` / `make_v71_rtl.py` / `make_v73_rtl.py` → 对应 `tools/impl_check_v70.tcl` / `impl_check_v71.tcl` / `impl_check_v73.tcl` |
| v74 / v85 | `tools/make_v74_rtl.py` → `tools/impl_check_v74.tcl`（生产）/ `tools/impl_check_disp_v74.tcl`（显示） |

脚本都在 [`tools/`](../tools/)，每次构建把报告写到 `_impl_*/` 并自动打印
WNS/TNS/DRC/布线汇总；签核判据见 [`tools/final_verify.ps1`](../tools/final_verify.ps1)。

## 5. 版本选择建议

- **答辩/提交**：以 v74 生产位流为准（时序、资源、转台数据都最完整）。
- **演示屏与上位机**：用 v85 显示位流（UI 最新），但话术必须是"构建签核 + 已下载"。
- **只关心编码器**：v74 生产位流即可，资源余量大（LUT 52.53%、BRAM 32/50）。
- **不要**把 v74 显示位流当作"最新 UI"——它已被 v85 取代，仅作血缘证据保留。

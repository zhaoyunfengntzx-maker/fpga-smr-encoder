## 1. 结论摘要

| 项 | 结论 |
|---|---|
| 页面从 8 页减到 5 页 | **已实现**：删 **P3 李萨如 XY / P5 六状态 / P8 系统信息**，保留 P1 总览、P2 输入波形、P4 逻辑时序、P6 设置、P7 标定（页号留空洞 0/1/3/5/6） |

| 文字清晰度 | **已实现**：数值改 **30×48 原生栅格化**（Arial Narrow Bold，墨迹在 32×64 格里 y_off=8、cap 高 48），小字 11×14（Arial Bold）。计划里的"格 32×48 省 ROM"**未采纳**——64 行是 2 的幂，ROM 地址才是纯拼接 |

| 资源收益 | **实测（P&R）**：LUT **−2,434（79.63% → 67.93%）**、BRAM **−1 块（99% → 97%）**、DSP **−4**；详见 §9.6 |
| 蓝线异常 | **已修复**：`disp/disp_engine.v` 卡 6 电平条缺 `page==0` 门控，每页都画（§3.8） |
| 工作量 | 实际按 M1–M5 一次做完，落在"仿真 + 实现"两层验收上（上板未做） |

> ★ 这张表初版是**计划书**，2026-10-22 收尾时按实际落地结果逐行改写。
> 两处与计划不同，原因都记在 §8/§9：① 38→36 行省 BRAM 的推算**是错的**
> （BRAM 受深度约束，2304 字仍要 RAMB36，省不了）；② 2×3 总览暂缓。

**两笔最大的资源收益（按实测修正）**：① 删 P3 的 XY 点阵 RAM
（`disp/legacy/xy_ram.v` 是 131072×1 bit = 4 块 RAMB36）+ 删 3 页各自的文字 RAM；

（RAMB18 最深 2048×9，2304 字仍要 RAMB36），压到 36 行省不了任何块，已取消。

### 2.3 文字/字模现状（R1 的根因）

- `tools/gen_font_rom.py`：`ASCII_SIZES = [lab: cell 16, 字形 10×14, 2 倍; val: cell 64, 字形 30×42, 6 倍]`。
- 源字模只有 **5×7 手写点阵**，生成时**最近邻整数倍放大**：
  - 大字 30×42 = 5×7 放大 6 倍 ⇒ 每一笔都是 6 px 粗的方块，这是"糊"的主因，不是分辨率不够；
  - 小字 10×14 = 5×7 放大 2 倍 ⇒ 尚可，但笔画同样偏粗。
- 汉字 16×16 原生点阵（`tools/cn_glyphs.py`），本身清晰，不在本次改造范围。
- 字模已预放大存 ROM，像素路径只读一次 ROM，运行期不做除法/乘法（`disp_engine.v:22-35` 的纪律）。
- ⇒ **换成按最终像素尺寸原生栅格化的字模，ROM 深度/位宽不变，像素路径不变，BRAM/LUT 增量为 0。**

## 3. 需求逐条

### R1 文字适度提升分辨率

- **方案（定稿）**：`lab` 格 16×16 不变；`val` 格由 32×64 改 **32×48**（字形 30×48），
  格行省 16 行正是 ROM 的净减量：
  - 大字：用等宽字体（Consolas / 思源等宽）在 30×48 原生栅格化 + 阈值化，
    数字/小数点/负号/`×`/`÷`/`%`/`○` 逐字符校验；字重可调到 2–3 px 笔画。
  - 小字 ASCII：用 10×14 原生点阵替换 5×7×2，汉字不动。
  - 顺带把 lab 格网 38 → 36 行（18,432 bit 正好一块 RAMB18），与 M1 同批做完。
- **代价**：`tools/gen_font_rom.py` 新增栅格化路径（约 100 行）；`font_rom.v` 重生成；
  `text_ram.v` 与 `val_format.v` 的格行换算参数化；`tb_font_rom.v` 的字形期望值需同步。
- **风险**：中。字库覆盖（140 个 lab 码 / 52 个 val 码）必须逐码核对；阈值化可能让细笔画断线，
  需要 1–2 轮人工看预览图；格网 38→36 会牵动 P6 行带与 P7 版式，必须逐页比对。
- **收益**：观感提升最大的一项；ROM 反而从 99,840 bit 降到 ≈80,000 bit，lab 每页从 1 块 RAMB36 降到 1 块 RAMB18。
- **可选增强**：2 bit 灰度抗锯齿（4 级）——字模 ROM 位宽 30→60 bit，需要一次颜色混合，
  约 +2 LUT；但会让 BRAM 用量翻倍（多 1–2 块），**建议不做**，保持 1 bpp。

### R2 省去不必要的显示页

- 与 R5/R7 合并处理（见 §5）。**推荐一次删 3 页：P3、P5、P8**。
- 注意：`docs/13_display_ui_requirements.md` 与 `docs/15_display_touch_bringup.md` 的
  页面清单/坐标/验收步骤是按 8 页写的，删页后必须同步改，否则测试清单会指向不存在的页。

### R3 删除左侧导航「XY」

- 若只删导航项而保留 P3，P3 将只能靠 KEY1 循环进入（等于隐藏页），不合理。
- **建议连 P3 页一起删**（与 R2 合并），导航 6→4 项。
- **导航改法**：`NAV_H` 96→144（4×144=576，正好 24..599），仍用比较器不用除法器
  （`hit_test.v:192-198` 与 `disp_engine.v` 的 `nav_idx` 两处同步）；标签行号
  `tools/gen_text_ram.py` 的 `NAV` 改为 4 项并重算行号（24/144→行 3/12/21/30），
  所有保留页的 lab 平面前缀一起改。
- **导航宽度**：建议保持 80 px（触摸舒适、P2/P3 轨迹区已是按 80 起算）；若想再省，
  可收窄到 64 px，把 P2/P4 的轨迹区加宽 16 px —— 收益小、改动面大，**不推荐**。

### R4 时序页波形纵向放大、填充页面

- 现状：框 y=140..480（340 px），6 行 ×48 = 288，轴 452，**y 480..599 有 120 px 空白**。
- **方案**：框改 y=140..596，行高 48→**68**（6×68=408，152..560），
  时间轴 572，刻度 576..586，角度数字 588..600（或把 8 个角度数字并进轴内）。
- 底部那行「按电角度重建128箱等效采样」移到标题带右侧（与「展开」按钮位置二选一），
  或缩为轴下小字。
- **「展开」按钮必须删**：它唯一的动作是 P4→P5（`enc_top_disp.v:722-726`），P5 删后无意义。
  删除按钮 = 少一个 hit 区域、少一组 LUT，也避免"点了没反应"。
- **代价**：`disp_engine.v` 的 `LG_*` 常量 + 行号比较链（行高 68 不是 2 的幂，行号比较从 5 档变 6 档即可）；
  `logic_scope.v` 只存电平，不受影响；`gen_text_ram.py` 的 P4_LAB 行号重排；`tb_disp_engine.v` 的 P4 坐标断言同步。
- **风险**：低–中。纯几何，无新存储。

### R5 删除状态页（P5）

- 页面本身 + `p5_view`（851 LUT、1 DSP、1 块 lab RAM）+ `disp_engine` 里的表格/条形图几何
  （约 150 LUT）+ P4「展开」入口一起删。
- **需要确认**：六状态占比（U/V/W 八种组合的统计）是否还要在上位机或别处看？
  目前它只在这一页显示；P1 卡片 6 的 `U● V● W○` 迷你条仍在，基本状态不丢。
- **风险**：低。删除面清晰，但测试台 `tb_p5_page.v` 整文件作废（保留历史或删）。

### R6 不重要的信息不采集

- 先明确边界：**只删"显示页专用统计"，不动编码器采集（ADC/ABZ/UVW/位置环）与上位机遥测**。
- 可删清单（按收益排序）：
  1. P5 六状态占比统计（随 R5 消失，851 LUT + 1 DSP）。
  2. P8 的 LUT/BRAM/DSP 百分比、IIC 计数、自检结论（随 R7 消失，约 300–400 LUT；
     这些百分比是**常量且已过时**，留着反而误导）。
  3. P2 右下四枚徽标 VPP-PC / F-HZ / DT-US / DV-PC（`p2_badge` **585 LUT + 3 DSP**）——
     **已确认删除**（§7），这是单笔最大的 LUT 收益之一。
  4. P3 XY 点采样（随 R3 消失，`xy_plot` 59 LUT + 4 块 RAM）。
- **不建议删**：`freq_meter`（输入频率是总览第一卡）、`val_format`（P1/P6 数值）、
  `p7_view`（标定曲线与参数）。
- 这些"采集"都在显示侧、每帧跑；删页后对应写使能自然消失，**不需要额外门控**。

### R7 删除系统信息页（P8）

- 与 R5 同批：`touch_view` 151 LUT、`band_view`、`selftest_lab`、`p8_lab_ram` 1 块、
  `p8_val_ram`、状态栏「⚙」图标与其 hit 区域（`hit_test.v` 的 `HIT_SYS`）。
- **固件版本号已确认不保留**（§7）：P8 删掉后版本号不再显示，需要时查上位机/烧录工具；诊断信息全删。

### R8 右下角蓝色线异常 —— 已用上板照片定位

- **现象（7 张上板照片）**：P1/P2/P3/P4/P7 的右下角都有 1–3 条 1 px 横线，
  位置固定在 **x≈752..1007、y≈512..560**，间距 8 px；其中长的（≈255 px）是蓝色，
  短的（16 px）是浅蓝。P6 看不到；P1 上它们恰好在卡片 6 底部，看起来"正常"。
- **根因（确定）**：`disp/disp_engine.v:2416-2426` 的卡 6 迷你六通道电平条
  （`C6_X0=752, C6_X1=1007, C6_Y0=512`，6 道 ×8 px，`cy[2:0]==4` 时落 1 px）
  **没有按页门控**：

  ```verilog
  wire c6_band = (cy >= C6_Y0) && (cy < (C6_Y0 + 12'd48)) &&
                 (cx >= C6_X0) && (cx <= C6_X1);      // ← 缺 (page == 3'd0)
  wire c6_lvl  = c6_mid ? q_io_state[c6_k] : 1'b0;
  wire c6_draw = c6_mid && (c6_lvl || c6_stub);        // 电平 1 画满 C_ACC(蓝)，0 只画 16 px 短桩 C_GRID
  ```

  这段本该只属于 P1 卡片 6，实际每一页都在同一位置画 —— 于是每页右下角都浮出
  几条通道电平线。电平为高的通道 = 长的蓝线，为低的 = 短的浅蓝线。
- **为什么 P6 没有**：危险区 `dz_px` 在合成链里层级更高（`with_dz = dz_px ? dz_col : ...`），
  把这几条线盖住了 —— 正好对应"大多数页面"。
- **为什么预览图里没有**：`tools/preview_pages.py` 把这段画在 P1 分支里，**预览与 RTL 不等价**。
- **修法（1 行）**：`c6_band` 加 `(page == 3'd0)`；补两条断言：
  `tb_disp_engine.v` 加"非 P1 页在 (800,516) 必须是页面底色"、"P1 页在 (800,516) 必须是电平线"；
  预览不用改（它本来就是对的），但要把这条差别记进"预览/RTL 对账清单"。
- **代价**：半天（与 R9 同批，已并入 M1）。**状态：RTL + tb + 预览三处已改，待仿真通过**。

### R9 总览页导航「设置」消失 —— 照片已复现

- **现场**：P1 照片左侧只有 总览/波形/XY/时序/状态 五项，**「设置」确实没有**；
  P2/P4 照片里六项齐全 ⇒ 是 P1 独有。
- **根因**：`disp_engine.v:2022-2026` 的 `glyph_page` 为隐藏面板模态字，
  在 P1 上**整行**排除 `lrow2==21 || lrow2==34`；导航「设置」的 lab 格正好在
  **行 34、列 1**（`tools/gen_text_ram.py` 的 `NAV`），被一起抹掉。
  注意 :2007 的注释写的是"P1_LAB 用 5/13/15/22/33/35 行"，**漏算了 NAV 的行 34**。
- **修法**：行 21/34 的排除加格列门控 `cx[9:4] >= 6`（面板左沿 `PNL_X0=96`=列 6），
  导航列 1 保留。三处同步：
  - `disp/disp_engine.v:2022-2026`
  - `tools/preview_pages.py:862-865`（`if page == "p1" and not panel: for r in (21,34)` 同样加列门控）
  - `disp/tb_disp_engine.v` 的 P1 行 21/34 判据（补"面板关时 (1,34) 必须是导航字"）
- **风险**：低。行 21 的 `倍频分频 / PRESET` 在列 7/28，行 34 的 `CANCEL/APPLY/回到`
  在列 13/30/46，都在列 6 之后，不会被漏抑制。
- **代价**：半天（含预览与回归）。

### R10 其它可省资源的点

1. **文字层 RAM 压缩（可选，收益大、风险中）**：当前每页 19,456 bit（38 行×64 列×8 bit），
   只比一块 RAMB18（18,432）多 1,024 bit ⇒ 每一页都占一块 RAMB36 却只用一半。
   把格网从 38 行压到 36 行（18,432 bit，正好一块 RAMB18），两块拼进一块 RAMB36：
   保留 5 页时 5 块 → 3 块，**再省 2 块**。代价：行 36/37 目前被 P2 徽标/P8 底栏占用，要先上移；
   `text_ram.v` 地址映射与 `lab_raddr` 要改。**建议放到第二阶段，先不做**。
2. **P2/P4 轨迹 RAM**：`wave_ram` 2048×32 bit = 2 块，双缓冲；若 P2 只保留 1 条通道可减半
   （不建议，双通道是核心信息）。
3. **删页后的死代码**：`p5_view.v`、`touch_view.v`、`band_view.v`、`selftest_lab.v`、
   `xy_plot.v`、`xy_ram.v`、`p3_lab_ram`/`p5_lab_ram`/`p8_lab_ram` 全部从 `disp_engine` 例化里摘掉，
   否则综合仍会保留（Verilog 不会自动优化有输出的模块）。
4. **状态栏「⚙」**：随 P8 删除，少一个 hit 区与图标绘制。
5. **不动的**：2 Hz 闪烁/反色状态条（spec 要求的四重冗余）、危险区二次确认、面板键盘。

### 10.2 125M ↔ sys_clk 的 CDC 约束

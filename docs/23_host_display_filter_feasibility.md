# 上位机显示滤波可行性分析

> 结论先行：**可行、低风险，但优先级最高的不是“滤波”，而是“显示抽稀”**。
> 抓包页现在是「每 12 个点取 1 个直接画」，这是波形看起来毛、毛刺时有时无、缩放后形状变的主因；
> 换成 min/max 包络是**零失真**的，成本 <1 ms。真正的平滑滤波建议做成**可选、默认关、只影响显示**的第二层。
>
> 本文只做分析，未改任何代码。请确认 §8 的四个选项后再开工。

## 2. 图像“不好看”的三个来源（必须分开治）

| 来源 | 现象 | 正确手段 | 滤波能解决吗 |
|---|---|---|---|
| **显示抽稀**：每像素 24 个点只画 1 个 | 毛刺带时有时无；窗口一拉伸形状就变；尖峰概率性消失 | **min/max 包络抽稀**（每像素列画 [min,max]） | ❌ 不能，反而更糟 |
| **真实噪声**：ADC 几个 LSB + 前端 | 线粗、XY 图毛、读数末位跳 | 可选零相位平滑（FIR / 中值 / Savitzky-Golay） | ✅ 能 |
| **触发/采样抖动** | 波形左右轻微错位、叠加变粗 | 触发对齐、多次平均 | ⚠ 低通只能部分掩盖 |

> 关键点：现在 1.15 ms 窗口里画 28672 个点，1440 px 宽只能放 ~1200 列 ⇒ **每个像素代表 24 个采样点**。
> 点采样会把 24 个点里的尖峰随机丢掉 → 这正是“看着糊、缩放后不一样”的根因。

## 3. 候选算法与实测开销（28672 点，本机实测）

| 算法 | 作用 | 耗时 | 失真 | 依赖 |
|---|---|---|---|---|
| min/max 包络抽稀 | 保峰抽稀，治显示混叠 | **<0.2 ms** | 无（保留每列极值） | numpy |
| 移动平均（cumsum） | 最简单平滑 | 0.11 ms | 削峰、-3 dB 带宽随窗宽降 | numpy |
| 中值滤波 w=9 | 去毛刺、保边沿 | 0.57 ms（scipy）／~3 ms（numpy 滑窗） | 会抹掉 ≤4 点的窄脉冲 | numpy/scipy |
| Savitzky-Golay 11/3 | 保峰平滑（推荐默认平滑） | 5.56 ms（scipy）／~2 ms（预存系数卷积） | 轻微 | numpy 可实现 |
| FIR 低通 63 taps（窗函数法） | 线性相位、零相移 | ~0.4 ms | 有过渡带 | numpy |
| Butterworth + filtfilt | 零相位 IIR | 0.31 ms | 相位已补偿，仍有振铃 | **scipy** |
| FFT 低通/小波去噪 | — | 5–20 ms | 易出振铃、参数难解释 | scipy/pywt |
| 50 Hz 陷波 | 工频干扰 | — | — | **不适用**：1.15 ms 窗口连 50 Hz 的一个周期都不到 |

**结论：不需要引入 scipy。** 用 numpy 就能实现 min/max 包络、移动平均、中值、SG（预存系数）、FIR 低通，
全部 ≤5 ms，对 1 Hz 级的人工抓包和 300 ms 的连续流刷新都绰绰有余；也避免给 558 MB 的交付包再加 ~40 MB。

## 4. 三种落地形态（这是最需要拍板的设计决策）

| 形态 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **A. 纯显示**（建议默认） | 只在绘制前生成显示数组，`res.s/res.c` 一个字节都不动 | 数据可信、导出仍是原始 | 用户可能以为看到的就是存下来的 |
| **B. 可导出滤波后** | 勾选后另存 `*_filt.npy`，文件名/PNG 标注参数 | 便于做演示图 | 容易和原始数据混淆 |
| **C. 测量前处理** | 滤波后再算频率/幅值/相位 | 读数更稳 | **必须**标延迟与不确定度，否则等于篡改测量 |

建议：**只做 A + B（B 必须显式勾选）**；C 不做，或只提供“多次触发平均”这种无损手段。

## 5. 建议路线

| 阶段 | 内容 | 工作量 | 收益 |
|---|---|---|---|
| **P0** | min/max 包络抽稀（抓包页 + 连续流） | 0.5 天 | 解决 80% 的“图不好看”，零失真 |
| **P1** | `host/filters.py` + 抓包页「显示滤波：关/3/5/9/15」下拉；实时页与 XY 共用；图上标注当前参数 | 1 天 | 噪声大时线更干净，可随时关 |

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| 削峰：窄脉冲被低通压平 | 默认关；下拉里明确写“平滑（会削峰）”；中值/SG 优先于低通 |
| 相位：IIR 有相移 | 只用零相位实现（对称 FIR 或 filtfilt 等价物） |
| 误读：读数与原始不一致 | 图上必须显示「已滤波 w=9」；状态栏同步 |
| 性能：每帧对 28k 点重算 | 只对**显示数组**算，并缓存；拖动/缩放不重算 |
| 数据污染 | 自检断言：关滤波时输出与输入**逐点相等**；导出文件里写参数头 |

---

## 7. 不推荐的做法

- 对连续流 **12.5 MSPS 全采样率**滤波：每秒 1250 万点，纯浪费 CPU，显示只用 1024 点。
- 自适应滤波 / 小波 / FFT 域去噪：参数难解释、易造假象，示波器场景收益低。
- 50 Hz 陷波：窗口 1.15 ms，根本看不到 50 Hz。
- 默认开启任何平滑：会让用户误判“信号本来就这么干净”。

## 8. 需要你确认的 4 个选项

1. **范围**：只做 P0（包络），还是 P0+P1（包络 + 可选平滑）？
2. **默认状态**：平滑默认**关**（建议）还是记住上次？
3. **导出**：是否允许另存“滤波后”数据（建议允许但必须勾选）？
4. **页面**：只改抓包页，还是实时页 + XY 图也一起加？

## 10. 「以太网和串口的波形一样好看」能保证到什么程度

**能保证，而且是结构性的，不靠“调参调得像”。** 但要先把话说清楚：

### 10.1 为什么能保证

| 环节 | 串口通道 | 以太网通道 | 是否同源 |
|---|---|---|---|
| 板上缓冲 | 同一块 `scope_capture` 28672 点 | 同左 | ✅ 同一块 RAM |
| 采样格式 | int16 小端 s/c | 同左 | ✅ 逐点同格式 |
| 主机结果对象 | `CaptureResult`（`host/capture.py`） | `CaptureResult`（`host/udp_capture.py`） | ✅ 同一个类 |
| 绘图代码 | `CapturePlot` / `WavePanel` | 同左 | ✅ 同一个控件 |
| 滤波/包络（P0/P1 后） | 同一个 `filters.py` | 同左 | ✅ 同一段代码 |

也就是说：**滤波和包络作用在“显示数组”上，跟数据从哪条链路来完全无关**。
做完 P0/P1 后，同一份 28672 点数据无论走串口还是以太网，画出来的像素应当一模一样。

### 10.2 唯一真实的风险：丢块补 0

- 以太网：`host/udp_capture.py` 按 `first` 归位，缺包的位置**补 0**（记 `covered`/`dropped_range`）。
- 串口：`host/capture.py` 按块下标归位，丢块同样补 0。

补 0 的区段在图上就是一条平线/毛刺，**任何滤波都救不回来**，而且会让“好看”变成假象。
所以“一样好看”的前提是：**缺块 = 0**。这一点必须做成硬门槛，而不是靠运气：

- 抓包摘要里 `缺块 N` 必须红色显示；N ≠ 0 时不允许出“标准波形”的结论；
- UDP 已有“缺块自动重试一次”，P1 再加一条：重试后仍缺块 → 图上把缺块区间标黄。

### 10.3 可以写成验收的三条

| # | 验收项 | 判定 |
|---|---|---|
| 1 | **渲染一致性**（离线，可进自检） | 同一份数组分别包成“串口结果”和“UDP 结果”，经同一绘图纯函数后**逐像素一致** |
| 2 | **传输完整性**（上板） | UDP `missing = 0`、串口 448 块齐全、主机端块 XOR 全过 |
| 3 | **上板 A/B**（上板，统计而非逐点） | 同一稳定信号，两条链路各采 10 次，峰值/RMS/频率的**分布**一致（不逐点比，因为两次采集时刻不同、相位本来就不同） |

### 10.4 不能保证、也不该承诺的

- **不同时刻采集的波形本来就不一样**（自由触发时相位不同），这跟传输方式无关；
- 以太网在缺块时**不会**比串口“更好看”，只会更糟（串口丢的是整块 264 B，以太网丢的是 816 B 一包）；
- 滤波只能改善“噪声造成的粗糙”，不能改善“丢数据造成的断裂”。

### 10.5 顺带一句

以太网通道的**吞吐**远好于串口（2 ms vs 0.66 s），且不占用遥测链路；所以正常情况下，
以太网这条路的显示质量应当**等于或优于**串口——前提仍是缺块为 0。

## 11. 落地记录（P0 / P1 / P2，2026-10-22 晚）

### 11.1 做了什么

| 项 | 文件 | 说明 |
|---|---|---|
| P0 包络抽稀 | `host/filters.py`、`host/panel_capture.py` | 每个像素列画 `[min, max]` 竖线 + 中心折线；不再"每 12 点取 1 点"。抽稀比 ≥2 时才画竖线，缩小到点比像素少时自动退化成折线 |
| P1 可选平滑 | `host/filters.py`、抓包页「显示」下拉、`host/panel_wave.py` | 关 / 3 / 5 / 9 / 15 点，零相位；默认关；实时页与 XY 同步；只作用于"要画的那份"，触发检测仍用原始数据 |
| P1 缺块标黄 | `host/panel_capture.py` | `res.missing` 换算成样点区间，图上画琥珀色竖带，右上角标「缺块 N」，摘要同步提示 |
| P2 持久化 | `host/main_window.py`、`host/ui_prefs.py` | `ui_prefs.json` 的 `capture.smooth`，启动恢复、关窗保存 |
| P2 导出标注 | `host/capture.py` | PNG 标题追加「显示平滑 N 点（仅绘制，数据未改）」；CSV 首行写 `# 注释`；**导出的数值始终是原始 `res.s/res.c`** |
| P2 自检 | `host/selftest_filter.py`、`host/selftest_display.py` | filter 29 checks（恒等/长度守恒/不篡改输入/线性保持/中值去毛刺/降噪 ≥5 dB/包络含极值/性能）；display 10 checks（包络含尖峰、平滑不动原始数组、缺块区间换算、ui_prefs 往返） |
| 导出一致性 | `host/capture.py::to_png` | PNG 也用包络画（原来也是点采样），并显式给中文字体，避免标题变方框 |

### 11.2 实测（本机，28672 点）

| 操作 | 耗时 |
|---|---|
| 包络（1200 列） | 0.19 ms |
| SG 平滑 9 点 | 0.08 ms |
| 中值 9 点 | 3.42 ms |
| FIR 63 taps | 0.51 ms |

界面重绘约 0.5–4 ms，远低于 16 ms 帧预算；拖动窗口不会卡。

### 11.3 刻意没做的

- **没有**在采集/传输链路上滤波（会改数据、影响触发与测量）；
- **没有**引入 scipy（包体 +40 MB，且现有 numpy 实现已够快）；
- **没有**默认开启平滑（低通会削峰，示波器用途不能默认平滑）；
- **没有**把"滤波后数据"写进 NPY（格式固定为原始 int16 两列，避免下游误用）。

### 11.4 与"以太网和串口一样好看"的关系

见 §10：两条链路读同一块板上缓冲、用同一个 `CaptureResult`、同一段绘图代码，
所以 P0/P1 之后显示质量**结构性一致**；唯一变量是缺块，缺块已标黄并计入摘要。

# 资源预算与优化菜单（v62 交付位流，2026-10-27）

> **这份文档回答一个问题**：v62 的 LUT 82.01% / BRAM 46/50 到底是**谁**吃掉的，
> 想再加东西应该先动哪一块、能省多少、代价是什么。
>
> 数据来源：`tools/util_hier.tcl`（新增）—— 与出交付位流的 `_impl_v62.tcl` 同源文件、
> 同约束，唯一差别是 `-flatten_hierarchy none`（保留层次才能按模块统计）。
> 综合后 LUT 合计 **17,465**，交付位流实现后是 **17,059**（+2.4%，属正常），
> **模块之间的相对占比可信，绝对值引用时请带这句说明**。
> 复现：`powershell -File tools\run_vivado.ps1 -Tcl tools\util_hier.tcl`，
> 报告落在 `_hier_work/util_hier.rpt`。

## 3. 谁吃了 BRAM（46 块当量）

| 模块 | RAMB36 | RAMB18 | 当量 | 占比 |
|---|---|---|---|---|
| `u_enc/u_cap`（采集环 28,672×32 bit，三 bank） | **28** | 0 | **28** | **56%** |
| `u_disp`（字库 + 5 页文字层 + 波形环 + P7 三块） | 13 | 6 | 16 | 32% |
| `u_enc/u_eth`（RX 队列 + 流 FIFO + UDP FIFO） | 1 | 2 | 2 | 4% |

> **每个样点写 32 bit，但 AD9238 只有 12 bit**：`wr_din = {c_in, s_in}` 里的 `c_in/s_in` 是 12 bit 有符号扩展成的 16 bit，每一半都有 4 bit 纯冗余（pad），合计 8 bit/样点。
> **每个样点占 32 bit，而实际只用了 24 bit**（`c[31:16] | s[15:0]`，两个 12 bit 各占 16 bit）。

## 4. 优化菜单（按"省得多 / 风险低"排序）

| # | 动作 | 预期节省 | 风险 | 必须重跑的验证 |
|---|---|---|---|---|
| R1 | **采集样点 32→24 bit 重打包**（RAM 内只存 `{c[11:0], s[11:0]}`，读侧符号扩展回 16 bit） | **BRAM −8**（28→20） | **中低**：对外帧格式不变（仍是两个 16 bit 有符号），只有 RAM 内部宽度与读写各加一拍；但最差 setup 路径可能会挪位 | `tb_scope_banked` / `tb_scope_chain` / `tb_dump_start`；板上 448 块 dump + 82/82 UDP 抽检 |
| R2 | **采集深度 28,672→16,384**（`eth_top #(.DEPTH(...))` 已经是参数） | **BRAM −12** | 低（改参数），但窗口 1.147 ms → **0.655 ms** | 同上 + 报告 §10.5 与屏 P2 时间轴说明 |
| R3 | **`eth_reply` 模板改 ROM**（128×8 固定帧存 ROM，只算校验和，不再逐字节 case 拼装） | **LUT −600…−900** | 中高：碰 ARP/ICMP 协议 | `tb_icmp_reply` / `tb_eth_udp`；板上 ping 4/4 |
| R4 | **十进制格式化去重**（`val_format` / `pnl_calc` / `p7_view` 三处各有一套 div+补零） | **LUT −400…−600** | 中：要逐页比对版面 | `tb_val_format` / `run_sim_disp.py` 18 台 + 屏目视 |
| R5 | **CORDIC 19→17 级** | LUT −220（精度 2⁻¹⁷ rad ≈ 0.0004°） | 低，但动黄金模型口径 | `tb_cordic_atan2`；报告 §3 与 `model/` |
| R6 | **调试/桥接链路编进宏**（`uart_spi_bridge` 270 + `uart_scope` 117 + `scope_dump` 202） | LUT −400…−600 | 低（做"精简版"位流另出一份） | 精简位流不能 dump，需保留 v62 作为完整版 |
| R7 | **字库瘦身**（`font_rom` 16 bit + 30 bit 两套 = 4 块） | BRAM −1…−2 | 中：字形要重渲 | 屏五页目视 |
| R8 | **P7 三块 RAM 合一块**（32+16+16 bit 分时） | BRAM −1 | 中 | `tb_disp_v58` + P7 目视 |

**组合建议**（目标"给新功能腾地方"）：

- 只要 **LUT**：R3 + R4 + R5 ≈ **−1,200…−1,700 LUT**（→ 72–76%），不动 BRAM。
- 只要 **BRAM**：R1 + R2 ≈ **−20 块**（46→26，占 52%），代价是窗口与帧格式。
- 想塞 **ILA**（约 1–2k LUT + 若干 BRAM）：R3+R4+R5 之后 BRAM 仍需 R1；或干脆继续用 v12 的独立 ILA 位流（现在就是这么做的）。
- 想加**第二轴编码器**（v12 单机 6,298 LUT）：**现有优化全部做完也不够**，必须砍显示（−5k）或换更大器件。

## 5. 建议的时机与做法

1. **11-04 之前不要动 v62 的 RTL**。它已经在板验收（ping / 448 块 dump / 30 min 99.74%），
   任何资源优化都要重跑 47 台回归 + 时序 + 上板抽检，风险与收益不成比例。
2. 如果新功能**是评分必需**：开一个 `opt/` 分支，只做 R5+R4（低风险 LUT），
   保留 v62 位流作为兜底；上板只做"抽检四件"（ping、dump、屏翻页、连续流 2 min）。
3. 如果新功能**不是必需**：把本文件当赛后路线图，按 R1→R3→R2 顺序做，
   每做一项就更新 `deliverables/data/v62/` 的签核件与 `evidence_index.md`。

# 上位机以太网通道使用指南

> 适用版本：v61 位流（2026-10-22 之后的所有构建）＋ 本轮上位机（带「网络自检 / 使用指南」按钮）。
> 抓包页右上角的「使用指南」按钮会直接打开这份文件。

---

## 0. 一分钟版

1. **网线直连**：板子 RJ45 ↔ PC 网口（千兆），PC 网口设 `192.168.1.100 / 255.255.255.0`。
2. **串口照旧连上**（COMx，2 Mbaud）。以太网只负责传数据，**配置和寄存器仍然走串口**。
3. 打开「抓包」页 → **通道** 选「网口 UDP」或「网口连续流」。
4. 点 **「网络自检」**：出现 `ping 通 ｜ ARP ✓ ｜ ICMP ✓ ｜ 主机 MAC ✓` 就说明链路 OK。
5. 点 **「抓一次」**（连续流模式下按钮会变成「停止连续流」，再点一次停止）。

---

## 1. 接线与网络

| 项目 | 值 | 说明 |
|---|---|---|
| 板子 IP | `192.168.1.10` | 固定，不可 DHCP |
| 板子 MAC | `02:00:00:00:00:01` | |
| PC 网口 IP | `192.168.1.100/24` | 建议只给这一个 IPv4，别开自动跃点 |
| 速率 | 1000 Mbps 全双工 | 百兆会大面积丢包，先看 `Get-NetAdapter` 的 LinkSpeed |
| UDP 端口 | 默认 `5000`，被占用自动顺延 | 见 §4 |

> **WLAN 也在 192.168.1.x 时**：Windows 可能把回包从 WLAN 送出去，表现为「自检 ping 不通、但网线是好的」。
> 处理：关掉 WLAN，或把 WLAN 换到别的网段（例如 192.168.31.x）。

---

## 2. 三种通道怎么选

| 通道 | 数据路径 | 一次传输量 | 耗时 | 适合 |
|---|---|---|---|---|
| **串口回读**（默认） | UART 2 Mbaud | 28672 点 / 448 块 | ≈0.66 s | 不接网线、只想快速看波形 |
| **网口 UDP** | 千兆 UDP，82 个包 | 28672 点整窗 | ≈2 ms | 要快照、要连续抓多次 |
| **网口连续流** | 千兆 UDP，设备不停发 | 滚动最近 1024 点 | 实时 | 看长过程、调参、观察漂移 |

三种通道抓到的都是**同一块板上缓冲**，数据格式一致，导出的 CSV/NPY/PNG 完全一样。

## 3. 切换步骤（GUI）

1. 顶部选串口 → **连接**（状态栏出现设备信息即成功）。
2. 进「抓包」页，参数行：**源**（原始 50 MSPS / 校正 12.5 MSPS）、**抽取**、**点数**。
3. **通道**下拉：
   - 选「网口 UDP」或「网口连续流」后，下面会出现网络状态行。
4. 点 **「网络自检」**，等 1–2 s：
   ```
   网口 192.168.1.10 ｜ ARP ✓ ｜ ICMP ✓ ｜ 主机 MAC ✓ ｜ UDP 端口 47234 ｜ ping 通
   ```
5. **显示**（可选）：参数行最右的下拉，`关 / 3 / 5 / 9 / 15 点`。
   - 只影响**画面**，不改导出数据；默认「关」。
   - 原始信号噪声大时可以选 5/9 点；要量峰峰值就保持「关」。
6. 点 **「抓一次」**：
   - 网口 UDP：约 2 ms 收完，摘要显示 `缺块 0`；
   - 网口连续流：按钮变 **「停止连续流」**，界面每 300 ms 刷新最近 1024 点，摘要显示
     `已收 N 包（x.xx MSPS）｜丢 M 点`。
7. 连续流再点一次按钮停止；停止后设备端也会 `stream_stop`，不会一直占带宽。
   关闭软件时若流还开着，会先自动停流再退出。

> 图上出现**琥珀色竖带** = 那一段数据没收到（补 0），右上角会标「缺块 N」，
> 摘要也会提示。出现带状区域就按 §6 的 `缺块` 一行处理。

## 4. 端口是怎么选的（不用你操心）

- 默认从 **5000** 开始；如果本机 5000 被占用（常见：Vivado 许可证服务 `lkcitdl`），
  自动顺延到 5001…5020 里第一个能绑的端口。
- 选中的端口会写进板子寄存器 `0x070C`，**每次重新烧写后都会复位回 5000**，
  所以软件每次开抓/开流都会重写一遍。
- 想强制起始端口：设环境变量 `FPGA_UDP_PORT`（例如 `set FPGA_UDP_PORT=6000`）。
- 想只监听某块网卡：设 `FPGA_UDP_BIND_IP=192.168.1.100`（默认监听全部）。

## 5. 刚烧写完 / 刚上电的注意事项

| 现象 | 原因 | 软件已做的兜底 |
|---|---|---|
| 第一次 UDP 抓包固定少 40 多块 | 板子 `host_mac=0`，UDP 目的 MAC 全 0，网卡丢包 | 抓前自动 ping 一次（等 `0x0710 bit2`），缺块再自动重试一次 |
| ping 第一次 `General failure` | PC 的 ARP 表还是空的 | 再 ping 一次即可；「网络自检」本身就会先 ping |
| 连续流一包收不到 | 端口没写对 / 被占用 / 目的 MAC 全 0 | 开流前按 §4 选端口 + 学 MAC，顺序已修正 |

## 6. 常见问题

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 自检 `ping 不通` | 网线没插好、PC IP 不对、WLAN 抢路由、防火墙拦 ICMP | 看 LinkSpeed 是否 1 Gbps；临时关 WLAN；确认 PC 是 192.168.1.100 |
| 自检 `ARP ✗` | 板子没收到 ARP（不在同网段/网线断） | `arp -d 192.168.1.10` 后再自检 |
| 自检 `主机 MAC ✗` | 板子还没收到过发给它的包 | 多 ping 几次；确认 PC 网口就是抓包用的那块 |
| UDP 抓包 `缺块 40+` | 首次抓包、端口冲突、网卡节能 | 再抓一次；设备管理器里关网卡「节能/绿色以太网」 |
| UDP 抓包 `缺块 1–3` | 偶发丢包 | 允许范围内（软件会标注位置，补 0） |
| 连续流 `0 包` | 端口/目的 MAC/百兆 | 先做网络自检；确认 1000 Mbps |
| 连续流速率低、丢点很多 | 画图占住 GIL，收包线程被饿死 | 已内置 64 MB 接收缓冲 + 300 ms/1024 点刷新（丢点 <0.02%）；仍高就关掉其它抓包工具、换 PCIe 网卡 |
| 串口 dump 超时 | 桥正忙（遥测行边界） | 重试一次；`tools/board_dump_test.py` 已内置降级提示 |
| 波形有毛刺、看着"脏" | 真实噪声 + 每像素抽稀 | 先用「显示」= 9 点平滑看趋势；**不要**用它替代测量（峰峰值仍按原始数据） |
| 波形太密看不清细节 | 28672 点压进约 1100 像素 | 缩小「点数」或加大「抽取」；包络已保证尖峰不会丢 |
| 图上出现黄色竖带 | 该段没收到（丢块/丢包，补 0） | 见上表 `缺块` 两行；黄色带位置就是缺失位置 |

## 7. 命令行等价操作

```bat
:: 串口回读（不依赖网络）
python tools\cap_dump.py --port COM6 --len 28672 --out cap.npy

:: 网口 UDP 抓包（端口按 §4 实际值填）
python tools\cap_dump.py --udp --udp-port 47234 --len 28672 --out cap_udp.npy

:: 网络体检 + 抓一次 + 校验点数和 npy
python tools\board_eth_check.py --port COM6 --out cap_check.npy

:: 串口 dump 到文件（448 块，主机端校验块 XOR）
python tools\board_dump_test.py --port COM6

:: 连续流长稳（默认 30 s，>95% 判 PASS）
python tools\stream_longrun.py --com COM6 --dur 30

:: 上位机整条链路冒烟（自检 → UDP 抓包 → 连续流开关，全自动）
python tools\gui_eth_smoke.py --port COM6
```

## 8. 寄存器速查（以太网相关）

| 地址 | 名称 | 说明 |
|---|---|---|
| `0x0700/02` | MAC 低/高 | `02:00:00:00:00:01` |
| `0x0704/06` | 本机 IP 低/高 16 位 | `192.168.1.10` = 0xC0A8010A |
| `0x0708/0A` | 主机 IP 低/高 | `192.168.1.100` |
| `0x070C` | UDP 目的端口 | 复位 5000，软件每轮重写 |
| `0x070E` | 源端口 | 5000 |
| `0x0710` | 链路状态 | bit0 ARP、bit1 ICMP、bit2 已学主机 MAC |
| `0x0712/16` | 发送/接收包计数 | |
| `0x071A` | 抓包深度 | 28672 |
| `0x072E` | dump 控制 | bit0 启动、bit1 中止 |
| `0x0730/32/34` | dump 状态/长度/块数 | 448 块完成时 `0x0734=0x01C0` |
| `0x0740/42` | 连续流使能/抽取 | 抽取 ×4 = 12.5 MSPS |
| `0x0744` | 流状态 | bit0 en、bit1 run |
| `0x0746/48` | 已发包数 | |
| `0x074A/4C` | 丢样点 | |
| `0x0750…` | RX 诊断计数/延时 | 链路排查用 |
| `0x0760…` | 发送侧字节快照 | 帧长/IP 长/端口/MAC/校验和 |

完整定义见 `rtl/SPEC_interface_contract.md` 的 v1.5 / v1.6 章节。

## 9. 已知限制

- 显示平滑是**零相位**的（不搬移相位），但会削峰：测峰值/过冲请把「显示」调回「关」。
- 导出（CSV/NPY/PNG 数值）永远是**原始样点**，平滑只作用于屏幕；PNG 与 CSV 会标注平滑档位。
- 连续流是"最近 1024 点"的滚动窗，不是整段缓存；要整窗曲线用「网口 UDP」或串口。

- 只支持 **1000 Mbps** 全双工，无 MDIO（读不到 PHY 寄存器、不能强制自协商）。
- 抓包深度固定 **28672 点**（≈1.15 ms @25 MSPS）；要更长窗口用抽取（×2/×4/×8）。
- RGMII RX 输入延时是经验值（2.3 / 1.7 ns，对应 YT8531C 内部延时），换板/换 PHY 需重调。
- 连续流的上限约 **12.5 MSPS**（×4 抽取），再快会顶爆千兆。

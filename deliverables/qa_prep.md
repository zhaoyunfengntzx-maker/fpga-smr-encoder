## Q1 为什么不用 iC-TW28 / TW29 这类专用细分芯片？

一句话：**专用芯片把分辨率、算法和接口都锁死了；我们用一片 FPGA 把这三件事都打开。**

- TW28：分辨率固定 **10 bit**（0.3516°/LSB），内部算法不可见不可改，串行口只有 SPI 与 Encoder Link 两种；
  我们：增量 **16 bit / 65,536**（量化步长 0.0055°），算法全在 RTL 里（六参数校正 + CORDIC + PI 环路），
  **ABZ / UVW / SPI / UART 四路输出**（另有 UART 遥测与千兆以太网抓窗）。
- 代价：TW28 延迟 1.5 µs 是硬件固定；我们的延迟是**设计值约 830 ns**（逐级相加 41.5 拍 @50 MHz），
  但**尚未实测**（R6），报告里标 `[设计值]`。
- 证据：报告 §1 需求、§4.3 延迟预算表、摘要「核心数字」表。

## Q2 精度到底多少？板上测的还是仿真的？

一句话：**两条口径分开说 —— 模型 1273×，板上几何 176×，板级跟踪残差 0.009° RMS。**

| 口径 | 数字 | 类别 |
|---|---|---|
| 复合畸变下的电角度误差（黄金模型 + 仿真） | 20.9839° → 0.0165°，**1273×** | `[仿真]` |
| 板上圆度 RMS（注入失真 → 一键标定） | 17.786% → 0.101%，**≈176×** | `[实测]` |
| 板级角度跟踪残差 | **0.009° RMS**（v7 自由运行窗口） | `[实测]` |
| 标定重复性 | 12/12 GOOD（另一次 20/20） | `[实测]` |

- 为什么两个数差这么多：1273× 是"同样的复合误差在理想模型里能被算法压掉多少"，
  176× 是"板上真实链路（ADC 量化、时钟抖动、信号源失真）剩下的还能压掉多少"，**不是同一个东西，不混用**。
- 证据：报告 §6.4 李萨如表、`figures/lissajous_{before,after}_distortion.png`、`data/lissajous_*.csv`。

## Q3 延迟为什么没实测？

一句话：**要示波器同屏测"模拟输入过零 → 数字输出跳变"，10-29 上板日做；现在只有预算。**

- 预算 **≈830 ns** = 41.5 拍 @50 MHz（ADC 内部 7 拍 + 捕获 3 + 抽取 2 + 校正 3 + CORDIC 19 + 环路 3 + ABZ 3 + 输出 1.5）。
- 其中 ADC 的 **7 拍流水线延迟在 AD9238 手册里查不到**（`docs/AD9238_module_digest.md:179` 明确"not found in document"），
  是按架构估的工程值 —— 这一点我们在报告里主动交代了，因为它会让"830 ns"偏乐观。
- 证据：报告 §4.3、§7 R6；`docs/AD9238_module_digest.md`。

## Q4 你们测的是信号发生器，不是真传感器，怎么证明能用？

一句话：**定量标定必须用已知误差的激励；真实传感头的画面 10-29 补拍，但结论不依赖它。**

- 用信号源的**唯一理由**：只有信号源能注入**已知**的偏置（±3000 LSB）、增益失配（1.25×）、正交误差（3°/5°），
  才能验证"标定确实把已知误差压到 0.1%"，否则只是"看起来圆"。
- 真实传感头的验证是另一件事：接线、磁环偏心、温漂 —— 我们在报告 §5.2 与 §7 R7 里**如实标"未接入"**，
  并把它列为答辩前必补项（`photo_shot_list.md` P2-6）。
- 证据：报告 §5.2、§7 R7；`photo_shot_list.md` P2-6。

## Q5 资源用了 82%，时序余量还剩多少？还能加东西吗？

一句话：**能跑，但没余量了 —— LUT 82.01%、BRAM 46/50、WNS +0.471 ns、WHS 只有 +0.042 ns。**

- LUT **17,059 / 20,800 = 82.01%**；FF 11,193 = 26.91%；BRAM **46 / 50 = 92.00%**；DSP 18；IOB 107。
- WNS **+0.471 ns**（33,255 端点，0 失败）；WHS **+0.042 ns**（hold 很薄，靠 cordic 的短路径撑着）。
- 所以：**再加 ILA 或深存储就放不下**（报告 §7 R12）。调试必须烧单独 ILA 位流（v12 版 1,428,064 B），不能塞进交付位流。
- **转台版怎么塞进去的**（v66，`[构建签核]`）：v62 的 BRAM 已 46/50，四个新模块装不下 ⇒ **同一个 RTL 出两个位流**
  （RTL 只差一个 `ENC_DISP_TAP` 宏）：生产版（无屏无网）**LUT 10,916 = 52.48%、BRAM 32/50、WNS +0.186 / 0 失败（24,630 端点）**；
  显示调试版 **LUT 17,435 = 83.82%、BRAM 48/50 = 96%、WNS +0.229 / 0 失败（34,303 端点）**。两个都没上板（§7 R14）；**到 v74 生产位流已上板复验（WNS +0.409）、显示位流仍待目视**。
- 证据：`data/v62/impl_util.rpt`、`impl_timing.rpt`、`impl_hold_paths.rpt`；v66 见 `data/v66/prod_util.rpt`、`prod_timing.rpt`、`disp_util.rpt`。

## Q6 屏和千兆网同时跑会不会互相干扰？

一句话：**各自都单独验收过，同时跑 10-29 验（报告里标"待补"，没假装验过）。**

- 已验：屏五页在 v58/v59 独立位流上 18/18 回归 + RTL 常量级版面；以太网在 v62 上 ping 4/4、UDP 82/82、连续流 10/30 min。
- 未验：**屏刷新的同时跑连续流**、**触摸翻页的同时抓包**（R13）。
- 风险在哪：屏和网共用 `sys_clk` 域与 BRAM（屏的波形 RAM 与采集环形缓冲是分开的，但都吃 BRAM），
  最坏情况是屏刷新拉长以太网帧间隔 —— 所以 10-29 的验收单里专门有一条"屏停在 P2 时抓一枪包，屏不花不闪"。
- 证据：报告 §7 R13、`deliverables/board_day_checklist.md` §2。

## Q7 连续流 99.74%，那 0.26% 丢在哪？

一句话：**丢在 PC 侧接收（端到端），板端环形缓冲覆盖只有 0.0002%，两者不是一回事。**

- 30 min、dec=3（6.25 MSPS）：板端发 **56,251,240** 包，主机收 56,102,291 ⇒ 端到端 **99.74%**。
- 板端 `lost` 是**环形缓冲被覆盖的样点数**（1 M 点环跑 30 分钟必然绕圈），**不是传输丢失**。
- 为什么满速会掉：12.5 MSPS × 200 点/包 ≈ **688 Mbps**，1GbE 理论 1000 Mbps，扣掉以太网头/帧间隔后基本吃满 ⇒ 这是设计边界，不是 bug。
- 旁证：连续流跑起来时 ping 会掉（满速约 1/3、dec=3 17/20），停流立刻恢复 ⇒ 验收顺序规定"ping/自检一律停流做"。
- 证据：报告 §10.6.4 已知边界、`docs/DEV_STATUS.md` §13.5/§13.6。

## Q8 输入频率能到多少？

一句话：**ABZ 边沿率上限 12.5 MHz；输入 1 kHz–500 kHz 六点都测了，500 kHz 只作带宽边界证据。**

- 六点（1k/10k/50k/100k/200k/500k）圆度 0.093%–0.211%，跨两个数量级只劣化 1.5×。
- 500 kHz × 4×32 = **64 MHz** 已远超 12.5 MHz 边沿率上限 ⇒ 那一点说明"算法在极限下仍不崩"，不能说"支持 500 kHz"。
- 证据：报告 §6.3 六点表、`data/freq_ladder_summary.csv`、`figures/freq_*.png`。

## Q9 和市面上的方案比，创新点到底是什么？

一句话：**不是"做了个编码器"，而是"把专用 SoC 的三件事拆开、全部可改、并给出可复核的证据链"。**

- ① 算法可换：六参数闭式标定 + 可注入误差的验证路径（176×）；
- ② 接口可换：ABZ/UVW/SPI/UART 四路，串行口可由 UART→SPI 桥或千兆以太网直接回读；
- ③ 自带仪表：5 页触摸 UI（波形/时序/设置/标定），不接电脑也能判断"传感器坏还是板子坏"；
- ④ 数据可搬：千兆网 28,672 点原始波形 **0.06 s**（串口要 0.65 s）；
- ⑤ 证据可复核：**54 台**回归（sim 36 + disp 18）、DRC 0 Error、两个版本的签核件 + SHA256 清单（**259 行**，逐行复核通过）。
- ⑥ 硬件无关的可移植性：v66 把周期数参数化（2500→2048 周期/转只是改 `POLE_BITS`），同一套 RTL 同时适配信号源与转台。
- 证据：报告 §8 创新点（每条一句话 + 一个数字）。

## Q10 为什么不做 DDR3 深存储 / 更多轴？

一句话：**时间与资源都到边界了，我们选择了"能交付的完整链路"而不是"半条更长的链路"。**

- DDR3 自检顶层已经跑通（修了 5 个根因：`sys_rst` 低有效、`wr_en` 握手、`app_addr` 字节地址、UI 读后写可见性、`S_FLSH` 4 ms），
  但**没接进生产工程**：BRAM 只剩 4 块，接 DDR3 要改采集侧仲裁与时序收敛，风险大于收益（报告 §7 R12、`docs/18`）。
- 后果：连续流窗口是 **28,672 点 ≈ 1.147 ms @25 MSPS**（滚动窗），不是 2.56 s 深存储。
- 多轴：架构上 `enc_top` 可例化多份（单份 30.28% LUT），但本轮只做单轴 + 上位机多通道显示。
- 证据：报告 §10.5、§7 R12；`docs/18_streaming_ddr_plan.md` §4.8。

## Q11 你们做的是编码器，怎么又去适配转台了？

一句话：**同一个 RTL 换一个真实传感器 —— 这才是"能不能替代专用芯片"的证明题，不是加分题。**

- 转台侧的基线（`改进需求.docx`、`docs/27` §0.5）：**2048 周期/转**、每腿对地 **0.5 Vpp**、经差分转单端模块
  **G=8** 放大到约 **8 Vpp**（ADC 侧约 **1638 码**），转速上去后电信号频率到 **50 kHz** 并随转速波动；
  目标是**机械 ±1″ 峰峰**。设计按 **200 kHz（5859 rpm）** 留余量。
- 这一版（v63–v66）加的四件事，都是信号源不会暴露的问题：
  ① **延迟前馈**（不降延迟而是把 ω·T 补掉：3000 rpm 约 26.5° 电角 ≈ **46″**，默认 `TAU_Q8=2304`=720 ns，1 个 DSP48）；
  ② **三态锁定状态机**（把"还没锁 / 毛刺 / 真丢线"分开，12,500-2,500-12,500 样本滞回，W1C 粘滞）；
  ③ **分块积分偏置跟踪**（2.62 ms 窗口，避免 EMA 成反馈环；默认关）；
  ④ **4096×16 全周补偿表**（1 LSB = 0.0097″，默认旁路 —— 没有 ±0.5″ 外部基准就不开）。
- 为什么 1″ 难在别处：2048 周期/转时，机械 1″ 只对应 **0.568° 电角 = 103 LSB**，细分位数有两个数量级余量；
  真正的敌人是**刻度与偏心、相位滞后、温漂、诊断**。
- 老实说：**v66 两个位流当时都没上板**；到 **v74 生产位流已上板复验**、显示位流仍待目视（§7 R14）。上板清单是 `docs/28` 七步；所以这条答"设计已就绪、闸门已建"，
  不答"已经做到"。
- 证据：报告 §11（11.1–11.13）、`data/v66/`、`docs/28`、`host/lut_tool.py`。

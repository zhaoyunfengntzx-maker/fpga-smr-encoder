## Q1 为什么不用一颗专用细分芯片？

一句话：**专用芯片把分辨率、算法和接口都锁死了；我们用一片 FPGA 把这三件事都打开。**

- 市售专用细分芯片：分辨率固定 **10 bit**（0.3516°/LSB），内部算法不可见不可改，串口通常只有一两种固定格式；
  我们：增量 **16 bit / 65,536**（量化步长 0.0055° 电角），算法全在 RTL 里（六参数闭式校正 + 17 级 CORDIC + PI 环路），
  **ABZ / UVW / SPI / UART / 1 GbE 五路输出**并行，参数全部运行期寄存器可配。
- 代价：专用芯片的延迟是硬件固定的，我们的延迟是**设计值 ≈830 ns**（41.5 拍 @50 MHz），
  且**尚未实测**（R6），报告里标 `[设计值]`。
- 证据：报告 §1 需求、§4.3 延迟预算表、`topic_proposal.md` §2–§3。

## Q2 精度到底多少？板上测的还是仿真的？

一句话：**三件事分开说 —— 模型 1273×、板级内部一致性 RMS 0.71°、没有外部角度基准。**

| 口径 | 数字 | 类别 |
|---|---|---|
| 复合畸变下的电角度误差（黄金模型 + 仿真） | 20.9839° → 0.0165°，**1273×** | `[仿真]` |
| 板级角度内部一致性（`angle_vs_sc`，上位机脚本） | offset **1.76°** / RMS **0.71°** / max **2.88°**、\|err\|>5° 占 **0.03%** | `[实测]` |
| 板上圆度 RMS（注入已知失真 → 一键标定） | 17.786% → 0.101%，**≈176×** | `[实测]` |
| 标定重复性 | 20 轮 20/20 一致、参数幂等 | `[实测]` |

- 为什么三个数差这么多：1273× 是"同样的复合误差在理想模型里能被算法压掉多少"；176× 是"板上真实链路（ADC 量化、时钟抖动、信号源失真）剩下的还能压掉多少"；
  `angle_vs_sc` 的 0.71° RMS 是**内部一致性**（同一时刻角度通道 vs 软件重算），**没有外部角度基准，不作绝对精度主张**（R15）。
- 早期曾报过 **0.009° RMS**：那是 v7 自由运行窗口、单点工况、没有外部基准的测量，**属旧口径，不再作为当前值**，报告里保留但标了版本与条件。
- 证据：报告 §6.4 李萨如表、§11、`figures/lissajous_{before,after}_distortion.png`、`_boardtest/angle_vs_sc.py`、`data/v90/prod_util.rpt`。

## Q3 延迟为什么没实测？

一句话：**要示波器同屏测"模拟输入过零 → 数字输出跳变"，本轮没做；现在只有预算。**

- 预算 **≈830 ns** = 41.5 拍 @50 MHz（ADC 内部 7 拍 + 捕获 3 + 抽取 2 + 校正 3 + CORDIC 19 + 环路 3 + ABZ 3 + 输出 1.5）。
- 其中 ADC 的 **7 拍流水线延迟在 AD9238 手册里查不到**（`docs/AD9238_module_digest.md:179` 明确"not found in document"），
  是按架构估的工程值 —— 这一点报告里主动交代了，因为它会让"830 ns"偏乐观。
- 证据：报告 §4.3、§7 R6；`docs/AD9238_module_digest.md`。

## Q4 你们测的是信号发生器，不是真传感器，怎么证明能用？

一句话：**定量标定必须用已知误差的激励；真实传感头已经接上转台跑闭环，但只有一台。**

- 用信号源的**唯一理由**：只有信号源能注入**已知**的偏置（±3000 LSB）、增益失配（1.25×）、正交误差（3°/5°），
  才能验证"标定确实把已知误差压到 0.1%"，否则只是"看起来圆"。
- 真机侧：v90 在 **2048 周期/转**磁环上跑通闭环（Z 7.62/7.65 Hz ⇒ 457–459 rpm、UVW 六态计数均衡、60 s 长跑不丢帧），
  但**只有这一台传感头与这一台转台**，异型号/异极对数的通用性仍缺证据（R7 收窄为"只有一台"）。
- 证据：报告 §5.2、§11.14；`_boardtest/z_rate.py`、`_boardtest/check_v70.py`、`docs/39`。

## Q5 资源用了多少？时序余量还剩多少？还能加东西吗？

一句话：**生产版还有余量（52.78% LUT / 32 BRAM），显示版已经顶到边（82.16% LUT / BRAM 91%）。**

| | 生产 `enc_top_v90.bit` | 显示 `enc_top_disp_v90.bit` |
|---|---|---|
| LUT | **10,978 = 52.78%** | **17,090 = 82.16%** |
| FF | 8,724 = 20.97% | 11,601 |
| BRAM | **32 / 50 = 64%** | **45.5 / 50 = 91%** |
| DSP | 17 | 20 |
| WNS | **+0.199 ns**（24,691 端点，0 失败） | **+0.221 ns**（33,365 端点，0 失败） |
| WHS | +0.017 ns | +0.049 ns |

- 生产版还能再容纳约 18 块 BRAM 的新功能；**显示版没有余量**：再想加表/缓存必须先删东西。
- 调试一律用**单独的 ILA 位流**（`_synth_work/enc_top_ila.bit`），不塞进交付位流。
- 构建命令就在仓库里：生产 `tools/impl_check_v90.tcl`、显示 `tools/impl_check_disp_v90.tcl`（带 `-verilog_define {ENC_DISP_TAP ENC_V69_CPR2048}`）；
  报告产物 `deliverables/data/v90/prod_*.rpt` / `disp_*.rpt`。
- 证据：`data/v90/prod_util.rpt`、`prod_timing.rpt`、`prod_hold_paths.rpt`、`disp_util.rpt`、`docs/39` §0。

## Q6 屏和千兆网同时跑会不会互相干扰？

一句话：**各自都单独验收过（v90：ping 4/4、UDP 28,672 点抓窗），同时满速长跑没验（R13）。**

- 已验：v90 显示位流的四页（P1 总览 / P2 输入波形 + 预触发缓冲 + AUTO 时基 / P4 逻辑时序 / P6 设置）在板上可导航、触摸翻页可用；`angle_vs_sc` 由上位机脚本算，与屏幕无关；
  以太网在 v90 上 `ping` 4/4、UDP 抓窗 **28,672 点 @50 MSPS** 通过。
- 未验：**屏刷新的同时跑连续流**、**触摸翻页的同时抓包**。
- 风险在哪：屏与网共用 `sys_clk` 域与 BRAM（波形 RAM 与采集环形缓冲分开，但都吃 BRAM），
  最坏情况是屏刷新拉长以太网帧间隔 —— 所以验收单里专门有一条"屏停在 P2 时抓一枪包，屏不花不闪"。
- 证据：报告 §7 R13、`deliverables/board_day_checklist.md`。

## Q7 以太网连续流丢不丢包？

一句话：**v62 期做过 30 min 连续流（99.74%），v90 只做到 ping + 抓窗；0.26% 丢在 PC 侧接收，不是板端。**

- 30 min、dec=3（6.25 MSPS）：板端发 **56,251,240** 包，主机收 56,102,291 ⇒ 端到端 **99.74%**（`[实测]`，v62 期口径）。
- 板端 `lost` 是**环形缓冲被覆盖的样点数**（1 M 点环跑 30 分钟必然绕圈），**不是传输丢失**。
- 为什么满速会掉：12.5 MSPS × 200 点/包 ≈ **688 Mbps**，1GbE 理论 1000 Mbps，扣掉以太网头/帧间隔后基本吃满 ⇒ 这是设计边界，不是 bug。
- 旁证：连续流跑起来时 ping 会掉（满速约 1/3、dec=3 17/20），停流立刻恢复 ⇒ 验收顺序规定"ping/自检一律停流做"。
- v90 的诚实边界：以太网只做了 ping 与 28,672 点抓窗，**没有重跑 30 min 长跑**（R17 标"抓窗已过、长跑未复验"）。
- 证据：报告 §10.6.4、`docs/DEV_STATUS.md` §13.5/§13.6。

## Q8 输入频率能到多少？

一句话：**ABZ 边沿率上限 12.5 MHz；输入 1 kHz–500 kHz 六点都测过（v62/v66 期口径），500 kHz 只作带宽边界证据。**

- 六点（1k/10k/50k/100k/200k/500k）圆度 0.093%–0.211%，跨两个数量级只劣化 1.5×。
- 500 kHz × 4×32 = **64 MHz** 已远超 12.5 MHz 边沿率上限 ⇒ 那一点说明"算法在极限下仍不崩"，不能说"支持 500 kHz"。
- 真机工况是 2048 周期/转、Z 7.62/7.65 Hz（457–459 rpm），电信号频率约 15.6 kHz，离上限很远。
- 证据：报告 §6.3 六点表、`data/freq_ladder_summary.csv`、`figures/freq_*.png`。

## Q9 和市面上的方案比，创新点到底是什么？

一句话：**不是"做了个编码器"，而是"把细分全信号链拆开、每一级可改、并给出可复核的证据链"。**

- ① 算法可换：六参数闭式标定 + 可注入误差的验证路径（176×）；
- ② 接口可换：ABZ/UVW/SPI/UART/1 GbE 五路，串行口可由 UART→SPI 桥或以太网直接回读；
- ③ 自带仪表：触摸 UI（波形/预触发/精度自检/设置），不接电脑也能判断"传感头坏还是板子坏"；
- ④ 数据可搬：以太网 28,672 点原始波形抓窗（UDP @50 MSPS）；
- ⑤ 证据可复核：**57 台**回归（`sim/` 37 + `disp/` 20）、DRC 0 Error、双位流签核件 + **323 条 SHA-256** 清单；
- ⑥ 硬件无关的可移植性：周期数参数化（2500→2048 周期/转只是改 `POLE_BITS`），同一套 RTL 同时适配信号源与转台；
- ⑦ 缺陷根治而非掩盖：Z 喘振用 45° 布防窗在 RTL 层解决（v90），UVW 回绕、多圈符号扩展、捕获窗相位余量都是"定位根因 + A/B/A 复验"。
- 证据：报告 §8 创新点（每条一句话 + 一个数字）。

## Q10 为什么不做 DDR3 深存储 / 更多轴？

一句话：**时间与资源都到边界了，我们选择了"能交付的完整链路"而不是"半条更长的链路"。**

- DDR3 自检顶层已经跑通（修了 5 个根因：`sys_rst` 低有效、`wr_en` 握手、`app_addr` 字节地址、UI 读后写可见性、`S_FLSH` 4 ms），
  但**没接进生产工程**：显示位流 BRAM 已 45.5/50，接 DDR3 要改采集侧仲裁与时序收敛，风险大于收益（报告 §7 R12、`docs/18`）。
- 后果：抓窗是 **28,672 点 ≈ 0.57 ms @50 MSPS**（滚动窗），不是 2.56 s 深存储。
- 多轴：架构上 `enc_top` 可例化多份（生产版单份 52.78% LUT、32 BRAM），但本轮只做单轴 + 上位机多通道显示。
- 证据：报告 §10.5、§7 R12；`docs/18_streaming_ddr_plan.md`。

## Q11 你们做的是编码器，怎么又去适配转台了？

一句话：**同一个 RTL 换一个真实传感器 —— 这才是"能不能用"的证明题，不是加分题。**

- 转台侧的基线（`docs/27` §0.5）：**2048 周期/转**、每腿对地 **0.5 Vpp**、经差分转单端模块 **G=8** 放大到约 **8 Vpp**（ADC 侧约 **1638 码**），
  电信号频率到 **≈15.6 kHz**；目标是**机械 ±1″ 峰峰**。设计按 **200 kHz** 留余量。
- v63–v74 加的四件事，都是信号源不会暴露的问题：
  ① **延迟前馈**（不降延迟而是把 ω·T 补掉：3000 rpm 约 26.5° 电角 ≈ **46″**，默认 `TAU_Q8=2304`=720 ns，1 个 DSP48）；
  ② **三态锁定状态机**（把"还没锁 / 毛刺 / 真丢线"分开，滞回 + W1C 粘滞）；
  ③ **分块积分偏置跟踪**（2.62 ms 窗口，避免 EMA 成反馈环；默认关）；
  ④ **4096×16 全周补偿表**（1 LSB = 0.0097″，默认旁路 —— 没有 ±0.5″ 外部基准就不开）。
- v90 修的是真机上唯一还在抖的东西：**停位 Z 喘振**。旧版停位时会吐出多个 Z；v90 的 `z_index_gen` 出 Z 后撤防、
  离开 ≥1/8 圈才重新布防，板上实测**严格每转 1 个 Z**（Z 7.62/7.65 Hz）。
- 老实说：**转速只认 Z 频率**。`check_v70.py` 里那栏"机械转速"是按 `cycle_cnt` 步进推的，10 kHz 遥测对上 >10 kHz 电信号会混叠，
  屏上/脚本曾出现的 **621 rpm** 就是混叠伪值，**不得引用**；权威判据是 `_boardtest/z_rate.py`。
- 证据：报告 §11（11.1–11.14）、`data/v66/`、`data/v70/`、`docs/28`、`docs/39`、`host/lut_tool.py`。

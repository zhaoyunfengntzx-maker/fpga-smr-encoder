## 2. 片子怎么走

**一条线**：磁环 → 传感头 → 差分转单端 → SMA → AD9238 → FPGA → 五路输出 → 屏 / 上位机。
镜头**沿着线走**，不来回跳场景。

**三处必须讲清楚**：
1. **静止到转动**：角度不变时是两条稳定电压；转起来才变成两路正弦余弦（S2→S3）。
2. **模拟到数字**：差分、单端、同轴、采样，四步把模拟量交给 FPGA（S4）。
3. **一个角度到五路输出**：算法把一对正余弦，变成角度、增量、换向、遥测、波形（S5→S6）。

**最后一句话**：这一整套过去要一颗专用细分芯片加一堆外设，现在装进一颗 FPGA（S9）——不是换成更贵的一颗，而是把整条链拆开自己做。

## 5. 算法段怎么讲、怎么可视化

### 5.1 六步，一句话一步

```
正余弦 ──①对齐──②降噪──③标定──④反正切──⑤跟踪+计数──⑥编码──> 五路输出
         12bit    12.5M   椭圆→圆   1角度/拍   32bit 全周     ABZ/UVW
```

| 步 | 一句话（旁白说的） | 它解决什么 |
|---|---|---|
| ① | 两路采样对齐，负电压换成有符号数 | 两路必须采自同一时刻，否则角度里带一个随速度变化的误差 |
| ② | 四个点取平均，数据降到四分之一，噪声小一半 | 用带宽换信噪比；等效多出 1 位，后面也全是低速逻辑 |
| ③ | 量出零点、幅度、相位差，补掉，圆就不歪了 | 传感器和安装带来的偏置、增益失衡、正交误差，在这里一次扣掉 |
| ④ | CORDIC 算反正切，每拍一个角度 | 不用除法器、不用查表，延迟固定 |
| ⑤ | 跟踪环压抖动、算转速，记下转了多少圈 | 压掉量化抖动，把 0–360° 展开成整圈位置 |
| ⑥ | ABZ / Z / UVW 编码 | 变成伺服驱动器认识的增量与换向信号 |

### 5.2 每一步必须有的画面（缺一个就补拍）

1. **对齐**：ADC 排线接口特写（证明双通道物理上是一起进来的）。
2. **降噪**：示波器上"原始波形"与"平均后波形"同屏叠加（可用上位机波形页做）。
3. **标定**：李萨如图从歪椭圆变正圆，**前后同框、中间不剪**。
4. **反正切**：`pipeline_41_5.mp4` 的流水线动画（已有素材，8 s，取前 4 s）。
5. **跟踪+计数**：屏上"角度"连续变化、"累计转数"单调递增。
6. **编码**：示波器 A/B 正交方波（S6 已拍，可复用 2 s）。

### 5.3 三条"为什么"，大概率会被问

- **为什么要标定？** 理想情况是正圆；实际是歪的椭圆，直接算反正切，误差能到十几二十度。标定就是先把椭圆补圆，再算角度。
- **为什么用 CORDIC？** 除法和查表在 FPGA 里都费资源；CORDIC 只用移位和加法，17 级流水后每拍出一个角度，延迟固定。
- **为什么整块板只有一个 50 MHz 时钟？** 没有跨时钟域，延迟才数得清（41.5 拍）；多一个时钟，就多一处"抖一下"的可能。

## 6. 全文逐字稿（连读版）

> `／` = 停 0.3 s，`‖` = 停 0.5–0.8 s；**粗体**重读。数字按读法念，见 §7.4。

**S1（0:00）**
这是我们做的磁编码器，用磁阻传感器加一块 **FPGA**。‖ 接下来三分钟，从转台一直看到屏幕。‖

**S2（0:11）**
现在电机停着。／ 这圈磁环，磁场是一圈一圈变的。传感器里两组检测单元错开四分之一周期，电角度正好差**九十度**。‖ 所以停住时，输出的不是波形，是两对**固定的电压**，正弦一对、余弦一对。‖ 每路都是正负两根线，外面的干扰两边一样，**一减就没了**。‖

**S3（0:40）**
让电机转起来。／ 角度一直在变，这两对电压就跟着变成正弦和余弦，始终差着**九十度**。／ 谁在前谁在后，就是转的方向。‖

**S4（0:54）**
信号出来，先进差分转单端模块，变成普通正余弦；／ 再走 **SMA** 同轴线，进 **AD9238**。／ 它双通道、十二位、**五十兆**，两路同时采，同一个时钟。‖

**S5（1:11）**
进到 FPGA，六步。‖
先把两路采样对齐，负电压换成有符号数；／
然后四个点取平均，数据少四分之三，**噪声小一半**；／
接着量一遍，两个零点、两个幅度、两路之间的相位差，六个数补进去，圆就圆了；／
再用 **CORDIC** 算反正切，十七级流水线，每个时钟一个角度；／
出来还得稳一下，后面跟个跟踪环，压抖动、算转速，顺带把圈数记上；／
最后编成 **ABZ**，一圈两千零四十八线，每转一个 **Z**，六路 **UVW** 换向。‖

**S6（2:00）**
结果分五路出去：／ **ABZ、UVW** 差分给驱动器，拉几十米没问题；／ **SPI** 和两兆波特串口，一秒一万帧；／ 以太网抓波形，一次**两万八千多点**，串口要大半秒，它几毫秒。‖

**S7（2:20）**
板子上还有一块**七寸**触摸屏，四页：总览、波形、时序、设置。／ 没有整屏缓存，参数改完当场生效。‖

**S8（2:32）**
接上电脑就是上位机，六页：概览、实时、编码器信号、告警、记录、诊断。／ 刚才那串数据，就是它在实时收的。‖

**S9（2:45）**
一颗 **FPGA**，把整条正余弦细分链自己走完。／ 十六位角度、两千零四十八线增量，**时序能过**，开源，能复现。‖

### 7.2 开拍前的板子状态（v90 基线）

- Flash 里是**显示位流** `_impl_disp_v90/enc_top_disp_v90.bit`，断电重上电应直接进 P1。
- 串口 2 Mbaud，`0x05F2` 读回 `0x0019`，遥测 10 kfps（拍 S1 前先确认，出片才敢说"上电自启"）。
- 转台磁环 64 对极，编码器输出 2048 p/r；`0x0101` 倍频 32、`0x0102` 分频 1；ABZ/UVW 输出使能（`0x0109 = 0x00C0`）。
- 上位机已连接、已切到中文界面、字体放大到 125%。

## 8. 口径红线

> 原则：**板上测到的才叫实测；算出来的叫预算；仿真出来的写明仿真。**

| 能说 | 不能说 / 要加限定 |
|---|---|
| 16 bit 角度、0.0055°/LSB | — |
| 标定把电角度误差 20.98° 压到 0.0165°（**定点模型 / 仿真**） | "实测 0.0165°" |
| 全链路 41.5 拍、约 0.83 µs（**设计预算**） | "实测 830 ns" |
| 60 s 遥测帧率稳定在 9,965 fps 量级 | "一帧不丢"（长跑有 <1% 丢帧，被问就答"不到百分之一"） |
| ABZ 2048 p/r、四倍频解码 8192 counts/rev | "分辨率 2048 就是 2048 个位置" |
| 以太网 ping 通、UDP 抓窗无缺块 | "以太网实时连续流 25 MSPS"（那是二期） |
| 转速 **457–459 rpm**（Z 7.62/7.65 Hz，`_boardtest/z_rate.py`，每转 1 个 Z） | 串口遥测"机械转速"栏的读数（会混叠），以及任何"屏上读数为准"的说法 |
| 单芯片、全 RTL、MIT 开源、SHA256 可核 | "已量产" / "已通过计量" |

另：**不出现**校名、院名、指导教师、队员姓名；片尾只留作品名与技术信息。

## 9. 评委追问应答卡

| # | 问题 | 两句话回答 |
|---|---|---|
| 1 | 精度到底多少？ | 分辨率是 16 bit/圈、0.0055°/LSB；精度分两个口径：板上角度与原始 atan2 一致性 RMS 0.71°，标定后定点模型残差 0.0165°。 |
| 2 | 和市面上的专用细分芯片比呢？ | 不比具体型号：公开手册给出的专用细分芯片延迟多在 1.5 µs 量级、分辨率常见 10–12 位、算法封闭；我们是 16 位角度、全 RTL、延迟预算 0.83 µs，每一级都能改、能测。 |
| 3 | 为什么用 FPGA 不用 MCU？ | 每拍出一个角度、延迟确定、五路接口同时跑；MCU 做不到 12.5 MSPS 的流水线吞吐。 |
| 4 | 2048 线怎么来的？ | 每转 64 个电周期，倍频 32，合起来就是 2048 线；四倍频解码 8192 个位置。倍频可在线改，屏上就能演示。 |
| 5 | 标定是不是拟合/查表？ | 不是。是物理误差模型（偏置、增益、正交）加闭式矩估计，一个窗口一次解出六个参数，不迭代、不查表。 |
| 6 | 830 ns 实测了吗？ | 是逐级拍数加出来的设计预算，报告里标了"设计值"；AD9238 内部 7 拍是估计值，实测待补。 |
| 7 | 丢帧吗？ | 60 s 稳定跑 59.8 万帧、9,965 fps；10 分钟长跑丢帧不到 1%，有告警位可查。 |
| 8 | 转速多少？ | **457–459 rpm**：用 `z_rate.py` 量 Z 频率 7.62/7.65 Hz，每转 1 个 Z；屏上/串口的转速栏只看趋势，不做判据。 |
| 9 | 屏上怎么没有标定页？ | 按需求把标定页撤了，入口改成 KEY0 长按或串口写 `0x0502=0x0001`，避免误触。 |
| 10 | 能复现吗？ | MIT 开源，tag v1.0.0；37 个 testbench、两个位流的 SHA256、证据索引都在仓库里，一条 `final_verify.ps1` 全过。 |

## 10. 5 分钟加长版：可插入的三段（各 20–30 s）

1. **两个静默死锁**（插在 S6 之后）：计数停在零 → 四步定位 → 根因是符号扩展把 +133 算成 −65,403 → 改成无符号差分，代价 39 个 LUT。素材现成（`assets/cg_deadlock_card.mp4`、v2 脚本 S15–S17）。
2. **标定前后对比**（插在 S5 第 3 步后）：同一窗口，圆度偏差 17.786% → 0.101%，中间不剪。
3. **以太网 vs 串口**（插在 S6 后）：同一窗 28,672 点，按带宽估算串口 0.66 s、以太网 1.5 ms，屏幕计时器同框实拍。
